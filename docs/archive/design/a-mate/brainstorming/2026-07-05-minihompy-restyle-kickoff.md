## 사용자 요구 (2026-07-05, 원문 요지)

1. **대대적인 미니홈피 스타일 수정** — 참조: https://it.chosun.com/news/articleView.html?idxno=2021020203174 (싸이월드 미니홈피 스크린샷 기사. 새 세션에서 이미지 확인 권장)
   - **탭은 오른쪽**으로 (클래식 미니홈피의 우측 세로 북마크 탭)
   - 클래식 미니홈피 구성 요소(기억 기준, 기사와 대조할 것): 이중 프레임(바깥 창 + 안쪽 콘텐츠 영역), 상단 타이틀바("OO님의 미니홈피" + TODAY/TOTAL 카운터), 좌측 컬럼(프로필 사진·한마디·BGM 위젯 자리), 가운데 콘텐츠, **우측 세로 탭**(홈/다이어리/사진첩/방명록 식 책갈피)
2. **기능이 제대로 구현 안 됨 — 특히 코칭(핵심 기능)**: 지금은 raw data(JSON evidence)만 보이고 "어떻게 개선해야 하는지"가 안 나옴
   - ⚠ 중요 사실: **backend에 사람말 조언이 이미 있다** — `crates/core/src/diary/mod.rs`의 `finding_advice()`가 규칙별 `detail`(근거 수치 문장) + `suggested_action`(개선 행동)을 생성하는데, **다이어리 생성에만 쓰이고 UI에 노출이 안 된 상태**. 3단계에서 이걸 커맨드로 노출(`list_findings`에 advice 동봉 또는 신규 커맨드)하고 코칭 탭을 "무엇이 문제 → 왜 → 어떻게 고침(행동 버튼/안내)" 구조로 재설계
3. **홈 화면 개편**:
   - 상단: 더 도움되는 정보로 (예: 주간 추이, 모델 사용 분포, 절약 실천 top3 — 브레인스토밍에서 결정)
   - **하단: 미니홈피 마이룸 스타일 방** — 그 위에 128px 로봇이 있고 말풍선 등으로 코믹하게 표현 (마스코트 창의 말풍선 시스템 재사용 가능성)
4. **마스코트 클릭 시 홈피(chat 창)가 열려야 함**
   - ⚠ 설계 주의: 현재 로봇 canvas는 `data-tauri-drag-region`이라 클릭이 드래그 시작으로 소비됨 — 클릭 vs 드래그 판별(이동 임계값) 설계 필요

## 기존 3단계 백로그 (비전 스펙 §10 + triage — 함께 계획할 것)

- 다이어리 탭: 미니 달력(도트) + 날짜별 열람 (백엔드 커맨드는 1단계에 배선됨: `list_diary_dates`/`get_diary`)
- 채팅 탭: 마스코트와 1:1 대화 (기존 `Engine` 재사용, 옵트인)
- 픽셀 폰트(Galmuri 계열) 도입
- updater: **서명 인프라 선행 필요 — 스펙 단계에서 포함/제외 사용자 결정** (사내 인증서 정책 미확정이면 제외 권장)
- 후속 triage: occasion 시작 레이스(마운트 시 pull 커맨드), 위치 클램핑, 릴리스 로그 관측성, 스캔 진행률 바, UTC "오늘" 정책, content_protected 배선, allowScripts 정리

## 진행 방식 (관례)

브레인스토밍(이 문서 + 참조 기사에서 출발, 홈 콘텐츠·코칭 UX는 질문으로 구체화) → 스펙 `docs/specs/` → 플랜 `docs/plans/` → SDD(태스크별 서브에이전트+리뷰) → PR(봇 리뷰 대응) → 사용자 E2E. 빌드 환경·교훈은 메모리 `build-env`/`roadmap` 참조.
