# 코칭 v2.1 설계 스펙 — 신뢰 회복 (R5 재설계 + R11 승격 + 식별력)

- 작성: 2026-07-07 (브레인스토밍 산출물, 킥오프: `docs/brainstorming/2026-07-06-coaching-v2.1-kickoff.md`)
- 선행: 코칭 v2(스펙 `docs/specs/2026-07-06-coaching-v2-design.md`, PR #11) + 사용자 E2E
- 다음 단계: writing-plans → `docs/plans/` → SDD → PR → 사용자 E2E

## 1. 배경과 원칙

v2 완성 직후 사용자가 같은 잣대("실제 조치 가능한 것만 코칭")로 두 신뢰 문제를 제기했다.

1. **R5(반복 Read)**: 반복 읽기의 주체는 에이전트(컨텍스트가 흐려지거나 확신 부족 시 스스로 재확인,
   상당수는 압축 후 재읽기라는 하네스 동작). 세션 카드는 "사용자 잘못"으로 읽혀 오해를 낳고,
   세션 단위 dedup이라 스팸이 재발했다 → v2에서 발화 보류 + 세션 카드 삭제됨.
2. **R11(권한 재시도 마찰)**: ToolResult 미수집 상태라 연속 호출의 원인(권한 거부 vs 편집 실패 vs
   정상 반복)을 판별 못 해 가설 카드가 다발 → v2에서 발화 보류됨.

두 문제의 공통 열쇠는 **ToolResult/UserPrompt/cwd 수집**이다. 이것이 풀리면 R11이 결정론으로 승격되고,
R5가 실제 레버 있는 신호로 재설계되며, R10 카드 식별력도 개선된다.

**v2 원칙 (계승, 유지)**

1. 코칭 대상은 조치 지점이 **① 설정 파일 한 곳** 또는 **② 다음 세션의 선택(습관·작업 방식)** 인 것만.
2. 지나간 세션 안에서의 행동 교정 권고는 폐기 (관찰은 되, 과거 교정 지시는 안 함).
3. 정밀도의 선: **결정론적 사실만 서사에 인용**. 해석·가설은 사실과 구분 표기. 추정 수치는 "추정/잠재"로 명시.
4. 세션 단위 카드 스팸 폐지 → **프로젝트 집계 카드**가 기본.

**v2.1 추가 원칙 (수집·프라이버시)**

5. **프로즈는 DB에 두지 않는다.** 미리보기/플래그 + 포인터(파일+offset)만 저장하고, 전문은 필요 시
   원본 JSONL에서 지연 로드(deref)한다. JSONL이 사라지면 미리보기로 graceful fallback — 로컬 소유 원칙과 정합.
6. R5는 **관찰 지표**로 프레이밍한다. "사용자가 뭘 잘못했나"가 아니라 "에이전트가 어떤 환경에서 반복 확인을
   하게 되는지, 다음 세션에 어떻게 도우면 줄어드는지"를 보여준다.

## 2. 범위

| 포함 | 내용 |
|---|---|
| §4 수집 | tool_result 상태·user prompt 첫 줄·cwd·compaction 경계 (지연로드 포인터 방식) |
| §5 R11 승격 | 결정론 판정: "거부 → 결국 승인" 패턴만 발화 |
| §6 R5 재설계 | 세션 카드 폐기 → 2개 subtype 프로젝트 집계 카드 (CLAUDE.md 레버 + context_drift 관찰) |
| §7 R10 식별력 | 진짜 작업 경로(cwd) + 대표 세션 첫 요청 한 줄 |
| §8 표면 | deref 커맨드, sessions_ctx 확장, CoachTab/diary 문구, 다이어리 관점 전환(자기 일기) |

**제외 (후속)**

- 세션 내 반복의 다른 subtype 다중 카탈로그(normal_verify·search_then_read 등을 개별 카드로): 이번엔 억제(침묵)만
  하고 카드는 `context_drift` 1종만. 사용자의 5-subtype 분류 설계는 후속 확장 청사진으로 §9에 기록.
- 킥오프 §4 이월: 서브에이전트 미활용(v2 킥오프 3), 컨텍스트 눈덩이(5), 사내 스킬허브 어댑터(6②).
- R3/R4/R8(캐시 히트율·1h 캐시·에러 정밀 탐지): §4 수집이 선행 재료를 깔지만 룰 구현은 후속. 단
  tool_result 상태 enum은 이번에 수집되므로 R8 승격의 절반은 이미 준비됨.

## 3. 프라이버시 — 지연로드(deref) 규약

- **DB에 저장**: 분류 플래그(tool_result 상태), 미리보기 한 줄(user prompt), 경로(cwd), 그리고 각 항목의
  **포인터**(`source_file` + byte `offset`).
- **DB에 저장 안 함**: tool_result 본문, denied/ok 메시지, user prompt 전문.
- **전문 접근**: 세션 상세를 열 때만 포인터로 JSONL의 해당 라인을 seek+read해 전문을 지연 로드(§8 `deref_jsonl_line`).
- **fallback**: 포인터가 가리키는 파일이 없거나(사용자가 트랜스크립트 삭제) 라인이 안 읽히면 저장된 미리보기/플래그만 노출.
- **마스킹 불필요**: 자유 텍스트를 DB에 안 두므로 경로·비밀값 마스킹 코드가 필요 없다(마스킹 버그로 비밀값이
  DB로 새는 위험 제거). deref는 로컬 원본을 그대로 보여주는 것이라 마스킹 대상 아님.

## 4. 수집 (선행 과제)

### 4.1 스키마 변경

**`events`** — tool_result 연결 + deref 포인터:
```
+ source_file TEXT     -- deref 포인터(현재 source_offset만 저장). 세션당 1파일 가정이라 용량 허용.
+ tool_use_id TEXT     -- tool_call ↔ tool_result 조인 키
+ result_status TEXT   -- tool_result 행에만: 'ok' | 'denied' | 'error'
```

**`sessions`** — 세션 단위 필드(세션당 1행이라 자연스러운 집):
```
+ cwd TEXT                       -- §7-1 진짜 경로 · R5 CLAUDE.md 위치
+ first_prompt_preview TEXT      -- §7-2 첫 요청 한 줄(≤120자)
+ first_prompt_source_file TEXT  -- 전문 deref 포인터
+ first_prompt_offset INTEGER    --  "
  (git_branch 컬럼은 이미 존재 — 지금 항상 NULL, 이번에 채움)
```

**이벤트 종류 확장** (`EventKind`):
- `ToolResult { tool_use_id: String, status: ResultStatus }` — 신규. `ResultStatus = Ok | Denied | Error`.
- `Compaction` — 신규(마커만; §6.2 context_drift 판정에서 재읽기 원인 구분용).
- 기존 `SessionMeta { cwd, git_branch }`·`UserPrompt`(신규 `{ preview }`)는 **events에 안 쌓고 sessions만 갱신**(§4.3).

### 4.2 어댑터 — `user` 라인 파싱

현재 어댑터는 `assistant` 라인만 파싱한다. `user`/기타 라인을 다음과 같이 추가 처리한다.

- **tool_result 블록** (`type=="user"`, content에 `tool_result`): 각 블록 → `ToolResult` 이벤트.
  `status` 도출:
  - `denied` — content가 Claude Code 권한 거부 마커와 매칭될 때. (마커 문자열은 실 트랜스크립트로 핀 — §10 검증)
  - `error` — `is_error==true`이나 거부 마커 아님.
  - `ok` — 그 외.
  - **fail-safe**: 거부 마커를 못 알아보면 `error`로 폴백 → R11이 오탐 대신 침묵.
  - 포인터: 이벤트의 `source_file`+`source_offset`.
- **첫 사용자 프롬프트**: `type=="user"`이고 tool_result가 아니고 메타/커맨드(`isMeta`, `<command-*>`,
  compact summary 등)가 아닌 첫 텍스트 → `UserPrompt { preview }`(첫 줄 ≤120자) + 포인터.
- **compaction 경계**: compact/summary 마커 라인 → `Compaction` 이벤트(순서 보존용, 컬럼 없음).
- **cwd/git_branch**: 라인의 `cwd`·`gitBranch` → `SessionMeta`.
- **tool_use 블록의 tool_use_id**: 기존 tool_call 파싱에 `id` 캡처 추가(조인 키).

### 4.3 라우팅 (upsert_events)

- `AssistantTurn` · `ToolCall` · `ToolResult` · `Compaction` → **`events` 행**.
- `SessionMeta` · `UserPrompt` → **`sessions` 행만 갱신, events에 안 쌓음**:
  - cwd/git_branch: 세션당 1회 세팅.
  - first_prompt: `COALESCE(기존, 신규)` — 최초값 유지. 파일 순서 = 시간 순서라 처음 만난 프롬프트가 최초.
    (다중 파일 재개 세션은 근사 — §10 주석.)

### 4.4 마이그레이션

`migrate()`의 model_raw 전례 확장: `events.source_file` 컬럼 부재를 트리거로
`events`/`ingest_state`/`daily_rollup`/**`sessions`**를 비우고 전체 재수집. findings·status·diary_index는 보존.
(로컬 JSONL 파생 데이터라 손실 없음.)

## 5. R11 승격 — 권한 거부의 결정론 판정

`r11_permission_friction.rs` 재등록. 판정 입력을 "연속 호출 휴리스틱" → "거부→승인 사실"로 교체.

- **마찰 이벤트 정의**: 한 세션에서 같은 `(raw_name, tool_target)`에 대해 `denied` 결과가 있고,
  그 **이후** 같은 `(raw_name, tool_target)`가 `ok`로 실행된 경우 1건.
  - 판정: `tool_call` ↔ `tool_result`를 `(session_id, tool_use_id)`로 조인 → 세션 내 순서(id) 정렬 →
    (도구,대상)별로 `denied`가 선행하고 `ok`가 후행하면 마찰.
  - 근거: 사용자가 실제로 그 조치를 원했음이 증명됨(거부 후 승인) → **allowlist 처방이 항상 정확**.
  - 의도적 거부(재승인 없이 denied만)는 자연 제외 → 역방향 조언 없음.
  - "allow always"는 첫 실행이 `ok`(거부 기록 없음)라 자연 침묵.
- **발화 조건**: 프로젝트에 마찰 이벤트 ≥ **2건**.
- evidence: `{ session_ids, total_sessions, friction_events: [{tool, target, session_id}], friction_events_count, by_tool }`
- est_tokens_saved: **0** (tool_call에 토큰 컬럼 없음 — 근거 없는 수치 금지, 가치는 마찰 제거 서사로).
- prescription: `{ kind: "permission_allowlist", payload: { tools: [...] } }`
- fix_command: **None** (허용목록 편집은 서사로 안내).
- dedup_key: `R11|{host}|{project}`
- **advice (사실로 단정)**: "거부 후 결국 승인하신 `{tool}` → `{target}` 패턴이 N건 있었어요.
  settings.json 허용목록에 그 도구를 추가하면 매번 뜨는 승인 프롬프트와 거부→재시도 낭비가 사라져요."
  (v2의 "…일 수 있어요" 가설 표현은 제거 — 이제 결정론.)
- **ops.rs**: R11 재등록 + `delete_findings_by_rule_and_scope("R11","project")` 라인 제거(이제 upsert).

## 6. R5 재설계 — "반복 파일 재확인" (2개 subtype, 프로젝트 집계)

세션 스코프 R5(동일 파일 ≥4회 → 세션 카드)를 폐기하고, 레버가 있는 프로젝트 집계 신호 2종으로 분해한다.
`subtype`·`user_actionability`는 evidence JSON에 담아 **스키마 무변경**. 두 subtype는 서로 다른 레버이므로 별개 카드.

### 6.1 subtype `cross_session_claude_md` — CLAUDE.md 레버 (category ①)

같은 프로젝트의 여러 세션에서 반복해서 읽히는 파일 = "매 세션 필요한데 상주 컨텍스트에 없다"는 신호.

- **판별**: `file_read`를 `(host, project, tool_target)`로 묶어
  - **별개 세션 ≥ 3** (`COUNT(DISTINCT session_id)`)
  - **노이즈 경로 제외**: `node_modules`, `target`, `dist`, `build`, `.git`, `vendor` 포함 경로 및
    lock/생성 파일(`*.lock`, `package-lock.json`, `Cargo.lock`, `*.min.js` 등). (목록은 튜닝 가능.)
  - **읽기우세**: 같은 target에 대해 `reads > edits`(`file_edit`+`file_write` 합). WIP가 아닌 참조 파일만.
- **집계**: 프로젝트당 카드 1장, evidence에 파일 목록(파일별 distinct 세션 수).
- evidence: `{ subtype:"cross_session_claude_md", user_actionability:"high", files:[{path, session_count}],
  session_ids, total_sessions, cwd }`
- est_tokens_saved: **잠재(추정)** `Σ_file (distinct_sessions − 1) × 1200`. 서사에 "추정/잠재"로 명시.
- prescription: `{ kind: "add_to_claude_md", payload: { files:[...] } }`
- fix_command: **None** (편집은 서사로 — cwd로 어느 CLAUDE.md인지 지목).
- dedup_key: `R5|{host}|{project}|cross_session_claude_md`
- advice: "이 프로젝트 여러 세션에서 `{files}`를 반복해서 읽었어요(최대 ~N토큰 추정). 이 파일들의
  요약/포인터를 `{cwd}\CLAUDE.md`에 넣어두면 매 세션 다시 읽지 않아도 돼요."

### 6.2 subtype `within_session_context_drift` — 다음 세션 운영 팁 (category ②)

세션 안에서 같은 파일을 편집 없이 여러 번 다시 읽는 패턴 = 작업 기억이 흐려졌다는 신호.
"사용자 잘못"이 아니라 다음 세션 운영으로 줄일 수 있는 관찰이다.

- **드리프트 읽기 판별** (오탐 억제가 핵심): 세션 내 이벤트를 순서(id)대로 훑어, target X의 `file_read` 중
  다음을 **전부** 만족하는 것만 "드리프트 읽기"로 카운트:
  - X에 대한 선행 `file_edit`/`file_write`가 없음 (→ `verify_after_edit` 억제)
  - 직전 이벤트가 `Search`가 아님 (→ `search_then_read` 억제; Search는 target=파일이 아니라 근접 기준)
  - 직전 X 읽기 이후 `Compaction`이 끼지 않음 (→ `post_compaction_recovery` 억제)
- **세션 드리프트 판정**: 한 세션에서 어떤 target의 드리프트 읽기 ≥ **3**이면 그 세션이 X에 대해 context_drift.
- **발화 조건**: 프로젝트에서 context_drift를 보인 세션 ≥ **2건**.
- evidence: `{ subtype:"within_session_context_drift", user_actionability:"medium",
  sessions:[{session_id, path, drift_reads}], session_ids, total_sessions, cwd }`
- est_tokens_saved: **잠재(추정)** `Σ (드리프트 재읽기 − 1) × 1200`. 서사에 "추정/잠재"로 명시.
- prescription: `{ kind: "next_session_habit", payload: { tips:["file_map","scoped_read"] } }`
- fix_command: **None**
- dedup_key: `R5|{host}|{project}|within_session_context_drift`
- severity: `Suggest`
- advice (관찰+팁, 비난 금지): "몇몇 세션에서 에이전트가 같은 파일을 편집 없이 여러 번 다시 읽었어요
  (직접 시키신 게 아니라 작업 중 파일 구조 기억이 약해졌을 때 생겨요). 다음엔 '먼저 관련 파일을 읽고 역할·수정
  위치를 짧게 메모한 뒤 진행해'처럼 시작하면 반복 재확인이 줄어요."

### 6.3 이행

- `run_rules`의 `delete_findings_by_rule_and_scope("R5","session")`는 **유지**(옛 세션 카드 정리).
  새 R5는 `scope_kind="project"` + subtype dedup이라 이 삭제에 안 걸리고 공존.
- 기존 `R5RepeatedRead`(세션) 룰 구조는 재설계 룰로 대체(모듈 재작성). 헬퍼는 §4.1 세션요약(v2 `session_stats.rs`) 재사용 검토.

## 7. R10 식별력 개선 (탐지 로직 무변경 — evidence·렌더만)

`detect_bursts`·발화 조건은 그대로. 대표 세션(예: 버스트 최신 세션)의 수집 확장분을 evidence에 싣고 서사에 인용.

1. **진짜 작업 경로**: 정규화 키(`d--project-cowork--…`) 대신 대표 세션 `sessions.cwd`
   (`D:\Project\cowork\.worktrees\…`)를 evidence·advice에. (역디코딩은 대시 중의성으로 손실적이라 cwd가 유일한 정직한 경로.)
2. **첫 요청 한 줄**: 대표 세션 `sessions.first_prompt_preview` →
   advice에 "💬 이런 요청으로 시작해요: '{preview}'" 삽입 — 세션 상세 없이 자동화 도구 정체 즉시 식별.

- evidence 추가 키: `{ rep_cwd, rep_first_prompt }` (기존 R10 evidence에 병합).

## 8. 표면 변경

### 8.1 백엔드
- **신규 커맨드** `deref_jsonl_line(source_file: String, offset: u64) -> Option<serde_json::Value>`:
  guarded 읽기(파일 부재/파싱 실패 → None). 세션 상세에서 프롬프트/tool_result 전문 지연 로드용.
- `commands.rs::sessions_ctx`: 반환에 `cwd`, `first_prompt_preview` 추가(집계 카드 펼치기·식별용).
- `coach.rs::fix_command`: R5(두 subtype)·R11 → None 유지. 변경 없음(신규 kind에 대한 None 확인 테스트만).
- `diary/mod.rs::finding_advice`: R11(결정론 문구), R5(subtype별 문구, 관찰+추정 프레이밍),
  R10(진짜 경로 + 첫 요청 삽입)로 교체.

### 8.1a 다이어리 관점 전환 — 에이전트 자신의 일기

현재 `build_system_prompt`는 마스코트가 주인에게 말 거는 편지/보고 톤에 가깝다("사용자를 '{honorific}'이라고
부릅니다" + "주인이 바로 알 수 있게"). 이를 **마스코트가 자기 하루를 기록하는 1인칭 일기**로 바꾼다.

- 주인을 2인칭으로 부르지 않고 **3인칭(`{honorific}`)으로 지칭** — "오늘 {honorific}과 함께 …했다".
- 코칭(각 finding의 `detail`/`suggested_action`)은 주인에게 내리는 지시가 아니라 **마스코트 자신의
  회고·다짐**으로 녹인다("오늘 같은 파일을 여러 번 읽느라 헤맸다 — 다음엔 미리 메모해두면 좋겠다").
- 유지: 정밀도의 선(브리프 사실·수치만, 지어내기 금지), 행동 지시로 승격 금지, 유머·다마고치풍,
  occasions 언급, 톤 프리셋(A/B/C).
- `finding_advice`의 `detail`/`suggested_action` 문구 자체는 사실·방향 서술이라 그대로 두고,
  **관점 전환은 시스템 프롬프트(`build_system_prompt`)에서만** 처리(표면 최소 변경).

### 8.2 프론트 (CoachTab)
- R5 프로젝트 카드 2종(subtype별) 렌더 — 파일/세션 목록 펼치기는 v2 집계 카드 UI 재사용.
- R10 카드: 진짜 경로 + "💬 이런 요청으로 시작해요" 표시.
- R11 카드 재노출.
- 세션 상세: 저장된 미리보기 우선 표시, 사용자가 "전문 보기" 시 `deref_jsonl_line` 호출.

## 9. 후속 확장 청사진 (사용자 R5 분류 설계 — 이번 미구현)

이번엔 `context_drift` 1종만 카드화하고 나머지는 억제(침묵)한다. 후속에서 다음 subtype로 세분 가능(관찰 지표 용):
`normal_verify`(low), `search_then_read`(low), `post_compaction_recovery`(low), `failed_command_loop`(medium,
tool_result `error` 인접 — §4 수집으로 판정 가능), `unknown`. `user_actionability` 필드는 이미 evidence에 두므로
확장 시 호환.

## 10. 테스트 / 검증 기준

기존 룰 테스트 스타일(인메모리 store + 이벤트 주입) 유지.

- **수집**: tool_result status 도출(denied/error/ok, 거부 마커 미인식 → error 폴백) / user prompt 첫 줄
  COALESCE 최초값(재수집·순서) / tool_result·prompt를 events에 안 쌓고 sessions만 갱신 / cwd·git_branch 캡처.
- **deref**: (source_file, offset) 라운드트립으로 전문 복원 / 파일 부재 시 None fallback.
- **R11**: denied→ok 양성 / denied만(재승인 없음) 음성 / ok만 음성 / 마찰 1건뿐 음성 / dedup·est=0.
- **R5 cross_session**: 별개 세션 3 경계 / 노이즈 경로 제외 / 읽기우세(reads≤edits 음성) / 파일 목록·잠재추정.
- **R5 context_drift**: 편집 후 읽기 억제 / 검색 후 읽기 억제 / compaction 직후 억제 / 순수 재읽기 3회 양성 /
  프로젝트 세션 2건 경계 / subtype·user_actionability evidence.
- **R10**: evidence에 rep_cwd·rep_first_prompt 실림 / advice에 진짜 경로·첫 요청 삽입.
- **다이어리 관점**: `build_system_prompt`가 자기 일기 관점(주인 3인칭 지칭)·finding을 회고/다짐으로 녹임
  지시 포함, 2인칭 편지 톤 제거. (기존 프롬프트 테스트의 호칭·유머·occasions 검증은 유지.)
- **마이그레이션**: source_file 컬럼 추가 시 events/sessions 비우고 재수집, findings 보존.
- **거부 마커 핀(중요)**: `denied` 판별은 Claude Code 거부 메시지 텍스트 의존(안정 API 아님). 실 트랜스크립트로
  마커를 핀하고, 버전 변화 시 `error`로 degrade(오탐 대신 침묵). **E2E 검증 포인트**.
- **E2E 최종 판정**: 실데이터에서 R11 카드가 "거부→승인" 건만, R5 카드가 CLAUDE.md 후보/드리프트 세션만,
  R10 카드에 진짜 경로+첫 요청이 표시됨.
