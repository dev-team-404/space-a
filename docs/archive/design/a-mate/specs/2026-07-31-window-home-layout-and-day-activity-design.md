# 묶음 ⑦ — 창 크기 고정 + 홈 재배치 + 다이어리 일별 활동 패널(D1)

- **날짜**: 2026-07-31
- **컴포넌트**: a-mate (프론트 + Tauri 설정 + `crates/core` 조회 함수. a-hub·`contracts/` 미접촉)
- **관계**: [Life 소셜·일기 통합 후속 로드맵](../plans/2026-07-26-life-social-diary-followups-roadmap.md) **5차 배치 D1** +
  사용자 요청(창 크기 고정·홈 배치 싸이월드화, 2026-07-31 세션).
- **목적**: 미니홈피의 화면 크기를 확정하고, 그 확정된 폭 위에서 홈 배치를 싸이월드 결에 맞게 재구성하며,
  다이어리 탭의 빈 좌측 하단을 그날의 활동 요약으로 채운다.

## 0. 왜 한 묶음인가

셋 다 **같은 화면 구조**를 건드린다(`tauri.conf.json`·`HomeTab.svelte`·`DiaryTab.svelte`).
특히 D1은 "달력 아래 남는 공간"에 들어가는데, 창 크기가 가변이면 그 공간의 크기가 정해지지 않아
설계가 반응형으로 흐려진다. **창 고정 → 배치 확정 → 그 자리에 D1**이 자연스러운 순서다.

## 1. 창 크기 고정 (960 × 820)

### 1.1 현재 상태 (실측 2026-07-31)

`a-mate/src-tauri/tauri.conf.json`의 `app.windows[]`:

| 창 | 설정 |
|---|---|
| `chat` | `width: 860`, `height: 760`, `minWidth: 860`, `minHeight: 620` — **`resizable` 미지정 = 기본 `true`** |
| `mascot` | `width/height: 280`, **`resizable: false`** (선례 있음) |

레이아웃 CSS는 flex 기반이고 `max-width` 고정이 없다. 그래서 창을 늘리면 콘텐츠가 그대로 늘어나는데,
다이어리 탭은 늘릴수록 **달력만 좌상단에 남고 나머지가 전부 빈 여백**이 된다.

### 1.2 결정

**`width: 960`, `height: 820`, `resizable: false`.** `minWidth`/`minHeight`는 **제거한다** —
`resizable: false` 아래에서는 의미가 없고, 남겨두면 다음 사람이 조절 가능한 줄 오해한다.

### 1.3 기각한 대안과 이유

처음에 "창은 조절 가능하되 콘텐츠만 `max-width`로 고정(실제 싸이월드 방식)"을 제안했으나
사용자 반문으로 뒤집혔다 — **"창을 늘려도 내부 콘텐츠가 그대로면 창을 늘리는 의미가 있나?"**

그 지적이 맞다. 싸이월드에서 창 조절이 의미 있었던 건 **브라우저** 창이었기 때문이다(다른 탭·다른 사이트를
위한 창). 이 앱은 **창 자체가 미니홈피**라 콘텐츠가 고정폭이면 배경 여백만 늘어난다. 따라서 선택지는
"콘텐츠 고정 → 창도 고정" 또는 "창 조절이 의미 있으려면 콘텐츠가 실제로 늘어나야 함" 둘뿐이고, 전자를 택했다.

| 기각안 | 이유 |
|---|---|
| 콘텐츠 `max-width` + 창 조절 허용 | 위 반문 — 데스크톱 전용 앱에서는 조절의 실익이 없다 |
| 배율 프리셋(100%/125%) | 고DPI는 Windows 디스플레이 배율이 WebView2에 이미 적용된다. 실제 불편이 확인되면 그때 |
| 화면보다 크면 자동 축소 로직 | Rust에 화면 감지·창 조정 코드가 추가된다. 960×820은 1600×900 이상에서 안전하므로 과잉 |

### 1.4 알려진 한계

`resizable: false`이므로 **1366×768급 화면에서는 창이 화면을 넘어가고 사용자가 줄일 수단이 없다.**
a-mate는 자동 업데이트로 배포되는 앱이라 이 리스크는 실재한다. 배포 후 그런 보고가 나오면
§1.3에서 기각한 "자동 축소" 또는 배율 프리셋을 그때 도입한다. **지금 선제 대응하지 않는 것은 의도된 선택이다.**

## 2. 홈 재배치

### 2.1 현재 구조 (`src/lib/ui/HomeTab.svelte:73-96`)

```svelte
<section class="home">
  {#if hubConnected || interiorPreview}<LifeView />{:else}<MiniLife … />{/if}   ← 방
  {#if !visiting}
    <div class="strip">   세션 / 입력 / 출력 (+절약 가능)
    <div class="grid">    WeekTrend · ModelMix · SaveTop3 · NoticeLog
    <footer class="status">  마지막 스캔 · [지금 스캔]
  {/if}
</section>
```

**방이 `{#if !visiting}` 밖에 있는 것이 핵심 제약이다.** 남의 방을 방문 중일 때는 방만 보이고
내 로컬 통계는 전부 숨는다(주석: "남의 것으로 오독 방지"). 방을 조건 블록 **안**으로 옮기면
**방문 기능이 깨진다.**

### 2.2 목표 배치

```
┌────────┬───────────────────────┐┬─┐
│ 대문   │ 세션 5  입력 3,367 …  ││홈│
│ 사진   │┌────────┐┌─────────┐││다│
│        ││주간 추이││모델 분포  │││이│
├────────┤└────────┘└─────────┘││어│
│💬 한마디│┌────────┐┌─────────┐││리│
│        ││절약 top3││최근 알림  ││├─┤
├────────┤└────────┘└─────────┘││코│
│ A-Lens │┌─────────────────────┐││칭│
│ 이동   ││   내 방 (LifeView)   ││├─┤
│        ││      🤖 돌쇠         │││채│
│        │└─────────────────────┘││팅│
└────────┴─ 마지막 스캔   [지금 스캔]─┴─┴─┘
```

통계를 위로, **방을 아래로**. 싸이월드 결에 맞추려는 사용자 요청이다.

### 2.3 구현 방향 — 조건 블록을 둘로 쪼갠다

```svelte
{#if !visiting}
  <div class="strip"> … </div>
  <div class="grid"> … </div>
{/if}

{#if hubConnected || interiorPreview}<LifeView />{:else}<MiniLife … />{/if}   ← 조건 밖 유지

{#if !visiting}
  <footer class="status"> … </footer>
{/if}
```

`{#if !visiting}`이 둘로 나뉘는 것은 감수한다. 방을 조건 밖에 유지하는 것이 방문 모드의
불변조건이기 때문이다. **방문 중 화면은 이 변경으로 전혀 달라지지 않는다**(방만 보이는 것은 동일).

### 2.4 세로 예산

960×820 안에서 스크롤 없이 들어가야 한다. 현재 860×760에서도 전 요소가 스크롤 없이 보이므로
(2026-07-31 실측 스크린샷) 순서만 바꾸는 이 변경으로 세로 요구가 늘지는 않는다. 높이를 760→820으로
키운 것은 여유분이다. **구현 후 실제 화면에서 스크롤바가 생기지 않는지 확인할 것.**

## 3. D1 — 다이어리 탭 일별 활동 패널

### 3.1 자리와 제약

`DiaryTab.svelte`는 `display:flex`로 **좌측 달력 컬럼(`.cal`, `width: 238px`, `align-self: flex-start`)** +
**우측 일기 본문(`.body`)** 구조다. 달력이 위쪽에 붙어 있어 **그 아래가 통째로 빈다** —
일기를 선택해 본문이 길게 늘어날수록 이 여백이 두드러진다(2026-07-31 스크린샷 확인).

따라서 D1이 들어갈 공간은 **폭 ≈240px의 좁고 세로로 긴 영역**이다. 넓은 차트는 맞지 않고
세로로 쌓는 형태여야 한다.

### 3.2 패널 구성 (승인된 목업)

```
┌─ 2026-07-30 ──────┐
│ 세션 5 · 도구 550회  │
├──────────────────┤
│ 토큰                │
│  입력      3,367   │
│  출력    429,577   │
│  캐시       1.2M   │
├──────────────────┤
│ 도구 호출            │
│  bash  ████████ 210 │
│  edit  █████    142 │
│  read  ████      98 │
│  write ██        55 │
│  skill █         12 │
├──────────────────┤
│ 스킬 · MCP          │
│ [dataviz][docs-ar…] │
├──────────────────┤
│ 세션                │
│ 09:12 space-a       │
│  "PR138까지 머지…"   │
│ 14:03 a-mate        │
│  "일기 탭 확인…"     │
│ … 2개 더 ▾          │
└──────────────────┘
```

| 구획 | 내용 | 상한 |
|---|---|---|
| 요약 | 세션 수 · 도구 호출 총계 | — |
| 토큰 | 입력 / 출력 / 캐시(= `tok_cache_read + tok_cache_create`) | — |
| 도구 호출 | `tool_kind`별 가로 막대 + 횟수 | **상위 5종** |
| 스킬·MCP | 칩 나열 | 각 8 (기존 `ToolUsage` 상한 그대로) |
| 세션 | 시각 · 프로젝트 **표시명** · 첫 프롬프트 1줄 | **상위 3 + "N개 더" 펼치기** |

**프로젝트 표시명은 `project_id`가 아니다.** `sessions.project_id`는 `win:d:\project\space-a` 형태의
**정규화 키**다(`crates/core/src/hosts.rs:145` `project_identity`가 `(키, 표시이름)`을 반환하며,
WSL 직접 세션과 Windows UNC 세션을 같은 키로 통합하기 위한 값). 목업의 `space-a`에 해당하는 것은
같은 파일의 **`pub fn path_basename(cwd)`**(`hosts.rs:114`)이 뽑는 표시명이다.

→ 표시명은 **`path_basename(cwd)`**, `cwd`가 NULL이면 `project_id`로 폴백한다.
(참고: `CoachTab.svelte:77`은 `project_id`를 그대로 노출하는데, 그것은 이 묶음의 범위가 아니다.)

### 3.3 표시 조건 — `!visiting && selected`

`DiaryTab`은 `visiting` prop으로 **남의 방 일기도 보여주는 모드**가 있다(`lifeDiaries`로 조회).
방문 중에 내 세션 기록·토큰이 그대로 보이면 남의 것으로 오독되거나 내 활동이 새어 나간다.
**`visiting=true`면 패널 전체를 숨긴다.** 홈 탭의 `{#if !visiting}` 규율과 같은 원칙이다.

날짜가 선택되지 않았으면(`selected === null`) 패널도 없다 — 달력만 보이는 초기 상태를 유지한다.

### 3.4 컴포넌트 분리

**신규 `src/lib/ui/diary/DayActivity.svelte`.** `DiaryTab.svelte`는 41줄로 극도로 압축된 파일이라
(한 줄에 여러 문을 몰아 쓰는 스타일) 여기에 패널 마크업·스타일까지 넣으면 읽기 어려워진다.
`DiaryTab`은 패널을 `<DayActivity date={selected} />`로 부르고 조건만 관리한다.

### 3.5 백엔드 — 신규 커맨드 `day_activity(date)`

왕복 1회로 묶는다. 재료 3종의 현재 상태:

| 재료 | 위치 (실측 2026-07-31) | 필요한 일 |
|---|---|---|
| 세션 수·토큰 | `crates/core/src/store.rs:803` `pub fn summary_for_date(&self, date) -> DaySummary` | **그대로 사용**. `DaySummary { session_count, tok_input, tok_output, tok_cache_read, tok_cache_create }` (`store.rs:2046`) |
| 도구 집계 | `crates/core/src/diary/mod.rs:529` `fn collect_tool_usage(store, date) -> ToolUsage` — **private** | **`pub`으로 공개화**. `ToolUsage { total_calls, by_kind: Vec<(String,u64)>, skills: Vec<String>, mcp_servers: Vec<String> }`는 이미 `pub` + `Serialize` (`diary/mod.rs:23`) |
| 세션 목록 | **없음** | **`sessions_for_date(date)` 신규** — `sessions` 테이블에 `first_ts`·`project_id`·`cwd`·`first_prompt_preview` 존재(`store.rs:11`, 마이그레이션 `:184`). 참고 선례: `session_ctx(session_id)` (`store.rs:1376`)가 같은 컬럼을 세션 1건 단위로 뽑는다. 표시명 규칙은 §3.2 참조 |

> ⚠ 로드맵 5차 배치 D1의 조사 사실에 적힌 라인 번호(`store.rs:765`, `diary/mod.rs:482-506`)는
> **밀렸다**. 위 표가 2026-07-31 기준 실측값이다.

**날짜 필터 규약**: 기존 집계가 전부 `date(ts,'localtime')=?1`을 쓴다(`diary/mod.rs:534`).
`sessions_for_date`도 `date(first_ts,'localtime')`로 **같은 규약을 따른다** — 다른 기준을 쓰면
같은 화면 안에서 세션 수(요약)와 세션 목록의 길이가 어긋난다.

### 3.6 프라이버시

`first_prompt_preview`는 사용자가 직접 친 프롬프트의 앞부분이다. 이 패널은 **로컬 화면 전용**이고
(§3.3에 따라 방문 중엔 숨김) 어디로도 전송되지 않는다. a-hub 발행 경로와 무관하다.
