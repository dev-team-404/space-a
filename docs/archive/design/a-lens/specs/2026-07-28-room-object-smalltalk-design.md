# 방 오브젝트 잡담 — 설계 스펙

> **목적**: 방 안 오브젝트(창문·정수기·책장)를 클릭하면 그 자리에 어울리는 대사가 바로 위
> 말풍선에 타이핑으로 재생된다. 방이 "데이터 대시보드"가 아니라 사람이 지내는 공간으로
> 읽히게 하는 장치.

## 0. 30초 요약

| 항목 | 결정 |
|---|---|
| 대상 | **창문**(창밖 잡담) · **정수기**(물 권하며 위로) · **책장 배지**(쌓인 문서량 안내) |
| 상호작용 | 클릭 1회 → 2~3턴 자동 재생 (턴 사이 2.4초, 마지막 턴 후 4초 뒤 사라짐) |
| 표시 위치 | 오브젝트 상단 중앙에 말풍선 꼬리를 맞춘다 |
| 글씨·연출 | 캐릭터 상세 패널과 동일 — `Galmuri11` 픽셀 폰트 + 한 글자씩 타이핑 + 깜빡이는 커서 |
| 문구 생성 | 창문·정수기는 LLM(설정 창의 LLM API 재사용), 책장 배지는 **결정론**(건수는 사실) |
| 근거 | 화면에 실제로 그려진 것 + KST 시간대. 실제 기상·날짜는 모르는 정보로 취급 |

## 1. 무엇을 말할 수 있나 — 근거의 선

"오늘 날씨 좋죠"는 기상 정보가 아니라 **창밖에 그려진 그림**에 대한 반응이다. 방 프리셋은
5종이고 각각 창밖 풍경이 다르다 — 이건 서버가 아는 사실이므로 환각이 아니다.

| 프리셋 | 창밖 | 잡담 톤 |
|---|---|---|
| `r1` | 단풍 든 숲 | 가을·산책 |
| `r2` | 벚꽃과 도시 | 봄·나들이 |
| `r3` | 밤 도시 야경 | 야근·퇴근 |
| `r4` | 맑은 하늘과 초원 | 여름·휴가 |
| `r5` | 밤 도시(어두운 방) | 야근·마감 |

정수기는 풍경과 무관하고 **시간대만** 근거로 쓴다("쉬었다 하라"는 위로). 책장 배지는 문서
건수가 유일한 근거이므로 LLM을 쓰지 않는다 — 수치는 결정론이라는 저장소 원칙 그대로다.

실제 기상 API는 붙이지 않는다(사내망·키 부재). 프롬프트에 "실제 날씨·날짜는 모른다 —
보이는 것에만 반응하라"를 명시해 단정을 막는다.

## 2. 계약

```
GET /api/room-chat?spot=window|water&view=<r1..r5>&space_name=<방 이름>
→ { "lines": ["밖에 단풍 다 들었네요", "이런 날 반차 쓰고 걷고 싶다"], "source": "llm" | "fallback" }
```

- `spot` 미지정·미지원 → `window`. `view` 미지정·미지원 → `r1`.
- 항상 200. LLM이 없거나 실패하면 `source: "fallback"`으로 결정론 문구를 준다 — 오브젝트는
  절대 "오류"를 말하지 않는다.
- `lines`는 2~3개, 각 줄 40자 이내(서버가 자름).
- 책장 배지는 서버를 타지 않는다 — 프론트가 건수로 문구를 만든다.

## 3. 다양성과 비용 — 풀(pool)

같은 오브젝트를 여러 번 클릭하면 같은 말이 반복되면 안 되고, 클릭마다 LLM을 때리면 로컬
모델(LM Studio, 실측 약 4초)에서 체감이 느려진다. 절충:

- 키 = `(구역, 풍경, 시간대)`. 정수기는 풍경을 키에 넣지 않는다(무관하므로).
  시간대 버킷 = 아침/낮/저녁/밤(KST).
- 키별로 **최대 5세트**를 프로세스 메모리에 모은다. 5세트가 차면 그중 하나를 무작위로 고른다
  → 클릭이 잦아도 LLM 호출은 키당 5회로 끝난다. 영속화는 하지 않는다(취향 문구).
- 프론트는 **방에 들어올 때 창문·정수기 대사를 각각 1세트 선입**한다 — 첫 클릭이 4초를
  기다리지 않게. 재생을 시작하면 다음 세트를 백그라운드로 채운다.

## 4. 실패 격리

- LLM 타임아웃 12초(번역 경로 90초보다 짧게 — 대화는 즉시성이 품질이다).
- 예외·형식 불일치·빈 응답 → 폴백 세트. 프론트는 `source`를 신경쓰지 않는다.
- 프론트 fetch 실패 시에도 말풍선은 구역별 기본 문구로 뜬다 — 클릭이 무반응인 것이 최악.

## 5. 좌표와 히트존 — 겹침은 z가 아니라 영역으로 푼다

히트존은 배경 프리셋 이미지 좌표(`manifest.json`의 `cal`)로 잡는다. 기존 `backWall`(칠판)·
`shelfArea`(책장)에 `windowArea`·`waterArea`를 추가했다.

배경 한 장에 다 그려져 있어서 **창문·정수기·배지가 모두 `shelfArea` 안쪽과 겹친다**. 처음엔
창문 히트존을 창문 상단부만 잡아 겹침을 피했는데, 사람이 실제로 누르는 곳은 밝은 유리
한가운데라 클릭이 책장으로 먹혀 `문서함`이 열렸다(2026-07-29). z순서(zIndex)로 우선순위를
주는 방법도 실측에서 신뢰할 수 없었다.

**결론: 영역 차집합.** `subtractRect`로 `shelfArea`에서 창문·배지·정수기 사각형을 빼고,
남은 조각들만 책장 히트존으로 만든다. 순서 의존이 사라지고, 오브젝트가 늘어도 구멍 목록에
추가하면 된다.

디버그: URL에 `hitzones`가 있으면(`/?hitzones=1#life/<id>`) 히트존을 색으로 칠하고 탭을
콘솔에 찍는다 — 빨강 창문 / 하늘색 책장 / 노랑 칠판·배지·정수기.

| 위치 | 내용 |
|---|---|
| `backend/alens/room_chat.py` | 구역별 프롬프트·폴백·풀·시간대 버킷 (LLM 호출은 `translator`와 같은 httpx 패턴) |

| `frontend/src/main.ts` | 말풍선 재생(타이핑·턴 간격·취소), 대사 선입 큐, 배지 결정론 문구 |
| `frontend/src/style.css` | `.pixel-bubble` — 패널과 같은 픽셀 폰트, 꼬리 삼각형 |

## 7. 취소 규칙

말풍선은 **다음 중 하나라도 발생하면 즉시 사라진다**: 다른 곳 클릭, `Esc`, 창 리사이즈
(씬 배율이 바뀌면 좌표가 어긋난다), 방을 벗어남, 다른 오브젝트 클릭(새 대사로 교체).

## 8. 검증

- 프리셋 5종에서 창문·정수기 클릭 → 말풍선이 해당 오브젝트 위에 뜨고 2~3턴 재생.
- 책장 본체·칠판 클릭이 여전히 각 탭으로 진입(구멍 뚫린 뒤에도 남는 영역이 충분한지).
- 책장 배지 클릭 → 건수 문구 + 문서함 안내(탭은 자동으로 열지 않는다).
- LLM 미설정 상태에서도 폴백으로 재생(설정 창 LLM URL 비우고 확인).
- 리사이즈·`Esc`·다른 곳 클릭에서 말풍선이 남지 않음.
