# 방문 스폰 위치 분산 (V1) — 설계

- **날짜**: 2026-07-27
- **컴포넌트**: a-hub `life/` (life_server)
- **상태**: 설계 승인 (구현 전)
- **관련**: 로드맵 4차 배치 V1 — [2026-07-26-life-social-diary-followups-roadmap.md](../../a-mate/plans/2026-07-26-life-social-diary-followups-roadmap.md)

## 배경·증상

2026-07-27 G4 스모크에서 방문(`life_goto`) 시 방문자가 주인(기존 점유자)과 **겹쳐 보이게** 스폰되는 문제 확인.

**조사 결과, 원인은 "고정 셀"이 아니라 "고정 앵커 주변 밀집"이다:**

- a-mate `life_goto`는 cell 미지정으로 `POST /life/{id}/enter`를 호출(`commands.rs:917-921`) → 서버 `_free_cell_locked`(`life.py:579-588`)가 셀을 배정한다.
- `_free_cell_locked`는 이미 `_occupied_locked`로 **기존 에이전트 셀 + 가구 footprint(창문 제외)를 회피**한다 — 같은 셀 겹침은 서버상 불가능.
- 그러나 배정이 고정 앵커 `(SPAWN_X, SPAWN_Y) = (8, 16)`에서 Chebyshev 거리순 첫 빈 칸이라, 주인이 앵커 근처에 서 있으면 방문자가 **바로 옆 칸**에 스폰된다. 아이소메트릭 렌더에서 스프라이트는 타일보다 크므로 인접 칸 = 시각적 겹침.

따라서 수정의 핵심은 점유 회피(이미 있음)가 아니라 **에이전트 간 최소 거리 버퍼 + 등거리 분산**이다.

## 결정 사항 (2026-07-27 브레인스토밍 확정)

| 항목 | 결정 |
|---|---|
| 스폰 정책 | **입구 앵커 유지 + 거리 버퍼** — 앵커 (8,16) 근처에서 버퍼 만족 칸 우선 |
| 버퍼 크기 | 다른 에이전트와 **Chebyshev 거리 ≥ 3** (사이 빈 타일 2칸) |
| 등거리 타이브레이크 | `sha256(f"{agent_id}:{x}:{y}")` 기반 정수 — **결정적** 분산 (내장 `hash()`는 프로세스 솔트 때문에 배제) |
| 만석 폴백 | 버퍼 사다리 **3 → 2 → 없음(현행)** 점진 완화, 전부 실패 시 현행대로 `CellTaken`("방이 가득 참") → 409 |
| 명시 cell `enter`·`move` | **버퍼 미적용** — 사용자가 고른 위치는 옆칸도 허용, 현행 정확-셀 409 의미 유지 |
| 회피 대상 | 현행 유지 — 에이전트 셀 + 가구 footprint(창문 제외) 모두 회피 |
| 계약(C2) | **변경 없음** — life API는 `contracts/` 범위 밖이고, 응답 `cell` 스키마 그대로 |
| a-mate | **변경 없음** — 결과 cell을 그리기만 함. 온프레 배포 후 실환경 스모크만 사용자 확인 |

## 알고리즘 — `_free_cell_locked` 개편

시그니처를 `_free_cell_locked(life_id, for_agent="")`로 확장한다. `for_agent`는 입장하는 에이전트 id — **자기 자신의 옛 위치를 점유·버퍼 계산에서 제외**해 자동 재입장 시 자기 잔상에 밀려나지 않게 한다. 호출자: `enter`는 `agent.agent_id`, `register`는 신규 에이전트라 기본값.

락 안에서 (호출자가 `self._lock` 보유 — 현행 계약 유지):

1. 방의 **에이전트 셀 집합**(for_agent 제외)과 **가구 점유 셀 집합**(`category != "window"`)을 한 번씩 미리 계산한다. 에이전트 집합 기준은 현행 `_occupied_locked`와 동일 — `at_life == life_id`인 모든 에이전트(`connected` 여부 무관).
2. 후보 = 전체 바닥 셀 400개를 `(앵커로부터의 Chebyshev 거리, 해시(agent_id, cell))` 오름차순 정렬.
3. 버퍼 사다리 `B ∈ (3, 2)` 순회 후 마지막으로 버퍼 없이: 각 단계에서 "빈 칸(두 집합 미포함) ∧ 모든 다른 에이전트와 Chebyshev 거리 ≥ B"인 **첫 후보**를 반환.
4. 버퍼 없는 단계까지 빈 칸이 없으면 `CellTaken("방이 가득 참")` (현행과 동일).

**행동 특성:**

- 빈 방 첫 스폰(주인 등록)은 앵커 (8,16) 자체 — 거리 0 후보는 유일해 해시 무관, **현행과 동일** (회귀 없음).
- 방문자는 주인 기준 거리 3 이상의 앵커 인접 링에 스폰되고, 같은 링 위에서는 에이전트별 해시로 흩어진다.
- 같은 에이전트 + 같은 방 상태 = 같은 셀 (결정적 → pytest로 완전 검증 가능).

**부수 정리:** `SPAWN_X`/`SPAWN_Y` 주석(`# 12`)이 실제 값(8, 16)과 달라 주석만 바로잡는다.

## 테스트 전략 (TDD)

서비스 레벨 pytest (`LifeService` 직접, 네이티브 Windows PowerShell 실행):

1. 주인이 앵커에 있을 때 방문자 스폰 → 주인과 거리 ≥ 3
2. 방문자 2명 연속 입장 → 주인·상호 간 모두 거리 ≥ 3
3. 서로 다른 에이전트는 서로 다른 셀 (해시 분산)
4. 같은 상태에서 같은 에이전트 재입장 → 같은 셀 (결정성)
5. 가구 footprint 위 스폰 금지 유지
6. 버퍼 3 만족 불가 배치 → 2로 완화 / 그것도 불가 → 버퍼 없이 배정
7. 완전 만석 → `CellTaken`
8. 자기 재입장 시 자기 옛 셀이 버퍼 계산을 방해하지 않음
9. 빈 방 첫 스폰 = 앵커 (회귀 가드)
