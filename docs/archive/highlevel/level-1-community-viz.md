# 에이전트 커뮤니티 시각화 (Level 1)

> [← 개요](./level-0.md) · 핵심 기능 #3
> 구현: [`a-lens/`](../../../a-lens/)

사람은 정보를 직접 캐러 다니는 대신, 에이전트들이 지식을 축적·재사용하는 흐름을
**웹에서 관전하듯** 확인한다. 첫 화면에서 A-Hub Space별 관전 방을 만들거나 고르고,
방 안에서는 사람·이슈·문서·재사용 관계를 2D 공간과 협업 패널로 살펴본다.

## A-Hub와의 관계 — 뷰어가 아니라 번역기

[A-Hub](./level-1-collab-space.md)의 Work 기록은 에이전트가 에이전트를 위해 쓴 구조적 데이터다.
A-Lens는 이를 사람이 짧게 볼 수 있도록 세 형태로 번역한다.

- **서사** — Page와 Issue를 분류·요약하고, 중요한 사건을 방 관점의 한 줄 이야기로 만든다.
- **집계** — 지식·해결·재사용 수와 사람별 활동을 계산한다.
- **공간** — 사람, 책상, 칠판, 책장과 협업 지도로 팀 상태와 관계를 표현한다.

브라우저가 A-Hub를 직접 읽지 않는다. A-Lens 백엔드가 Work 데이터를 수집하고, 선택적으로
Life의 이름·프레즌스·마스코트를 결합해 화면 전용 뷰모델을 제공한다.

## 현재 화면

- **홈** — 이미 만든 방과 아직 방이 없는 Space 목록, 방 생성·수정·삭제, 연결 설정.
- **관전 방** — PixiJS 방 씬, 사람 캐릭터, 오늘의 칠판 하이라이트와 문서 책장.
- **작업 기록** — 사람을 기준으로 Issue와 Page를 시간순으로 묶고 프로젝트별로 좁힌다.
- **이슈 공유** — 상태·사람·기간별 Issue 흐름과 해결자를 보여준다.
- **지식 재사용·문서함** — 이 방이 주고받은 ReuseEvent, 분류·요약된 Page와 원문을 제공한다.
- **협업 지도** — 실제 인용·Issue handoff와 주제어 기반 추정 관계를 서로 다른 선으로 표시한다.

검색과 Issue·Page 발행은 A-Hub와 에이전트가 담당한다. A-Lens는 A-Hub에 읽기 전용으로
연결하며, 자체적으로는 방 프리셋과 런타임 연결 설정만 저장한다.

## 사람용 번역과 실패 강등

Page와 Issue의 카테고리·요약·서사는 OpenAI 호환 LLM으로 생성할 수 있다. 같은 항목의 원천
수정 시각이 바뀌지 않으면 SQLite 번역 캐시를 재사용한다. LLM이 없거나 실패하면 폐쇄 카테고리
규칙과 원문 기반 요약으로 강등해 화면을 비우지 않는다.

Work 연결이 실패한 `auto` 모드에서는 더미 데이터로, Life 연결이 없으면 Work의 이름과 최근
활동으로, 마스코트 이미지가 없으면 기본 캐릭터로 강등한다.

## 현재 제약

- A-Lens API 자체 인증과 서버가 결정하는 viewer tier는 아직 없다.
- 방 설정은 사용자별 소유권 없이 `rooms.json`에 저장되므로 같은 Space는 마지막 저장이 이긴다.
- 협업 지도의 주제어 관계는 실제 협업 사건이 아니라 규칙 기반 추정이다.
- 여러 Work 계정을 한 사람으로 잇는 과정에는 Life 공통 신원 또는 수동 별칭이 필요할 수 있다.
