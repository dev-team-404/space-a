> **목적**: 방 사이드바에 "이 방 사람들이 누구와 이어져 있는가"를 한 장의 그래프로 보여준다.

> 이어져 있고 누가 혼자인지**가 한눈에 읽힌다.

## 1. 왜 "협업"이 아니라 "주제 겹침"이 주인공인가

원래 요청은 "작업 기록에서 각 에이전트가 **누구와 협업하고 있는지**"였다. 배포 허브
(`spacea.msalt.net`) 실데이터를 그대로 세어본 결과가 이렇다 (2026-07-31 실측, `sw-innov`).

| 협업 신호 | 실측 | 판정 |
|---|---|---|
| 이슈 핸드오프 (A가 연 이슈를 B가 해결) | 이슈 145건, 조인 성공 142건 → **사람 간 핸드오프 0건** (142건 전부 자문자답) | 데이터는 읽히는데 **사건이 없다** |
| 인용(재사용) | `knowledge_linked` 이슈 **1건**, `GET /reuse-events`는 **404** | 사건도 희소하고 조회 경로도 막힘 |
| 문서 트리 인접 (A 문서 밑에 B가 붙임) | 페이지 156건 **전부 depth 0** (중첩 0건) | 엣지 0 |
| 같은 방 공동 소속 | 전원 `sw-innov` 한 방 | 완전그래프 = 정보량 0 |
| 방명록·방 방문 (life) | life 서버 무응답, `visits`는 `/life/me/visits`뿐(본인 방만) | 전수 수집 불가 |

즉 **접근이 막힌 게 아니라 사람 사이의 협업이 실제로 일어나지 않았다.** a-mate가 각자
자기 세션 요약을 자동 발행하는 구조라 자연스러운 결과다. 여기서 "협업 그래프"를 그리면
정직하게는 선이 한 개도 없는 그림이 나온다.

그래서 **질문을 바꾼다.**

> "누가 누구와 협업했나" → **"누가 같은 문제를 따로 풀고 있나"**

이건 협업의 부재를 감추는 우회가 아니라 **북극성(지식 재사용)과 같은 방향의 질문**이다.
"너희 둘이 같은 걸 각자 풀었다"는 사실 자체가 재사용이 0인 이유를 설명한다. 사실 엣지
2종은 **그대로 구현해 둔다** — 지금은 0건이지만 협업이 실제로 일어나는 순간 자동으로 켜진다.

## 2. 엣지 3종

| 종류 | 의미 | 방향 | 원천 | 현재 실측 | 표시 |
|---|---|---|---|---|---|
| `reuse` | B가 쓴 지식을 A가 자기 이슈에 인용 | A→B | `detail.reuse_events`의 `by` × 문서 저자 | 0건 (허브 404) | **굵은 실선** + 화살표 |
| `handoff` | A가 연 이슈를 B가 해결 | A→B | 이슈 × 파생 문서 (§3) | 0건 (전부 자문자답) | 실선 + 화살표 |
| `topic` | 두 사람의 문서가 같은 주제어를 공유 | 무방향 | 문서 제목·본문 (§4) | **9쌍** | **점선**, 방향 없음 |

**등급은 섞지 않는다.** `reuse`·`handoff`는 서버에 기록된 사건이고 `topic`은 텍스트에서
유도한 추정이다. 굵기·색이 아니라 **선 종류(실선/점선)** 로 가르는 이유는, 굵기는 상대적이라
"진한 선 = 확실한 사실"로 오독되기 때문이다.

## 3. 이슈 ↔ 해결 문서 잇기 (타임스탬프 조인)

`handoff` 엣지를 그리려면 "이 이슈를 누가 해결했나"를 알아야 하는데, 배포 허브에는 그 링크를
주는 경로가 없다.

- `Page.issue_id`는 **모델에는 있고**(`ahub/core/models.py`) REST 응답에는 **없다**
  (`GET /pages/{id}`·`GET /spaces/{id}/tree` 둘 다 미노출).
- 파생 문서의 제목은 이슈 제목이 아니라 `resolve_issue(summary=...)` 인자다 →
  제목 조인 실패 (실측 156건 중 **0건** 매칭).

대신 `resolve_issue`가 **이슈와 파생 페이지에 같은 타임스탬프(`_ts`)를 찍는다**
(`ahub/core/services.py`). 이걸 조인 키로 쓴다.

```
issue.updated_at == page.created_at  (문자열 완전 일치)
  → 그 페이지의 created_by = 이 이슈를 해결한 사람
```

| 검증 | 결과 |
|---|---|
| 매칭된 이슈↔문서 | **142** / 문서 156 |
| 같은 타임스탬프에 이슈 2건 이상 (모호) | **0건** |
| 매칭 후 opener ≠ resolver | **0건** (전부 자문자답) |

**모호하면 잇지 않는다.** 같은 타임스탬프를 가진 이슈가 2건 이상이면 그 조인은 통째로
버린다 — 추측으로 남의 해결을 다른 사람에게 붙이는 것이 선을 안 그리는 것보다 나쁘다.

부수 효과로 이슈 타임라인의 `resolved` 단계 행위자가 정확해진다. 지금은 상태와 무관하게
opener를 행위자로 적고 있어서, 남이 해결한 이슈도 "연 사람이 해결 완료"로 보인다
(오늘 데이터에선 차이가 없지만 첫 핸드오프가 생기는 순간 틀린 화면이 된다).

## 4. 주제 겹침 산출

### 4.1 왜 형태소 분석기를 안 쓰나

새 의존성(konlpy 등)은 JVM·사전을 끌고 온다. a-lens 백엔드 의존성은 지금 fastapi·uvicorn·
httpx 셋뿐이고, 이 기능 하나로 그 균형을 깨지 않는다. 대신 **접미 규칙 + 문서빈도 컷**으로
근사한다 — 완벽한 명사 추출이 목적이 아니라 **두 문서가 같은 주제인지**만 판정하면 된다.

### 4.2 토큰화 규칙

말뭉치의 성격이 규칙을 정했다. 실데이터 156건은 **a-mate가 만든 세션 요약 한 문장**이고
(본문 있는 문서는 14건뿐, 평균 104자), 요약체 서술어가 어휘를 지배한다.

| 단계 | 규칙 | 이유 |
|---|---|---|
| 정규화 | 소문자화, `[0-9a-z가-힣-._/]` 외 → 공백 | `a-mate`·`build.rs`·`claude.jsonl`을 한 토큰으로 살린다 |
| 조사 제거 | 꼬리 조사 목록 제거 (`을`·`를`·`에서`·`으로`…), **떼고 2자 이상 남을 때만** | `의`를 떼려다 1자가 되는 것 방지 |
| 혼합 토큰 조사 | 영문+한글(`powershell과`·`docker를`)은 한글 꼬리를 통째로 제거 | 안 떼면 같은 용어가 조사별로 다른 주제어가 되어 겹침이 흩어진다 |
| 어미 제거 | 3자 이상이면 끝의 `한`·`하` 1자 제거 | `다양한→다양`·`진행하→진행`. **2자는 안 건드린다** — `권한`·`제한`이 죽는다. `인`은 빼면 `파이프라인→파이프라`가 되므로 넣지 않는다(`~적인`은 아래 서술어 규칙이 잡는다) |
| 서술어 배제 | `했`·`였`·`었`·`겠`·`습니`가 들어갔거나 `다`·`요`·`적`으로 끝나면 버림 | `진행했습니다`·`성공적`이 상위 키워드를 다 먹었다 |
| 횟수 배제 | `^\d+[가-힣]+$` (`5회`·`14회의`) | 도구 실행 횟수는 주제가 아니다 |
| 길이 | 한글 2~8자 / 영문 3자 이상 | |
| 불용어 | 요약체 상용어 고정 목록 (`작업`·`오류`·`도구`·`확인`…) | 문서빈도 컷만으로는 활용형이 갈려 안 걸린다 |
| 문서빈도 컷 | **2 ≤ df ≤ 30%·N** 인 토큰만 사용 | 1회짜리(우연)와 흔한 말(무의미) 양쪽 제거 |

### 4.3 엣지 판정

```
문서쌍 (d1, d2), 저자가 서로 다를 때만
  shared = keywords(d1) ∩ keywords(d2)
  score  = Σ idf(t) for t in shared,    idf(t) = ln((N+1) / df(t))
  자격    = len(shared) ≥ 2  AND  score ≥ 1.0 × ln(N+1)

사람쌍 엣지 weight = 자격을 얻은 문서쌍 수
근거(evidence)     = 공유 빈도 상위 키워드 5개 + 점수 최고 문서쌍 1개
표시               = weight 상위 12개 엣지까지 (잘린 수는 stats.dropped_edges)
```

**임계는 절대값이 아니라 `ln(N)` 비율이다.** idf는 문서 수에 비례해 커지므로, 156건짜리 방에서
맞춘 절대 임계(5.0)를 20건짜리 방에 쓰면 어떤 겹침도 통과하지 못한다. 실데이터 튜닝값
5.0 ÷ ln(157) ≈ 1.0을 비율로 고정해 **큰 방의 동작은 그대로 두고 작은 방만 살렸다**.
idf에 `+1` 평활을 넣은 것도 같은 이유 — 문서가 2건이면 `ln(N/df)`가 0이 되어 점수가 안 붙는다.

**임계값 근거** — 실데이터 156건으로 탐색한 결과 (df 컷 × 최소 공유어 × 최소 점수):

| 파라미터 | 엣지 수 | 관측 |
|---|---|---|
| 20% / 3 / 8.0 | 3 | 너무 성김 — `a-hub·life·docker` 같은 진짜 겹침이 잘려나감 |
| **30% / 2 / 5.0** | **9** | 채택. 사람 7명에 엣지 9개 = 읽히는 밀도 |
| 30% / 2 / 4.0 | 14+ | 서술어 잔여가 다시 올라옴 |

채택 설정의 실제 산출(사람쌍 · 대표 키워드):

| 사람쌍 | 문서쌍 | 공유 키워드 |
|---|---|---|
| coolfebreeze ↔ kimmy-claude | 50 | 구현, askuserquestion, 브랜치, 설계 |
| kimmy-claude ↔ palendy | 29 | playwright, 브랜치, 공용, a-mate |

## 5. 사람 동일시

한 사람이 허브 계정을 여러 개 갖는다(등록 경로가 여럿). 노드가 갈라지면 그래프가 통째로
거짓말이 되므로, `collector._merge_people`이 이미 합쳐 놓은 결과를 **그대로 따른다**.

| 재료 | 용도 |
|---|---|
| `agent.agent_id` | 노드의 정식 키 |
| `agent.merged_ids` | 흡수된 옛 계정 id — 이 id로 남은 기록도 같은 노드로 |
| `agent.name` · `hub_name` | 이름으로만 남은 기록(`reuse_events.by`)의 폴백 조인 |

**계정 id가 남의 표시 이름을 항상 이긴다.** 조인 인덱스를 한 바퀴로 만들면 목록 앞쪽 사람의
*이름*이 뒷사람의 *id* 자리를 차지한다 — 실측에서 허브에 `agt_9`(표시 이름 `kimmy-claude`)와
`kimmy-claude`가 둘 다 있어 문서 36건이 엉뚱한 노드로 갔다. 그래서 id·`merged_ids`를 먼저
전부 등록하고, 이름은 그 다음 바퀴에서만 빈자리를 채운다.

여기서 **새 추측을 만들지 않는다.** 못 이은 작성자는 노드를 만들지 않고 그 문서를 통계에서
뺀다(`stats.unlinked_docs`로 보고).

**방 밖 사람(external).** 우리 지식을 가져간 사람이 다른 방 소속이면 노드가 없다. 이때는
지우지 않고 `ext:<이름>` 노드를 바깥 고리에 세운다 — "우리 지식이 밖에서 쓰였다"가 이 엣지의
값어치이므로 상대를 지우면 엣지 자체가 사라진다. 점선 테두리 + 기울인 이름으로 구분하고,
이 노드는 클릭해도 작업 기록으로 가지 않는다(이 방에 기록이 없다).

## 6. 화면

### 6.1 배치

**별도 탭이 아니라 `작업 기록` 탭 하단에 붙인다.** 탭을 하나 더 만들면 눌러야 보이는데,
이 지도는 사람별 기록을 보는 바로 그 맥락에서 같이 읽혀야 한다. 로비 전체 지도도 아니다 —
실데이터가 한 방에 몰려 있어 로비 그래프는 사실상 이 방 그래프와 같다.

작업 기록 탭은 두 화면이고, 지도는 **양쪽 모두**에 붙되 범위가 다르다.

| 화면 | 지도 범위 | 제목 |
|---|---|---|
| 사람 목록 (전체 보기) | 방 전체 | `협업 지도` |
| 한 사람 선택 | 그 사람에 걸린 선과 상대만 | `이 사람과 이어진 선` |

한 사람만 볼 때는 방 전체 집계 줄(인용/핸드오프/겹침 수)을 붙이지 않는다 — 그 사람 얘기가
아닌 숫자를 그 사람 화면에 두면 오독된다.

```
┌─ 작업 기록 ──────────────────┐
│ 사람 목록 / 선택한 사람의 기록  │
├─ 협업 지도 ──────────────────┤
│ 실선 사실 · 점선 주제 겹침(추정) │  ← 범례
│                              │
│      (원형 배치 SVG)          │  ← 사람 = 마스코트/점, 선 = 엣지
│                              │
│ 인용 0 · 핸드오프 0 · 겹침 8   │  ← 요약 줄(정직성, 전체 보기에서만)
└──────────────────────────────┘
   ↑ 선을 클릭하면 지도 **왼쪽 바깥**에 설명 카드 (§6.2·§6.4)
```

- **원형(방사형) 배치.** force 시뮬레이션은 프레임마다 좌표가 흔들려 "볼 때마다 다른 그림"이
  된다. 사람 수가 10명 안팎이므로 이름 가나다순 고정 원형이면 **매번 같은 자리**에 온다.
  방 밖 사람(external)은 이름순 정렬 뒤에 이어 붙어 항상 고리의 끝자락에 온다.
- 노드 = 마스코트 이미지(있으면) / 없으면 상태 점. 이름은 노드 아래 라벨.
- 엣지 = 두 노드를 잇는 2차 베지어. 굵기 = `1 + log(weight)`, 상한 4px.
- **그림의 선 클릭 → 지도 바로 왼쪽에 설명 카드**가 뜬다. 지도와 목록이 세로로 떨어져 있어
  그림에서 고른 선의 설명을 보려면 목록을 찾아 스크롤해야 했다. 카드는 사이드바 왼쪽
  바깥(상세 패널 `#panel`과 같은 자리 규칙)에, **클릭한 선의 높이**에 맞춰 띄운다 —
  어느 선을 눌렀는지 눈이 따라간다. 화면 위아래로 넘치지 않게 가두고, 오른쪽 삼각형이
  지도를 가리킨다. 닫기는 ✕·같은 선 재클릭·Esc. 창 크기가 바뀌면 좌표가 어긋나므로 닫는다.
- **선은 보이는 굵기보다 넓게 잡힌다.** 같은 경로에 투명한 두꺼운 선(`stroke-width: 16`)을
  깔아 클릭 판정으로 쓴다 — 얇은 곡선을 정확히 겨냥하는 건 어렵다. 사람 노드는 선보다 뒤에
  그리므로 이 넓은 판정 영역이 사람 클릭을 뺏지 않는다.
- 노드 클릭 → 그 사람의 작업 기록으로 (기존 동선과 동일). external 노드는 이 방에 기록이
  없으므로 클릭해도 아무 일도 하지 않는다.

### 6.3 엣지 목록은 두지 않는다

지도 아래에 엣지를 나열하지 않는다. 클릭 시 카드가 같은 내용을 보여주므로 목록은 **같은
정보의 두 번째 표면**이고, 줄마다 같은 문장(대부분 `topic`이라 "주제 겹침 · 같은 주제를
다뤘어요")이 반복되며 사이드바만 길어졌다. 지도 아래에 남는 것은 요약 줄뿐이다.

```
인용 0 · 핸드오프 0 · 주제 겹침 8
이슈 146건 중 143건을 스스로 해결 · 작성자 연결 못 함 5건 · 지도에 그릴 기록이 없는 계정 6명 제외
```

예외는 하나 — **선이 하나도 없을 때**는 "각자 따로 일했어요" 한 줄을 남긴다. 선 없는 지도는
"고장났나"로 읽히기 때문이다(§7).

### 6.4 "무엇이 통했나" — 근거 펼침

키워드 나열만으로는 "그래서 왜 이어졌지?"가 안 풀린다. 선을 고르면 **실제 문서·이슈 제목**을
그 자리에 펼치고, 제목을 누르면 기존 원문 모달을 연다.

| 엣지 | 펼치는 것 | 머리말 |
|---|---|---|
| `topic` | **문서쌍 3개** — 누구 문서인지 이름을 함께 (`doc_pairs`는 [source쪽, target쪽] 순서 보장) | 겹친 문서 |
| `reuse` | 재사용된 문서 최대 3건 | 가져다 쓴 지식 |
| `handoff` | 넘겨받아 해결한 이슈 최대 3건 | 넘겨받아 해결한 이슈 |

**문서쌍은 점수순이되 같은 문서를 두 번 쓰지 않는다.** 점수 상위 3개를 그냥 고르면 인기
문서 하나가 세 쌍에 모두 끼어 같은 제목이 세 번 나온다(실측에서 그랬다) — 근거가 3개처럼
보이지만 사실 1개다. 후보 24개를 들고 있다가 문서가 겹치지 않게 골라 **서로 다른 문서 6개**로
채운다. 다양한 쌍이 모자라면 점수순으로 채우고 빈칸으로 두지 않는다.

제목은 **한 줄로 자른다**. 두 줄까지 풀면 근거 블록이 목록만큼 길어져 원래 문제로 돌아간다.

**겹친 말은 금색으로 짚는다.** 제목 안에 그 말이 실제로 박혀 있으면 그 자리를 칠하고
(`.kw-hit`), 쌍 아래 공유 주제어 줄도 같은 금색으로 둔다. 둘 다 두는 이유 — 주제어는
제목뿐 아니라 요약·본문에서도 뽑히므로 **제목에 그대로 박히는 건 절반쯤**이다(실측 6개 중 3개).
제목 강조만 두면 나머지 절반은 근거가 비어 보인다.

### 6.5 네 탭 공통 — 중요한 말 금색 강조

같은 금색 규칙을 사이드바 전체(작업 기록·이슈 공유·지식 재사용·문서함)로 넓힌다. 제목과
요약에서 **그 항목을 다른 항목과 구별해주는 말**이 금색으로 보인다.

| 항목 | 근거 |
|---|---|
| 색인 | 서버가 `collab.terms`로 준다 — 항목 id → 주제어 최대 3개 |
| 기준 | **협업 지도와 같은 IDF 표**(`build_idf`). 기준이 갈리면 지도에서 근거로 나온 말이 목록에서는 안 짚어진다 |
| 대상 | 문서는 제목+요약+본문에서, 이슈는 본문이 없으므로 제목에서 |
| 범위 | 저자를 못 이은 문서도 포함 — 강조는 사람과 무관하다 |

흔한 말은 IDF 컷에서 이미 빠지므로, 남은 것 중 상위만 고르면 "이 항목이 무엇에 관한 것인지"가
남는다(실측: `docker`·`compose`, `브랜치`·`구현`, `대시보드`·`현황`).

### 6.2 색

| 요소 | 값 |
|---|---|
| `reuse` 실선 | 금색 (기존 하이라이트 강조색과 동일) |
| `handoff` 실선 | 청록 |
| `topic` 점선 | 회색 (`stroke-dasharray: 4 3`) |

## 7. 정직성 규칙

이 화면의 가장 큰 위험은 **없는 협업을 있어 보이게 만드는 것**이다.

1. **추정을 사실처럼 그리지 않는다.** `topic`은 점선 + 범례에 "추정" 명시. 툴팁 문구도
   "함께 일했어요"가 아니라 **"같은 주제를 다뤘어요"**.
2. **0을 숨기지 않는다.** 요약 줄에 `인용 0 · 핸드오프 0`을 그대로 적는다. 사실 엣지가
   0건인 것은 빈 화면이 아니라 **읽어야 할 결과**다.
3. **혼자 일한 사람을 지우지 않는다.** 엣지가 없어도 **문서를 쓴 사람**은 원 위에 남긴다 —
   고립은 지울 상태가 아니라 읽어야 할 정보다. 남기는 기준은 "지도에 그릴 재료가 있는가"다:

   | 조건 | 판정 |
   |---|---|
   | 문서를 썼다 | 남긴다 (주제 겹침의 재료가 있다) |
   | 실제로 선에 걸렸다 | 남긴다 (이슈만 열었어도 남이 해결해줬으면 그 선이 있다) |
   | 둘 다 아니다 (이슈 몇 건뿐인 `bot`·`reader` 같은 테스트 계정) | **뺀다** — 어떤 선도 만들지 못하고 원만 채운다 |

   뺀 수는 `지도에 그릴 기록이 없는 계정 N명 제외`로 적는다.
4. **못 이은 기록을 보고한다.** 작성자를 사람 노드로 못 이은 문서 수를 요약 줄 끝에
   `작성자 연결 못 함 N건`으로 적는다. 문서 상한(400)이나 엣지 상한(12)에 걸려 뺀 것도
   같은 줄에 적는다 — 조용한 절단은 "다 봤다"로 읽힌다.
5. **자문자답을 셀프 루프로 그리지 않는다.** 선이 아니라 요약 줄의 문장으로 적는다
   (`이슈 142건 중 142건을 스스로 해결`) — 셀프 루프는 그래프만 어지럽힌다.

## 8. 원천별 동작

| 원천 | 동작 |
|---|---|
| `hub` | 위 규칙 그대로. 현재 `topic`만 켜진다 (실측 10개) |
| `dummy` | `topic`만. 더미 재사용 이벤트에는 **가져간 사람이 없고** 방 이름만 있어 사람 엣지를 못 만든다 (실측: soc-design 노드 10 · 엣지 12 · 생략 33) |
| `fixtures` | 재사용 픽스처에는 `consumer_agent`가 있어 `reuse` 실선 + external 노드가 나온다. 문서 수가 적어 `topic`은 거의 없다 |
| 로딩 전·계산 실패 | `collab: null` → 탭은 "아직 계산 전" 문구. 방은 정상으로 열린다 |

## 9. 비목표

- **개인 랭킹 아님.** 엣지 수로 사람을 줄 세우지 않는다 (04-data-mapping "팀 단위 — 개인
  랭킹은 비목표"와 같은 선).
- **force 레이아웃·줌·팬 없음.** 사이드바 폭에서 읽히는 정적 한 장이면 충분하다.
- **로비 전역 그래프 없음** (§6.1).
- **LLM 요약 없음.** 엣지 설명은 키워드 나열 그대로.

## 10. 허브가 바뀌면 자동으로 켜지는 것

이 스펙은 허브 재배포를 **전제하지 않지만**, 재배포되면 코드 변경 없이 살아나도록 짠다.

| 허브 변경 | 그 순간 켜지는 것 |
|---|---|
| `GET /reuse-events` 배포 | `reuse` 실선 (collector가 이미 읽고 있다 — 404를 빈 값으로 강등 중) |
| 실제 사람 간 이슈 해결 발생 | `handoff` 실선 (타임스탬프 조인은 이미 동작) |
| `Page.issue_id` 노출 | 타임스탬프 조인을 정식 링크로 교체 (§3 대체) |
