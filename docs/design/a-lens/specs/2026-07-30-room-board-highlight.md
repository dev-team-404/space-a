# 방 칠판 하이라이트 — 설계 스펙

> **목적**: 방 뒷벽 칠판에 "이 방의 오늘 가장 의미 있던 일" 한 줄을 분필로 적는다.
> 방을 열었을 때 표·숫자를 읽기 전에 **이 팀이 오늘 무엇을 해냈는지**가 먼저 눈에 들어오게
> 하는 장치.

## 1. 왜 사람별 로테이션이 아닌가

검토한 대안은 "각 사람의 오늘 하이라이트를 돌아가며 표시"였다. 두 가지 이유로 접었다.

1. **개인 랭킹은 비목표.** [04-data-mapping](../04-data-mapping.md) 대시보드 절이 이미
   "팀 단위 — 개인 랭킹은 비목표"로 못박고 있다. 칠판은 방(=팀)의 게시판이므로 주체가
   팀인 쪽이 은유에 맞다.
2. **중복.** 사람별 활동은 이미 두 표면에 있다 — 캐릭터 말풍선(`agents[].recent_activity`)과
   사람 클릭 시 사이드바 `trail` 탭. 칠판이 그걸 또 돌리면 같은 정보의 세 번째 표면이 된다.

대신 **선정 축은 팀 성과, 문장의 주인공은 사람**으로 둘을 합친다(§3). 로테이션 없이도
랭킹 1위가 바뀔 때마다 등장 인물이 자연히 바뀐다.

## 2. 선정 기준

새 기준을 만들지 않는다. 2026-07-14에 이미 정해진 로비 하이라이트 랭킹을 **방 범위로
좁혀 그대로 쓴다**. 같은 랭킹을 두 표면이 공유하므로 로비의 ★와 방 칠판이 어긋나지 않는다.

```
1. reused (크로스팀이면 가점)   ← 지식이 방 밖으로 나가 쓰였다. 가장 희소하고 자랑할 일
2. skill_proposed
3. knowledge_created            ← 문서함에 새 자산이 들어왔다
4. condensed
5. issue_opened
동점 → 최신순
```

**방 범위 필터** — 아래 둘 중 하나면 이 방의 이벤트다.

| 조건 | 뜻 |
|---|---|
| `event.space_id == 방` | 이 방에서 일어났다 |
| `doc_id`의 원천이 이 방 | 이 방의 지식이 다른 방에서 재사용됐다 (`reused`) |

두 번째 조건이 핵심이다. 이게 없으면 "우리 지식이 다른 팀에 쓰였다"는 가장 가치 있는
사건이 정작 원천 방 칠판에는 안 뜨고 소비한 방에만 뜬다.

**기여 우선 (동급 세부 순위)** — 한 재사용 이벤트는 원천 방과 가져간 방 **양쪽** 풀에 걸린다.
등급이 같을 때는 **기여(우리 것이 나갔다)를 소비(우리가 가져왔다)보다 앞**에 둔다. 북극성이
기여↔소비 중 기여 쪽이므로 자기 칠판에는 자랑할 쪽을 먼저 적는다.

### 오늘 아무 일도 없으면

**범위를 넓힌다** — 하루치로 자르지 않고 스냅숏 전체 풀에서 뽑고, 오늘이 아닌 항목엔 시간
접두를 붙인다. 빈 칠판은 관전 UI에서 죽은 방으로 읽히므로 피한다.

```
(지난주) 민수님이 쓴 『배포 체크리스트』, 플랫폼팀이 가져갔어요
```

**#40 제약** — 허브 `knowledge_created` 이벤트에는 아직 타임스탬프가 없다
(`collector._hub_snapshot`이 `at`을 안 싣는다). 시각을 모르는 이벤트에는 시간 접두를
**붙이지 않는다** — "오늘"로 단정하지도, 가짜 날짜를 만들지도 않는다. `#40`으로 실 시각
필드가 들어오면 접두가 자동으로 붙기 시작한다.

풀 자체가 비면(그 방에 org-safe 이벤트가 하나도 없으면) 칠판은 빈칸이다. 넓힐 대상이
없는 정직한 빈칸이므로 문구를 만들지 않는다.

## 3. 문장 규칙 — 주인공은 사람

**이 방의 관점으로 쓴다.** 같은 재사용 이벤트가 양쪽 칠판에 걸리므로, 방향을 안 보면 내 방
칠판에 내 방 이름이 3인칭으로 나온다 (`SoC 설계팀` 칠판에 "SoC 설계팀이 가져갔어요").

| 이벤트 | 이 방의 위치 | 칠판 문장 |
|---|---|---|
| `reused` (크로스팀) | 원천 — 우리 것이 나갔다 | `민수님이 쓴 『배포 체크리스트』, 플랫폼팀이 가져갔어요` |
| `reused` (크로스팀) | 소비 — 우리가 가져왔다 | `플랫폼팀 민수님의 『배포 체크리스트』를 가져와 썼어요` |
| `reused` (같은 팀) | — | `민수님이 쓴 『배포 체크리스트』, 팀에서 다시 꺼내 썼어요` |
| `knowledge_created` | — | `민수님이 『배포 체크리스트』를 문서함에 넣었어요` |
| `issue_opened` | — | `‘로그인 실패’ 이슈를 민수님이 올렸어요` |

- 저자를 모르면(저자 미상 문서) 사람 없이 팀 주체로 적는다 — 없는 이름을 만들지 않는다.
- **제목을 모르면 서버 `summary`를 그대로 쓴다.** 문장을 억지로 조립하지 않는다 (픽스처처럼
  구조 필드가 얕은 소스의 안전망).
- 조사(`을/를`·`이/가`)는 앞 낱말의 종성으로 고른다 — `『회고』를` / `『기록』을`.
- **한 줄 예산 48자.** 허브 페이지 제목은 a-mate가 LLM으로 만든 여러 문장짜리라 실측 151자까지
  나온다 — 그대로 실으면 칠판을 덮는다. 고정 길이로 제목을 자르는 게 아니라 **예산에서 문장
  나머지(사람 이름·팀 이름·시간 접두)를 뺀 만큼만** 제목에 주고 `…`로 자른다. 팀 이름이 길면
  제목 몫이 줄어드는 식이다.
  - 시간 접두도 같은 한 줄이므로 예산에 포함한다 (안 그러면 접두 붙은 줄만 길어진다).
  - 제목은 최소 12자는 보여준다 — 이 하한 때문에 최대 50자까지 나갈 수 있다.
  - `summary` 폴백도 같은 예산으로 자른다.
- 조사는 **말줄임표를 뗀 어간**으로 고른다 — `『…클론한…』을`.

## 4. 데이터 형태

방 뷰모델의 `highlight`는 이미 프론트가 기대하는 형태가 있다 (`api.ts: SpaceHighlight`).
그 형태를 유지하고 `kind`에 `knowledge`를 추가한다.

```ts
type SpaceHighlight = {
  text: string                                  // 칠판에 적히는 한 줄
  kind?: 'reuse' | 'knowledge' | 'issue'
  doc_id?: string                               // kind=reuse|knowledge
  issue_id?: string                             // kind=issue
}
```

`kind`는 **칠판 클릭 연동**에만 쓰인다 — 클릭하면 사이드바에서 관련 항목을 강조한다.

| `kind` | 여는 탭 | 강조 대상 |
|---|---|---|
| `reuse` | 지식 재사용 | `[data-reuse-doc]`·`[data-docid]` |
| `knowledge` | 문서함 | `[data-docid]` (**신규**) |
| `issue` | 이슈 흐름 | `[data-issue]` |

로비 층 목록의 `floors[].highlight`는 지금처럼 **문자열**을 유지한다 (hover 카드 1줄).

## 5. 권한 — 이름 노출은 G7의 의도적 예외

[04-data-mapping](../04-data-mapping.md) 권한 절(2026-07-14 보강)은 로비·게스트 노출 풀을
org-safe 이벤트로 제한하고, 멤버 서사(이름·이슈 제목)를 게스트에 안 내보내는 걸 원칙으로
둔다. 칠판 이름 노출은 그 원칙의 **명시적 예외**다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 노출 풀 | org-safe 유지 (`issue_opened` 제외) | G7 그대로 — 이슈 제목은 여전히 멤버 전용 |
| 사람 이름 | **게스트에도 노출** | 사내 팀 간 열람이고, 이름만으로는 업무 내용이 새지 않는다. "누가 기여했나"가 보이는 게 재사용 문화의 동기 |

→ 계약 소유자에게 전달할 항목: **게스트 tier 칠판에 멤버 이름이 실린다** (G7 예외).
`issue_opened`가 게스트 풀에서 빠지는 건 변함없으므로 이슈 제목 유출은 없다.

## 6. 통일 — 지금은 소스마다 규칙이 다르다

같은 칠판인데 데이터 소스별로 규칙이 셋이다. 이번 작업의 실질은 이 불일치 제거다.

| 소스 | 현재 | 이후 |
|---|---|---|
| 허브 실데이터 | **항상 빈칸** (`collector.py` 층 목록에 `highlight: None`, 방 상세엔 키 자체가 없음) | 랭킹으로 선정 |
| 더미 데모 | 자체 규칙 — 최다 재사용 문서 > 해결 이슈 (`_generate.py`) | 자체 규칙 제거, 랭킹으로 선정 |
| 픽스처 | `spaces.json` 하드코딩 | 층 목록은 픽스처 유지, 방 칠판은 랭킹으로 선정 |

선정은 한 곳에서만 한다 — `pipeline`이 소스에 무관하게 이벤트 풀에서 뽑는다. `pipeline`이
결정론 가공을 담당한다는 [ADR 0003](../../../adr/0003-a-lens-server-and-frontend-stack.md) §2
역할 분담 그대로다.

## 8. 비목표

- **LLM 문장 생성** — 선정도 문장도 결정론. 창문 잡담과 달리 칠판은 사실을 적는 자리다.
- **여러 줄·여러 건** — 칠판은 1건. 나머지는 사이드바가 이미 전부 보여준다.
- **"오늘" 정확 필터** — `#40` 실 시각 필드 이후. 지금은 풀 전체 + 시간 접두로 대체한다.
- **개인 기여 랭킹** — 비목표(§1). 이름은 문장의 주인공일 뿐 순위가 아니다.
