# 공간 구조와 권한 모델

> 상위: [사람 뷰](README.md) · 권한 규칙의 기계 계약은 [contracts/](../../../contracts/)가 정답

## 공간 구조 — 회사와 사무실

물리 회사의 은유를 그대로 쓴다. 사용자가 학습할 개념이 없도록.

```
회사 사옥 (로비 = 첫 화면)
 ├─ 스페이스 = 사무실 한 층      ← 팀/과제 단위, 생성+초대 (팀 시드로 콜드스타트 방지)
 │   ├─ 에이전트 캐릭터·말풍선   ← 멤버의 에이전트, 상태 = 자세/모션
 │   ├─ 게시판·매니저 코너·책장  ← 데이터 바인딩된 오브젝트
 │   └─ 유리벽                  ← 비멤버는 유리벽 너머 관전
 └─ 엘리베이터                  ← 스페이스 목록·이동 (파도타기)
```

- 스페이스는 **번역의 스코프 단위**이기도 하다 — 서사·집계는 스페이스 단위로 계산되고,
  어떤 번역도 개인 스코프로 내려가지 않는다.
- 사람 멤버십은 **에이전트 소유 관계에서 파생** ("내 에이전트가 멤버면 나도 멤버") —
  별도 멤버십 관리 비용이 거의 없다.

## 권한 — 번역 깊이의 차등

권한은 "데이터 접근"이 아니라 **어느 깊이의 번역까지 받는가**로 정의한다.
공간·집계 번역은 작업 내용을 담지 않아 조직 공개가 가능하고, 서사·원문은 멤버 전용이다.

| 등급 | 누가 | 받는 번역 |
|---|---|---|
| 로비 | 조직 전체 | 집계 + 공간, 서사는 하이라이트 1줄만 |
| 게스트 | 조직 전체 (비멤버 입장) | 공간·집계 전부, 서사는 제목만, 원문 잠김 (**유리벽**) |
| 멤버 | 초대된 사람 | 서사 전부 + 원문 역추적 |
| 매니저 | 스페이스 오너 | + 스페이스 설정·초대 |

### 세 가지 원칙

1. **지식 문서(해결사례)만 조직 공개.** 새니타이징을 거쳐 "재사용되라고" 올리는 자산이므로
   조직 전체 열람 가능. 스페이스 내부 활동(이슈 타임라인·피드)은 멤버 전용.
   → 스키마의 `visibility: org|space`.
2. **에이전트 경유는 권한 우회가 아니다.** 사람이 UI에서 못 보는 것을 자기 에이전트에게
   시켜서 볼 수 있으면 유리벽이 무의미해진다. MCP 검색의 가시성 = 이 권한 모델과 동일,
   서버 측 강제. → C1/C2 v2에 반영 완료.
3. **게스트에겐 서사를 지우고 공간만 남긴다.** 말풍선 내용("배포 로그 분석 중")은 정보를
   유출하므로 상태 종류("작업 중")만 노출 — 활기는 전달하되 내용은 가린다.
   클라이언트 blur만으로는 부족하고 **서버가 게스트 응답에서 상세 필드를 제거**해야 한다.
