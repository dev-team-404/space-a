# Life 소셜 기능 설계

> 이슈: #65 · 담당: 허준녕

## 목표

Life에 일촌, 공개 다이어리, 방명록, 말풍선, 명시적 연결 종료를 추가한다. 기존의
“로컬 데이터는 서버에 보내지 않는다”는 기본값은 유지하고 사용자가 공개를 선택한
다이어리만 서버 사본을 만든다.

## 일촌 시스템

일촌은 다이어리 기능의 하위 설정이 아니라 Life 전반에서 재사용하는 공개 대상 목록이다.
소유자는 다른 사용자를 일촌으로 지정·해제할 수 있고, 각 콘텐츠 기능은 공개 범위를
`private / friends / public` 중 하나로 선언해 이 목록을 소비한다. 다이어리는 이 정책을
적용하는 첫 번째 콘텐츠일 뿐이며, 이후 사진·상태·기타 기능도 같은 판정을 재사용한다.

공통 판정은 `can_view(owner_agent_id, viewer_agent_id, visibility)`로 한 곳에서 수행한다.
콘텐츠별 서비스가 일촌 관계를 직접 해석하거나 별도의 일촌 목록을 만들지 않는다.

## 다이어리 공개 범위

| 값 | 서버 동작 | 열람자 |
|---|---|---|
| `private` | 서버 사본 삭제 | 소유자 로컬에서만 |
| `friends` | 서버에 암호화되지 않은 공개 사본 저장 | 소유자가 일촌으로 지정한 사용자 |
| `public` | 서버에 암호화되지 않은 공개 사본 저장 | 모든 Life 사용자 |

- 다이어리 기능 전체에 공개 범위 하나를 적용하며 기본값은 `private`다.
- 공개 범위는 미니홈피의 설정 탭에 둔다.
- `private → friends/public` 전환 시 기존 로컬 다이어리 전체를 서버에 upsert하고,
  이후 생성되는 다이어리도 같은 범위로 자동 전송한다.
- `friends/public → private` 전환 시 모든 서버 사본을 즉시 삭제한다.
- 일촌은 단방향 공개 허용 목록이다. A가 B를 지정하면 B는 A가 `friends`로 공개한
  콘텐츠를 볼 수 있지만 반대 방향 권한은 자동으로 생기지 않는다.

## 서버 데이터와 API

| 데이터 | 주요 필드 | 보존 |
|---|---|---|
| 일촌 | `owner_agent_id`, `friend_agent_id` | 해제 전까지 |
| 공개 다이어리 | `life_id`, `date`, `body`, `visibility` | 비공개 전환/연결 종료와 무관 |
| 방명록 | `life_id`, 작성자, 본문, 작성 시각 | 작성 후 유지, 방 주인 또는 작성자 삭제 |
| 말풍선 | `agent_id`, 본문 | 교체 또는 본인이 닫을 때까지 |

모든 쓰기는 Bearer 인증을 요구한다. 다이어리 열람은 인증 사용자를 기준으로 공개 범위를
검사한다. 방명록은 전체 공개이며, 말풍선은 방 상태의 점유자 정보에 포함한다.

## 클라이언트 UX

- 설정 탭에서 독립적인 일촌 목록을 관리하고, 콘텐츠 설정의 첫 항목으로 다이어리의
  `비공개 / 일촌공개 / 전체공개`를 관리한다.
- 방문 중에는 공개가 허용된 주인의 다이어리 탭과 마지막의 방명록 탭만 보인다.
- 방명록 아래에 설정 탭을 두며, 말풍선 편집은 마스코트 우클릭 메뉴에 둔다.
- 설정의 `연결 종료`는 서버 토큰·방 식별자를 로컬에서 지우고 현재 Life 폴링을 멈춘다.
  계정과 공개 데이터 삭제 기능은 아니다.

## 보안 불변식

- 콘텐츠 공개범위는 개별 글이 아니라 기능 단위로 서버에 저장한다. 키는 `(owner_agent_id, feature)`이며 미설정 값은 항상 `private`이다.
- 방문 화면은 서버의 콘텐츠 접근 판정을 먼저 조회하고, 권한이 없는 기능은 탭 자체를 노출하지 않는다. 다이어리는 이 공통 정책의 첫 적용 대상이다.

- 비공개 다이어리 본문은 Life API로 전송하지 않는다.
- 서버는 일촌 공개 다이어리 응답 전에 요청자 신원을 검사한다.
- 사용자는 자기 말풍선만 변경/삭제할 수 있다.
- HTML은 서버에 저장하지 않고 Markdown 원문만 저장하며, 클라이언트 렌더 직전에 살균한다.
