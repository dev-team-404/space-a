# Life 서버 전환 하위호환 설계

## 문제

최신 A-Mate가 구버전 Life 서버에 연결된 상태에서는 다음 교착이 생길 수 있다.

1. 새 Life 서버 연결에는 로컬 `user_name`이 필요하다.
2. 마스코트 이름 저장은 기존 서버의 `PATCH /life/me` 성공을 먼저 요구한다.
3. 구버전 서버가 이름 변경 API를 제공하지 않으면 이름도 저장하지 못하고 새 서버에도 연결하지 못한다.

추가로 현재 연결 로직은 대상 URL이 달라져도 기존 토큰을 대상 서버에 먼저 사용하며,
연결 종료 역시 원격 disconnect 성공 전에는 로컬 연결 정보를 지우지 않는다.

## 결정

### 프로필 저장

- 프로필의 단일 원본은 로컬 DB다.
- 유효성 검사를 통과한 프로필은 원격 Life 서버 상태와 무관하게 먼저 저장한다.
- 연결된 서버의 이름 변경은 best-effort 동기화로 수행한다.
- 원격 동기화 실패는 경고 로그로 남기되 로컬 저장을 되돌리지 않는다.

### 서버 연결

- 기존 URL과 대상 URL을 후행 슬래시를 제거한 형태로 비교한다.
- URL이 다르면 기존 토큰을 사용하지 않고 대상 서버에 새로 등록한다.
- 새 등록이 성공하기 전까지 기존 연결 설정은 유지한다.
- URL이 같을 때만 기존 토큰으로 이름 변경을 시도한다.
- 같은 서버가 `404` 또는 `405`를 반환하면 구버전의 이름 변경 미지원으로 보고 기존 연결을 유지한다.
- `401` 또는 `403`이면 토큰이 거부된 것으로 보고 새로 등록한다.

### 연결 종료

- 사용자의 연결 종료 의도는 로컬 연결 해제를 의미한다.
- 원격 disconnect는 best-effort로 호출하고, 실패해도 로컬 토큰·에이전트·방 식별자를 지운다.
- 원격 실패는 경고 로그에만 남긴다. 서버의 기존 방과 공개 데이터는 유지된다.

## 검증

- URL 정규화 후 동일 서버와 다른 서버를 구분한다.
- `401/403`, `404/405`, 기타 오류를 서로 다르게 분류한다.
- 구버전 서버 연결 상태에서도 프로필 이름을 로컬에 저장할 수 있다.
- 다른 URL로 전환할 때 기존 토큰을 재사용하지 않는다.
- 원격 disconnect 실패에도 로컬 연결 상태는 해제된다.
