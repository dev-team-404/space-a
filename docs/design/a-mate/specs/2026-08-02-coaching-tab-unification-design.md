## 1. 배경 & 문제 정의

코칭 탭에 성격이 다른 두 덩어리가 한 화면에 섞여 있다. 하나는 **내 로그 기반 패널**(「오늘의 배움」 TipCard), 하나는 **조건별로 생성되는 룰 카드**(findings)다. 같은 "코칭"인데 카드 문법·수명·처분 모델이 전부 다르다.

### 1.1 현행 실측 (2026-08-02, 코드 기준)

**① 「오늘의 배움」 TipCard 1장** — 큰 카드 1건 + 접힌 목록 3건. `ops::run_curation`이 6개 소스를 **하나의 풀에 섞어** 점수순 정렬한 뒤 상위 4건만 노출한다.

| 소스 | 규모 | 배지 | 점수 |
|------|------|------|------|
| 내장 커리큘럼 팁 (T3) | 19개 고정 | 축 이름 | 프론티어 500 / 미래축 100↓ / 숙달축 −1000 |
| **개인 실전 레슨** (`content::personal_lessons`) | 최대 7종 | **내 로그 맞춤** | **550 (최상위)** |
| plugin 추천 (E, `plugin_reco`) | work-kind별 | 축 / 새 소식 | 300 |
| Claude Code changelog | 최대 1 | 새 소식 | 25 |
| Boris 팁 (외부 HTML) | 최대 8 | 축 | 300~500 |
| a-hub 팀 지식 | 최대 N | 축 | 300~500 |

개인 실전 레슨 7종: `lesson-struggle`, `lesson-cache`, `lesson-cache-create`, `lesson-model`, `lesson-praise-cache`, `lesson-praise-struggle`, `lesson-weekly-{YYYY}-W{ww}`, `lesson-frontier`.

**② 룰 카드 (findings)** — `ops::registered_rules()`에 실제 등록된 룰은 **R6·R7·R8 셋뿐**이다. R1·R2·R5·R9·R10·R11·R12·R24는 은퇴했고 매 스캔 `delete_findings_by_rule_and_scope`로 purge된다.

### 1.3 사용자가 요구한 것

1. 두 덩어리를 통일성 있게 정리하고 실제로 도움이 되게 할 것
2. 외부에서 배우는 카드는 **링크만 주지 말고 핵심 요약을 카드에 노출**(카드뉴스), 클릭하면 전문
3. **Claude Code 출시·프로모션 소식**을 수집해 노출 (예: Fable 출시, 기간 한정 세션 한도 2배)
4. 로그 기반 코칭은 카드로 나열하고 **수명 관리**
5. 기한이 있는 공지는 사용자가 [확인]을 누르기 전까지 최상단 유지 — **유효한 기한인 것만**
6. 개인 레슨의 "솔루션 소스 링크"를 유지할지 판단

## 2. 목표 / 비목표

**목표**
- 코칭 탭을 **근거 출처**로 2단 분리하고 카드 문법을 2종으로 통일
- 로그 기반 카드에 **단일 수명 규칙** 적용 (재무장·쿨다운·자동 소멸)
- 로컬 공지를 소식 카드로 노출하고, 유효 기한 공지는 상단 고정
- 배움·소식 카드를 카드뉴스 형태(핵심 요약 + 전문 링크)로
- D1~D7 잔재·성능 결함 정리

**비목표 (이번 범위 밖)**
- 코칭 **내용** 자체의 재설계 — R6·R7·R8의 판정 로직, 개인 레슨 7종의 발화 조건, 내장 팁 19개의 문안은 건드리지 않는다
- 새 코칭 룰 신설, 은퇴 룰 부활
- `anthropic.com/news` 스크래핑 (§6.2 참조)
- 역량 프로필·스코어링 알고리즘 변경

## 3. 최종 구조

```
┌ 코칭 탭 ──────────────────────────────────────┐
│ [⏳ 기한 공지 고정 슬롯]  유효 기한 + 미확인 시만, 최대 1건 │
│                                               │
│ § 내 로그에서 (N)                              │
│    룰 카드(R6·R7·R8) + 개인 실전 레슨(7종)      │
│    → 카드 문법 A, 수명 규칙 적용                │
│                                               │
│ § 배움 · 소식                                  │
│    내장 팁 / Boris / 팀 지식 / changelog /      │
│    로컬 공지(신규)                              │
│    → 카드 문법 B (카드뉴스)                     │
│                                               │
│ [숨긴 항목 N개 보기]                            │
└───────────────────────────────────────────────┘
```

**분리 기준은 "근거가 내 로그에서 나왔는가"** 하나다. 룰 카드와 개인 실전 레슨은 둘 다 내 로그에서 관측된 사건이므로 같은 섹션·같은 문법으로 합친다. 커리큘럼·외부 팁·소식은 아래로 내린다.

「내 로그에서」가 0건인 날에는 섹션 헤더 대신 기존 빈 상태 문구를 쓰고 「배움 · 소식」이 자연히 상단에 온다.

## 4. 카드 문법 2종

### 4.1 문법 A — 로그 카드

```
⚠ 최근 세션에서 도구 오류 3회 — 시행착오 줄이는 법
📊 당신 로그: 최근 세션에서 AskUserQuestion 3회 오류가 났다가 회복했어요 · 3회 · 오늘
   • 원리: 계획 없이 바로 손대면 Claude가 이 방법 저 방법 시도하며 헤매고, …
➜ 복잡한 작업은 `Shift+Tab`(플랜 모드)으로 "계획부터 세워줘"라고 한 뒤 …
[해결함] [나중에]
공식 가이드 →
```

| 슬롯 | 내용 | 출처 |
|------|------|------|
| 아이콘 + 제목 | 무슨 일이 있었나 | 룰: `coachTitle()` / 레슨: `title` |
| 📊 근거 | 내 로그 실측 + **신선도 칩** | 룰: `detail` / 레슨: `personal` |
| 원리 | 왜 그런 일이 생기는가 | 레슨: `body`의 `• 원리:` |
| 🧭 판정 | 코치 판정 사유 | 룰 전용 (`judgment.reason`) |
| ➜ 행동 | 지금 할 수 있는 한 가지 | 룰: `suggested_action` / 레슨: `body`의 `• 이렇게:` |
| 주 CTA | 행동 버튼 (`📋 복사`, `🧩 초안`, `세션 상세`) | 룰 전용 |
| 처분 | `[해결함] [나중에]` | 공통 |
| 각주 링크 | `공식 가이드 →` | `source_url` |

**본문은 현행 표시를 그대로 유지한다 — 접지 않는다.** 현재 `TipCard.svelte`의 `rest` 블록도 `it.body`를 전부 렌더하고 있어(`TipCard.svelte:91-93`) 사용자는 이미 모든 항목의 `• 원리`·`• 이렇게`를 보고 있다. 통일은 **컨테이너를 해체해 항목마다 독립 카드로 만드는 것**이지 본문을 줄이는 게 아니다.

### 4.1.1 무엇이 몇 장으로 쪼개지는가

현행 「오늘의 배움」은 **컨테이너 1장 안에 항목 4개**(큰 카드 1 + `rest` 3)가 들어 있다. 이게 항목 수만큼 독립 카드가 된다. 실측 예(2026-08-02):

| 현행 | 통일 후 |
|------|---------|
| 「오늘의 배움」 컨테이너 (항목 4개) | 로그 카드 4장 |
| R6 finding 카드 | 로그 카드 1장 (그대로) |

### 4.1.2 카드별 변경점

| 변경 | 이유 |
|------|------|
| 카드마다 `[해결함] [나중에]` 추가 | 현행은 컨테이너 전체에 `✕` 하나뿐이라 **개별 처분이 불가능**하다 |
| `~N tok` → 신선도 칩 | §1.2 D1 |
| 「내 로그 맞춤」 배지 제거 | 섹션 헤더가 그 역할을 한다. 같은 배지가 카드마다 반복될 이유가 없다 |
| 링크 라벨 통일 | 현행은 큰 카드 「공식 가이드에서 더 배우기 →」(accent 굵게), `rest` 「공식 가이드 →」로 갈린다. 각주 크기 하나로 |
| 「오늘의 배움」 라벨 제거 | 「내 로그에서」 섹션 헤더로 대체 |

**신선도 칩이 `~N tok`을 대체한다.** 절약 수치는 낼 근거가 없지만(§1.2 D1) "이 근거가 아직 유효한가"는 항상 낼 수 있다. 형식은 `{occurrences}회 · {상대 시각}` — 상대 시각은 `last_seen` 기준 `오늘/어제/N일 전`.

**소스 링크는 유지하되 위계를 낮춘다.** 현행 「공식 가이드에서 더 배우기 →」는 accent 색 굵은 글씨(`TipCard.svelte` `.more`)라 카드의 주인공처럼 보인다. 각주 크기 「왜 그런지 더 보기 →」로 내리고 주 CTA 자리는 행동 버튼이 가져간다. 링크 자체를 없애지 않는 이유는 "지어낸 조언이 아니라 공식 문서 기반"이라는 신뢰 근거이기 때문이며, 사내망에서는 `docs_reachable` 프로브가 이미 자동으로 숨긴다.

**불변식**: 문법 A 카드는 반드시 `➜ 행동` 한 줄을 갖는다. 칭찬·주간 리포트 레슨도 현행 본문에 이미 다음 행동 문장이 있다.

### 4.2 문법 B — 배움·소식 카드 (카드뉴스)

```
[소식] Claude Opus 5 출시
가장 어려운 작업에 Opus 5를 써보세요. /model로 언제든 전환됩니다.
전문 보기 →
```

| 슬롯 | 내용 |
|------|------|
| 출처 배지 | `소식` / `공지` / `배움` / `Boris` / `팀` |
| 제목 | 한국어 (원문이 영어면 §6.3 번역) |
| 핵심 | 2~3줄 요약 |
| 주 CTA | `전문 보기 →` |
| 처분 | `✕` (기존 dismiss) |

문법 A와 정반대로 **전문 링크가 주 CTA**다. 이 대비가 두 섹션의 성격 차이를 만든다.

## 5. 수명 규칙 (문법 A 공통)

| 처분 | 의미 | 재등장 조건 |
|------|------|-------------|
| **해결함** | 고쳤다 | 처분 이후 근거가 **새로** 관측되면 재무장(`→ new`) |
| **나중에** | 지금은 아니다 | 처분 후 14일 경과 + 근거가 여전하면 재무장 |
| **(자동)** | 근거가 사라짐 | 카드도 조용히 사라짐 |

- 「나중에」는 현행 findings의 `dismissed` 상태를 재사용한다(라벨만 변경). 「무시」라는 영구 어감을 버린다.
- 재무장 판정은 `last_seen > status_ts`(해결함) / `now - status_ts ≥ 14일`(나중에).
- 개인 레슨의 "근거가 새로 관측됨"은 **레슨 생성 조건이 다시 참이 된 것**으로 정의한다. `personal_lessons()`가 그 레슨을 다시 방출하면 `last_seen`이 갱신되므로 같은 식이 성립한다.
- 자동 소멸: `replace_content_items`의 프룬이 이미 `status='new'` 행만 지운다. 처분된 행은 쿨다운 기록이라 보존하되, **근거가 사라진 상태에서는 재무장하지 않는다**(재무장 조건에 "근거가 여전히 방출됨"이 포함되므로 자연히 성립).

### 5.1 스키마 변경

`findings`·`content_items` 양쪽에 `status_ts TEXT` 추가 (D5).

```sql
ALTER TABLE findings      ADD COLUMN status_ts TEXT;
ALTER TABLE content_items ADD COLUMN status_ts TEXT;
```

**이 마이그레이션은 재수집을 유발하지 않는다.** `judgment_json` 추가(`store.rs:219`)와 같은 컬럼 전용 패턴을 따르며, `events`/`sessions`/`ingest_state`/`daily_rollup`을 **절대 DELETE 하지 않는다**. 릴리스마다 콜드 스캔이 되돌아오는 기존 사고를 반복하지 않기 위한 명시 제약이다.

`set_finding_status`·`set_content_status`는 `now_ts`를 받아 `status_ts`를 함께 기록하도록 시그니처를 바꾼다. 기존 행의 `status_ts`는 `NULL` — NULL은 "처분 시각 불명"으로 보고 **재무장하지 않는다**(기존 사용자가 닫아둔 카드가 업데이트 직후 한꺼번에 되살아나는 사고 방지).

### 5.2 콘텐츠 status 어휘 확장

개인 실전 레슨이 문법 A로 넘어오면서 `[해결함] [나중에]` 두 처분을 갖는데, 현행 `valid_content_status`는 `new`/`shown`/`dismissed`만 허용한다(`commands.rs:164`). findings 쪽 어휘와 맞추기 위해 **`resolved`를 추가**한다.

| 상태 | findings | content_items | 의미 |
|------|----------|---------------|------|
| `new` | ✅ | ✅ | 노출 중 |
| `shown` | — | ✅ | (기존, 미사용에 가까움 — 유지) |
| `resolved` | ✅ | **신규** | 해결함 |
| `dismissed` | ✅ | ✅ | 나중에 |
| `pending`·`rejected` | ✅ | — | 판정 내부 상태 (노출 안 함) |

프론트의 `isHiddenFinding`(`coach-helpers.ts:56`)이 이미 `resolved`/`dismissed`만 「숨긴 항목」으로 보므로 문법 A 카드 양쪽에 그대로 적용된다.

## 6. 소식 파이프라인 (신규)

### 6.1 소스 — 로컬 `~/.claude.json`

Claude Code가 시작 공지를 로컬에 캐시해 둔다. 실측 경로:

```
~/.claude.json
  └ cachedGrowthBookFeatures.tengu_startup_announcements: [
      { "id": "fable-5-promo-2-4-team",
        "title": "Fable 5 is now a standard part of your Team plan",
        "text":  "You can use up to 50% of your weekly usage limit on Fable 5. …
                  Run /model and select Fable to use it. Learn more: https://support.claude.com/…",
        "maxImpressions": 5, "priority": 1 },
      { "id": "opus-5-launch",
        "text": "Tackle your toughest work with Opus 5. Switch anytime with /model.",
        "maxImpressions": 3, "priority": 0, "accentBar": false }
    ]
  └ announcementImpressions: { "fable-5-promo-2-4-team": 10, "opus-5-launch": 3, … }
  └ cachedGrowthBookFeaturesAt: 1785640280199   // 2026-08-02T12:11 — Claude Code가 직접 갱신
  └ lastShownEmergencyTip: "Claude Fable 5 is currently unavailable. … Learn more: https://…"
```

**왜 이 소스인가**
- **네트워크 0** — 파싱할 HTML도 추가 fetch도 TTL 고민도 없다. a-mate는 인벤토리 수집에서 이미 `~/.claude.json`을 읽는다(`hosts.rs::claude_json()`)
- **타게팅이 이미 반영됨** — 사용자 플랜·지역에 실제로 표시된 공지 그대로다. 웹을 긁으면 해당 없는 프로모까지 들어온다
- **Claude Code가 스스로 갱신** — 신선도를 a-mate가 책임지지 않아도 된다

**핵심 효용**: 시작 공지는 `maxImpressions`만큼만 스쳐 지나가고 사라진다. 실측상 `fable-5-promo-2-4-team`은 `maxImpressions: 5`인데 이미 10회 노출되어 **사용자는 더 이상 볼 수 없다**. A-Mate가 이걸 모아두는 자리가 된다.

**수집 규칙**
- `enumerate_hosts()`의 각 호스트 `claude.json`에서 읽어 `id`로 dedup, `priority` 내림차순
- `announcementImpressions`는 참고 신호로만 저장(노출 소진 여부 표시용). 노출 여부와 무관하게 카드는 만든다
- `lastShownEmergencyTip`은 별도 단일 항목으로 취급, 배지 `공지`

### 6.2 `anthropic.com/news`는 쓰지 않는다

조사 결과(2026-08-02 실측):

| 확인 | 결과 |
|------|------|
| 서버 렌더링 HTML인가 | ✅ 예 — `scraper` 크레이트로 파싱 가능 |
| 목록에 요약이 있는가 | ❌ 없음 — 날짜·카테고리·제목·링크뿐. 요약을 실으려면 **기사마다 추가 fetch** |
| 프로모션이 올라오는가 | △ 절반 — 2026-05-06 상시 2배(`/news/higher-limits-spacex`)는 있지만, 3월 단기 프로모·6월 Cowork 프로모는 news에 없고 서드파티 블로그에만 있음 |
| 노이즈 | 정책·연구·엔터프라이즈 제휴 글이 섞여 별도 게이트 필요 |

로컬 공지가 출시·프로모를 더 정확하게 덮고, 추가 fetch·게이트·TTL 부담이 없다. **YAGNI로 채택하지 않는다.** changelog 소스는 이미 있으므로 유지한다.

### 6.3 번역·요약 — "매번"이 아니라 아이템당 1회

로컬 공지의 `text`는 **이미 Anthropic이 쓴 1~2문장 요약**이다. 요약할 게 아니라 **번역**만 하면 된다. 환각 위험이 요약보다 훨씬 낮다.

| 소스 | 원문 | 처리 |
|------|------|------|
| 내장 커리큘럼 팁 | 한국어 | 그대로 |
| 팀 지식 (a-hub) | 한국어 | 그대로 (`tidy_body`) |
| **로컬 공지** | 영어 1~2문장 | **번역만** |
| changelog | 영어 bullet | 번역 + 한 줄 다듬기 |
| Boris | 영어 본문 | 요약 + 번역 |

- **아이템당 1회 + DB 캐시.** `content_items`에 `summary_ko TEXT` 추가(컬럼 전용 마이그레이션). id가 같으면 재생성하지 않는다
- 소식은 하루 1~2건이라 실질 비용이 없다
- `coachTip`의 매번 호출(D7)도 같은 캐시로 전환한다
- **엔진 없으면 원문 그대로 노출**한다. 커리큘럼 팁과 달리 소식은 코칭 문장이 아니라 정보 전달이라 영어라도 값이 남고, 현행 changelog가 이미 영어 bullet을 그대로 보여주고 있다

### 6.4 기한 추출과 고정 슬롯

**제약**: 공지 객체에 **만료 필드가 없다**. 기한은 `text`에서 추출해야 한다.

번역 LLM 호출에 필드를 하나 얹어 같이 뽑는다 — 추가 비용 0.

```
{ "title_ko": string, "summary_ko": string, "deadline": "YYYY-MM-DD" | null }
```

정밀도 우선: **확신 없으면 `null`**(기본 폐쇄, 기존 판정 원칙과 동일).

| 조건 | 동작 |
|------|------|
| 기한 있음 + 유효 + 미확인 | **최상단 고정 슬롯** (최대 1건, `priority` 내림차순) |
| `[확인]` 클릭 | 즉시 일반 소식 카드로 강등 |
| 기한 경과 | 사용자가 안 눌러도 **자동 강등** |
| 기한 없음 / 엔진 없음 | 고정 안 함 — 일반 소식 카드 |

기한 경과 자동 강등이 **LLM 오추출 안전망**이다. 잘못 뽑힌 날짜라도 그날이 지나면 스스로 내려온다.

### 6.5 새 공지 알림

새 공지 id가 처음 감지되면 기존 인프라로 **한 번만** 알린다 — 마스코트 말풍선(`robot/bubble.ts`) + 알림 로그(`notices.ts`, `home/NoticeLog.svelte`). 탭을 새로 만들지도, 홈을 복잡하게 만들지도 않는다.

### 6.6 관대한 파싱 (필수)

`tengu_startup_announcements`는 **비공식 내부 캐시(GrowthBook 피처 플래그)**다. 스키마가 예고 없이 바뀔 수 있다.

- 필드 누락·타입 불일치·경로 부재 → **그 항목만 skip**, 에러 아님
- 경로 전체가 사라지면 → 소식 카드만 침묵, 나머지 큐레이션은 계속
- 하드 에러 금지. 기존 `read_json_guarded`·changelog 소스의 관대한 파싱 원칙과 동일

## 7. 큐레이션 성능 정리

### 7.1 피드 fetch TTL (D6)

`maybe_curate_content`가 스캔마다 Boris HTML + changelog + 마켓플레이스 JSON(158KB)을 무조건 받는다. 스캔은 60초 디바운스라 작업 중 시간당 최대 60회다.

소스별 TTL을 `settings`에 마지막 fetch 시각으로 기록하고 만료 전이면 **네트워크를 건너뛴다**.

| 소스 | TTL |
|------|-----|
| Claude Code changelog | 24h |
| Boris 팁 | 24h |
| 마켓플레이스 카탈로그 | 24h |
| a-hub 팀 지식 | 6h |
| **로컬 공지** | 없음 (로컬 파일 읽기, 매 스캔 무해) |

**프룬 범위를 같이 좁혀야 한다.** 현행 `replace_content_items`는 `status='new' AND id NOT IN (이번 랭킹)`인 행을 전부 지운다(`store.rs:1061`). TTL로 스킵한 소스는 이번 랭킹에 항목을 하나도 못 싣기 때문에, 그대로 두면 **스킵할 때마다 그 소스의 카드가 통째로 사라졌다가 TTL 만료 후 다시 나타난다.**

따라서 프룬을 **이번 큐레이션에 실제로 참여한 소스로 한정한다**. `run_curation`에 참여 소스 집합을 넘기고, 프룬 조건에 `AND source_tag IN (참여 소스)`를 더한다. 소스 식별은 이미 있는 `trigger_tags`(`boris`, `changelog`, `team`, `personal` 등)를 쓰고, 태그가 없는 내장 팁은 항상 참여하므로 영향이 없다.

### 7.2 LLM 코칭 캐시 (D7)

`TipCard.svelte`의 `coachTip` 호출을 아이템당 1회로 바꾸고 §6.3의 `summary_ko` 캐시와 같은 저장소를 쓴다.

## 9. 에러 처리 & fail-safe

기존 패턴 계승.

- **엔진 없음** → 번역·기한 추출 no-op. 소식은 원문으로 노출, 고정 슬롯은 비활성. 결정론 경로(룰 카드·수명 규칙·신선도 칩)는 전부 정상 동작
- **공지 캐시 파싱 실패** → 해당 항목 skip, 소식 섹션만 침묵, 나머지 큐레이션 계속 (§6.6)
- **네트워크 실패** → 기존과 동일하게 빈 벡터로 계속. TTL 스킵과 구분해 로그
- **`status_ts` NULL** → 재무장하지 않음 (§5.1)
- **락 규율** → `claude.json` 읽기·LLM 호출은 **락 밖**, persist만 짧은 락. `maybe_curate_content`의 기존 3단 규율 그대로
- **프라이버시** → 공지는 로컬 파일 읽기, 외부 전송 없음. 번역은 설정된 Engine(온프레)에만

## 10. 테스트 전략

`cargo test` (in-memory store, 네이티브 Windows) + `npm test` (Vitest + svelte-check).

**Rust**
- **공지 파싱**: 정상 배열 → 항목 N개 / 필드 누락 항목 skip / 경로 부재 → 빈 벡터 / 타입 불일치 → skip / 호스트 간 id dedup + priority 정렬
- **기한 판정**: 유효 기한 → 고정 대상 / 경과 기한 → 강등 / `deadline: null` → 고정 안 함 / 확인 처분 → 강등
- **수명 규칙**: 해결함 후 `last_seen > status_ts` → 재무장 / 나중에 후 14일 미만 → 침묵, 14일 경과 → 재무장 / `status_ts` NULL → 재무장 안 함 / 근거 소멸 → 재무장 안 함
- **마이그레이션**: `status_ts`·`summary_ko` 추가 후 **`events`/`sessions`/`ingest_state`/`daily_rollup` 행 수가 보존되는지** 명시 검증 (재수집 회귀 방지)
- **TTL**: 만료 전 스킵 시 기존 소식 카드가 사라지지 않는지 / 만료 후 fetch 재개
- **번역 캐시**: 같은 id 재큐레이션 시 Engine 호출 0회 (MockEngine 호출 카운트)

**프론트 (Vitest)**
- 신선도 칩 포맷 (`4회 · 어제`, `1회 · 3일 전`)
- 섹션 분리 — `personal` 태그·룰 finding은 「내 로그에서」, 나머지는 「배움 · 소식」
- 고정 슬롯 렌더 조건 (유효 기한 + 미확인일 때만)
- `~0 tok`이 어디에도 렌더되지 않음 (회귀 방지)
- 카드 문법 A는 항상 `➜ 행동` 줄을 갖는다
