# 채팅 세션 회고 — 킥오프 시드 (브레인스토밍 전 메모)

> **상태**: 사용자 아이디어 접수(2026-07-06). 브레인스토밍 미진행 — 새 세션에서 superpowers:brainstorming부터.
> **선행**: PR②(채팅 탭) 머지 후. 코칭 v2.1의 UserPrompt 수집(`docs/archive/design/a-mate/brainstorming/2026-07-06-coaching-v2.1-kickoff.md`)과 시너지 큼.

## 사용자 요구 (원문 요지)

1. 진행했던 세션 중 **특정 세션을 골라 회고** 대화를 하고 싶다.
2. **세션 선택창**이 있고, 제목이 **사람이 읽었을 때 어떤 내용인지** 알 수 있어야 한다.
3. 세션을 지정하고 대화하면 **그 세션 전체 내용을 참고**할 수 있어야 한다.
4. 그 세션에서 **사람이 명령한 것 중 개선할 만한 사항**을 알려줬으면 한다.
5. 뭘 물어봐야 할지 모르는 경우가 있으니 **뱃지(칩) 형태로 다음 질문을 생성·제안**해 달라.

## 기존 자산 (재사용 가능)

- `get_session_transcript(session_id)` — 로컬 JSONL 파싱(user/assistant 텍스트·tools·model, 상한 2000엔트리). SessionModal에서 사용 중.
- `sessions` 테이블(project_id, first_ts) + `sessions_ctx` 배치 커맨드.
- PR②의 `Engine::chat` + `chat_send`/`chat_status` + ChatTab/chat-store.

## 핵심 설계 결정 (브레인스토밍 의제)

1. **전송 경계 변경 — 최대 쟁점**: 현행 스펙(미니홈피 §5)은 "트랜스크립트 원문 미전송"이 명시. 세션 회고는 세션 내용 전송이 본질 → **세션 단위 명시 옵트인 UX** 필요(전송 전 확인, 어떤 내용이 가는지 표시). 기본은 여전히 미전송.
2. **세션 제목 생성**: (a) 로컬 결정론 — 첫 user 메시지 발췌+프로젝트+날짜(전송 없음, 즉시 가능) vs (b) LLM 요약 제목(자연스러움, 비용·옵트인·캐싱 필요). v1은 (a) 권장, UserPrompt 수집 후엔 DB에서 직접.
3. **토큰 예산 / 다이제스트**: 세션 원문은 수십만 토큰 가능 → 전체 주입 불가. 목적이 "사람의 명령 개선"이므로 **user 프롬프트 전량 + assistant 축약(선두 N자·도구 호출 요약)** 다이제스트가 목적 정합·경계 최소. 상한(예: ~8k 토큰) 초과 시 절단 정책 필요.
4. **명령 개선 코칭 프롬프트**: 시스템 프롬프트에 "주인의 지시(프롬프트)에서 개선점(모호함, 반복 지시, 컨텍스트 누락, 모델/스킬 선택)을 근거와 함께" 지시. 기존 findings(해당 세션 스코프)도 동봉하면 근거 강화.
5. **질문 뱃지**: 엔진 응답을 구조화(JSON: `reply` + `suggested_questions[2..3]`)로 강제 → 칩 렌더, 클릭=전송. 파싱 실패/미설정 시 결정론 폴백(활성 findings 기반 질문). Engine 트레이트에 구조화 응답 관례 필요(JSON 모드 없는 on-prem 호환 — 프롬프트 지시+관대한 파싱).
6. **UI 흐름**: 채팅 탭 상단 "세션 골라 회고" 진입 → 세션 선택 모달(최근 N건, 제목·프로젝트·시각·토큰) → 선택 시 칩으로 표시(해제 가능) → 이후 메시지는 세션 컨텍스트 포함. 세션 미선택 시 기존 PR② 동작 그대로.

## 범위 밖 후보 (YAGNI 경계)

- 다중 세션 비교 회고, 회고 결과 저장/일기 연동, 세션 검색(제목 full-text) — 첫 릴리스 제외 검토.
