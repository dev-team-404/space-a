# Life 소셜·일기 통합 후속 로드맵

- **날짜**: 2026-07-26
- **컴포넌트**: a-mate (+ 일부 a-hub)
- **관계**: 현재 세션 스펙 [2026-07-26-bot-tab-mascot-identity-design.md](../../../archive/design/a-mate/specs/2026-07-26-bot-tab-mascot-identity-design.md)이 놓는 **프롬프트 배관(호칭·MBTI 문체)** 위에서 진행. 기반 인프라는 [2026-07-22-life-social-features-design.md](../specs/2026-07-22-life-social-features-design.md)에서 이미 구현(일촌·공개 다이어리·방명록·말풍선).
- **목적**: 방문/소셜 활동을 일기·마스코트에 반영하는 후속 아이템을 **세션 분리 · 병렬 가능 여부**와 함께 정리. 상세 설계는 각 아이템 착수 세션에서 브레인스토밍.

## 공통 의존

`owner_title`(호칭)·MBTI를 diary/chat/mascot 프롬프트로 흘리는 배관과 `mbti_voice_hint`(봇 성향 문체)는 **PR #104(2026-07-26 머지 완료)**로 이미 main에 있다. 아래 P1·P3·P4 및 2차 배치 G3의 "봇 성향 맞춤 발화" 품질은 이 배관에 의존하며, **배관이 머지됐으므로 바로 착수 가능**하다.

기반 API는 대부분 이미 존재: `lifeDiaries`(공개 일기 조회) · `lifeAddGuestbook`(방명록 작성) · `lifeSetBubble`(말풍선) · `lifeView.design.objects`(방 인테리어) · `lifeContentAccess`(공개범위 판정).

## 아이템

### P1 — 일촌 방문 → 상대 공개 일기 참조해 내 일기에 반영
- 내가 방문한 Life 목록을 로컬에 기록(방문 로그, `life_goto` 시 append).
- 일기 생성 시, 최근 방문한 일촌 중 공개(friends/public) 일기를 `lifeDiaries`로 가져와 diary 컨텍스트에 **요약** 주입(예: "어제 ○○네 놀러갔더니…").
- **터치**: `diary/mod.rs`(프롬프트·컨텍스트), `life_client.rs`(fetch), `store`(방문 로그), `commands`/`pipeline`.
- **세션**: 배관(PR #104) 머지 완료로 **착수 가능**. P2와 `diary/mod.rs` 공유라 **P1 → P2 순차**.

### P2 — 남의 방 인테리어 인식 → 일기 반영 *(이후)*
- 방문 시 `lifeView.design.objects`(가구·벽지·바닥)를 인식해 일기 소재로(예: "○○ 방에 새 책장 들어왔더라").
- **터치**: `diary/mod.rs` + life 인테리어 파싱.
- **세션**: **P1 이후**. 병렬 불가(diary 공유).

### P3 — 내가 남의 방 방문 시 자동 방명록 (봇 성향 맞춤)
- 방문(`life_goto`) 시 봇 성향(MBTI + 호칭 + 페르소나)으로 방명록 문구 1개 생성 → `lifeAddGuestbook`.
- 도배 방지(같은 방 재방문 쿨다운), 실패 무해(조용히 skip).
- **터치**: 신규 모듈(방명록 문구 프롬프트) + 신규 커맨드 + `api.ts` + 방문 훅. **diary 프롬프트 미접촉**.
- **세션**: **조건부 병렬** — 신규 파일 위주라 파일 충돌 적음. 단 "봇 성향" 문구 품질은 현재 세션 배관에 의존 → 배관 머지 후가 이상적.

### P4 — 누군가 내 방에 다녀가면 마스코트 말풍선 알림 *(+ 선택: 일기 반영)*
- 인바운드 방문 감지 → 마스코트 **말풍선**으로 "○○님 다녀갔어요"를 봇 톤으로 알림.
- **의존**: 인바운드 방문자 기록이 서버에 있어야 함. 현재 life-social 스펙엔 인바운드 방문 로그가 없음 → **a-hub 확장 필요**(방문 이벤트/최근 방문자 목록 API).
- **터치**: a-hub(방문 추적 API) **[별도 레포 · 완전 병렬]** + a-mate(폴링/이벤트 → 말풍선, `bubble.ts`).
- **선택**: 일기에도 "오늘 ○○ 놀러옴" 반영(P1 클러스터와 합류 가능).
- **세션**: a-hub 백엔드는 **완전 병렬**. a-mate 말풍선부는 서버 API 확정 후.

### P5 — 홈 화면 말풍선 텍스트 줄바꿈 개선 *(소품)*
- 증상: 사용자가 설정한 말풍선(`lifeSetBubble`)이 홈/방 화면에서 **단어 중간에서 깨지고** 어색하게 줄바꿈됨(예: "허락하/는"). 한국어 자동 줄바꿈이 어절 경계를 무시.
- 예상 수정: 말풍선 렌더러에 `word-break: keep-all`(어절 단위) + 사용자 입력 개행 존중(`white-space: pre-wrap`) + 적절한 max-width. 실제 원인·컴포넌트는 착수 시 확인.
- **터치**: 말풍선 렌더링(`bubble.ts` + 표시 컴포넌트 `RobotPortrait.svelte`/`MiniLife.svelte`/`Mascot.svelte` 중 해당). diary/프롬프트 미접촉.
- **세션**: 소규모·독립. 현재 세션과 파일 충돌 없음 → **완전 병렬(언제든 단독 처리 가능)**.

## 2차 배치 (2026-07-26 추가) — 방명록·신원·홈 표현

> 사용자 백로그 8건 캡처. **상세 설계는 각 아이템 착수 세션에서 브레인스토밍**한다. 각 항목의 "현재 상태"·"터치"는 PR #104 세션에서 조사한 사실(코드 라인 포함)이므로 콜드 스타트 시 재조사 부담을 던다.

### 클러스터 G — 방명록·소셜 신원

**G1 — 주인 신원 체계: 호칭 표시 + 풀네임 식별 *(foundational)*** (백로그 3·4)
- **현재 상태**: 신원 설정이 셋으로 나뉨 —
  - `user_name`(= 봇/마스코트 이름, 봇 탭 "마스코트 이름") → Life `name`으로 전송, 방 헤더 `App.svelte:161` "{owner_name}님의 미니홈피"에 사용.
  - `owner_title`(호칭, 기본 "주인", PR #104) → 프롬프트·대사에서 주인 지칭.
  - `owner_os_user`(OS 계정, PR #104 §F) → Life register/rename payload의 숨은 식별자(현재 서버 미소비 forward 필드).
- **요구**: **주인 풀네임(실명)** 을 새 설정으로 저장. 표시는 호칭(`owner_title`)으로 하되, **사람 구분·신원 확인이 필요한 곳**엔 풀네임을 쓴다. **Life 방 이동 payload에도 호칭이 아니라 풀네임**을 실어야 함.
- **방명록 작성자 이름 포맷**: 봇이 남길 때 = `{owner_title}님의 {봇이름}`(예: "대장님의 둘쇠"); 사람이 남길 때 = 호칭 기반이되 호칭만으론 여러 "주인"이 구분 안 되므로 풀네임으로 disambiguate.
- **터치**: `commands.rs`(새 설정 + 프로필 API), `MeGroup.svelte`(입력 필드), `life_client.rs`+`commands.rs`(방 이동/등록 payload에 풀네임), a-hub life `add_guestbook`의 `author_name` 조립(스키마 `guestbook(entry_id, life_id, author_agent_id, author_name, body, created_at)`).
- **의존·세션**: **G2·G3·G4의 선행 기반**. 신규 설정·payload 위주라 diary 미접촉. PR #104의 owner_title/owner_os_user 배관 위 확장.
- **열린 질문**: 풀네임 노출 범위(방명록 표시=호칭 / payload=풀네임처럼 채널별 분리?)와 방 헤더 `name`(현재 봇 이름)·풀네임의 관계 정리.

**G2 — 방명록 답글 (1단계, 중첩 불가)** (백로그 1)
- **현재 상태**: a-hub life 방명록은 **평면 목록만** — `GET/POST/DELETE /life/{id}/guestbook`(`api.py:197-207`), 스키마에 **parent/thread 필드 없음**.
- **요구**: 방명록 항목에 **답글 1단계** 허용, **답글의 답글(중첩) 불가**.
- **터치**: **a-hub** — guestbook 테이블에 `parent_id` 추가 + **1-depth 강제**(parent가 이미 답글이면 거부), reply 생성/조회 경로, `store.py` 마이그레이션. **a-mate** — `GuestbookTab.svelte` 답글 UI + `api.ts`.
- **의존·세션**: a-hub 백엔드 **별도 레포·병렬**. a-mate UI는 서버 스키마 확정 후. G1(작성자 표기)와 정합.

**G3 — 방명록 봇 자동 답글** (백로그 2)
- **요구**: 누군가 **내 방 방명록에 글을 남기면** 내 봇이 성향(MBTI+호칭+페르소나)으로 **답글 자동 생성**.
- **터치**: 인바운드 방명록 감지(폴링/이벤트 — 아래 P4의 인바운드 방문 추적처럼 a-hub 확장 필요할 수 있음), 답글 문구 프롬프트(신규, PR #104 `mbti_voice_hint` 재사용), 답글 생성 호출.
- **의존·세션**: **G2(답글 인프라) + G1(신원) 선행**. 문구 품질은 PR #104 배관 의존(이미 머지). 도배 방지(글당 1회), 실패 무해.
- **열린 질문**: 인바운드 방명록 알림을 서버가 주는가? (P4처럼 a-hub 최근 인바운드 이벤트 API 필요 가능.)

**G4 — 이름 클릭 → 그 사람 홈으로 이동 팝업 버튼** (백로그 5)
- **요구**: 방명록/방 등에서 **사람 이름 클릭 시** 그 사람 홈(Life 방)으로 이동하는 **팝업 버튼**.
- **터치**: 이름 렌더 지점(`GuestbookTab.svelte`, 방 점유자 목록 등) → 팝업 → `lifeGoto(life_id)`. 작성자(author_agent_id)→life_id 매핑 경로 확인 필요.
- **의존·세션**: 프론트 위주, **독립성 높음**. `life_goto`는 기존. G1 이름 표기와 정합.

### 클러스터 H — 홈·마스코트 표현

**H1 — 홈 좌측 "오늘의 일기" 박스 vs mood 중복 정리 → 하나만** (백로그 6)
- **조사 결과(현재 상태)**:
  - `App.svelte:174-178` **"📔 오늘의 일기" 박스** = `dailyLine`(=`getDailyLine`, LLM 오늘의 **한마디**)를 렌더, 클릭 시 일기 탭. **라벨만 "일기", 내용은 한마디** — 실제 일기 본문 아님.
  - `App.svelte:182` **`.mood`** = `summary.est_tokens_saved_total > 0 ? '절약할 게 보여요…' : '평화로워요'` — **하드코딩 2-state 파생 문자열**(사용자가 "오늘의 한마디"로 인식).
  - 진짜 일기 본문은 diary 탭(`getDiary`)에 별도.
- **요구**: **하나만 남긴다**. 옵션 — (a) "📔 오늘의 일기" 라벨을 "오늘의 한마디"로 바로잡고 `mood` 제거, (b) 박스가 실제 일기 발췌를 보이게 하고 한마디는 마스코트 말풍선에만, 등. 착수 세션에서 결정.
- **터치**: `App.svelte`(좌측 aside), `daily_line`/`get_diary` 배선.

**H2 — 매일 바뀌는 마스코트 홈 컷 *(재미요소·R&D)*** (백로그 7)
- **요구**: 새 일기 쓰는 타이밍에 **홈 좌측 상단 사진(RobotPortrait)을 매일 새 컷**으로.
  - 다양한 샷(풀샷/바스트/얼굴 클로즈업)·포즈, **MBTI 성향 기반**.
  - 마스코트 없는 그림도 비슷한 화풍으로(자기 사진만 올리진 않으니 **주인과의 대화·작업 내용 반영**).
  - **그림 안 텍스트 금지**(생성 모델 맞춤법 오류 잦음). **같은 프레임 하단에 그림 설명 한마디**(오늘의 한마디와 별개).
  - 웹서치로 **싸이월드 레전드 밈** 결에서 영감(가능하면).
- **터치**: `sprite.rs`(`character_description`가 시드+MBTI로 로봇 묘사 — PR #104에서 변주 시드 도입; 그 위에 "샷/포즈/장면" 축 확장), 이미지 엔드포인트(연결 테스트 기존), 일기 파이프라인(생성 타이밍 훅), 신규 저장/캐시(일자별 컷), `RobotPortrait.svelte`(일자 컷 + 하단 캡션).
- **의존·세션**: **가장 크고 독립적인 R&D — 별도 세션 권장**. 이미지 생성/캐시 위주라 diary 프롬프트와 약결합. 착수 시 브레인스토밍(샷 축 정의·장면 프롬프트·캐싱/과금·실패 폴백=기존 스프라이트).
- **열린 질문**: 컷 생성 비용·빈도(매일 1회?), 저장 위치, 마스코트-없는 그림 소재를 어디서(대화·작업 요약) 얼마나 안전하게(프라이버시) 끌어올지.

**H3 — CHATTER 자유 생성** (백로그 8)
- **현재 상태**: 잡담은 **두 소스** — (1) `compute_chatter_pool`(LLM, `mascot.rs`)이 오늘 사실 기반 N개 배치 생성(스캔당 1회 캐시), (2) `bubble.ts` **정적 `CHATTER` 15개 고정 배열**(폴백/상시). `pickChatter`가 둘을 합쳐 균등 랜덤.
- **요구**: 정적 고정 목록을 **더 자유롭게 생성**.
- **터치**: `bubble.ts`(정적 배열 축소/치환), `mascot.rs`(`compute_chatter_pool` 다양성·빈도 확대), 폴백 전략.
- **의존·세션**: 소규모·독립. PR #104가 `bubble.ts`/`compute_chatter_pool`을 이미 손봄(호칭 배선) — 그 위 확장.
- **열린 질문**: 완전 LLM화 시 오프라인/엔진 미설정 폴백은? (현재는 정적 배열이 그 역할.)
