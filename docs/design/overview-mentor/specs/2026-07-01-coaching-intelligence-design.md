# Agent Mentor — 코칭 지능(Coaching Intelligence) 설계

> **상태**: 브레인스토밍 합의 완료 (2026-07-01)
> **범위**: kickoff 문서(`docs/brainstorming/2026-07-01-kickoff.md`)의 §3.2(코칭 로직) + 다이어리 신규 아이디어를 심화한 하위 설계.
> **선행/후행**: 이 문서는 "정규화된 세션 이벤트가 존재한다"를 전제한다. 파서/어댑터 추상화, 3-윈도우 UI 상세, 트레이/업데이터 뼈대는 각자 별도 설계에서 다룬다.

---

## 0. 제품 정체성 (이 세션에서 재정의됨)

**Agent Mentor = 당신의 AI 코딩 여정을 (에이전트의 시점에서) 저널링하며, 그 안에서 코칭하는 동반자.**

경쟁 구도에서 의도적으로 비켜선다:

| 축 | ccusage | claude-hud | **Agent Mentor** |
|---|---|---|---|
| 성격 | 집계 | per-session 라이브 statusline | **해석·코칭** |
| 시간 | 리포트 | 지금 이 세션 | **여러 세션·며칠·몇 주 종단** |
| 형태 | CLI | 터미널 계기판 | **곁에서 회고하는 멘토(다이어리)** |

→ 우리는 **실시간 지표 대시보드를 만들지 않는다**(claude-hud가 그 니치를 이미 소유). 무게중심은 **사후 서사 + 코칭 + 종단 성장**.

## 1. 확정 결정 로그

브레인스토밍(2026-07-01)에서 합의된 사항. 근거가 약하면 재검토 가능하되, 아래 설계는 이 결정들 위에 서 있다.

1. **시간 모델 = 하이브리드 + 온디맨드**
   - 주력: 사후 다이제스트(세션 종료/주기적)
   - 실시간: 극소수 고신호 넛지만(세션 시작 always-on 토큰, 명백한 모델 오남용), **전역 쿨다운**
   - 온디맨드: 사용자가 "지금 분석/코칭해줘" 하면 즉시 개입
2. **개입 수위 = 처방(prescription)까지**
   - 진단을 넘어 구체적 처방 + 준비된 산출물(SKILL.md 초안, 제거할 MCP 리스트, 모델 권장)
   - **적용(파일 쓰기/설정 변경)은 항상 사용자 승인 버튼**을 거친다. "준비는 앱이, 실행은 사람이."
3. **LLM 3-티어 + 자기 토큰 계량**
   - Tier 0(무료·상시): 결정론적 Rust 규칙. 코칭 가치의 대부분 + 정량 차별점 전부.
   - Tier 1(기본 on): 다이어리의 **시맨틱 코치**. 작업이 저렴함(작은 브리프 → 짧은 서사). 엔진은 정책(§1.6)을 따름 — 기본 사내 on-prem, 옵션으로 Claude 우선+폴백.
   - Tier 2(옵트인·온디맨드): 깊은 질적 리뷰. 엔진 정책 따름(심층 품질 위해 Claude 옵션 권장), 캐싱.
   - **코치는 자기 토큰 소비를 계량해 UI/다이어리에 표시**한다("이 분석 ~2.4k 토큰").
4. **정밀도의 선 (핵심 원칙)**
   - **처방(결과 있는 행동) = 결정론적 규칙.** 환각 불가.
   - **인정·서사(칭찬·회고) = 시맨틱 LLM.**
   - 시맨틱 층 재량 = **"사실 근거 자유 서술"**: LLM은 사실 브리프 위에서 자유롭게 판단·서술하되, **구체적 수치/주장은 브리프의 사실에 근거**해야 하고(수치 지어내기 금지), 자유 소감은 서사에만 허용하며 **행동 카드로 자동 승격하지 않는다.** 진정 새로운 질적 통찰은 Tier 2로.
5. **다이어리 = flagship**
   - 에이전트(마스코트)의 1인칭 일기. 다마고치풍이되 분석이 녹아든다.
   - 톤: **B(균형) 기본**, 설정으로 A(감성)/B/C(분석) 강도 선택.
   - 호칭: **"주인" 기본값**, 사용자가 직접 지정 가능.
   - 출력: **사용자 지정 디렉터리**(예: Obsidian vault), 날짜별 `.md`.
   - **LLM 필수**(단순 템플릿 지양). **품질 > 정시성**: 엔진 미인증 시 큐에 보류 후 엔진이 살아나면 생성.
6. **엔진 정책 = 사내 on-prem LLM 기본, Claude는 옵션**
   - 기본: **사내 on-prem LLM** — 무인 자동 실행에 안정적, 사내망이라 반출 무관, 저비용.
   - 옵션: **Claude 우선 + 사내 LLM 폴백** — Claude 품질을 원하고 Bedrock 재인증을 감수할 때.
   - 어댑터로 추상화(on-prem은 OpenAI 호환 엔드포인트 가정). **기본이 on-prem이라 기본 상태에서 데이터가 사내망을 벗어나지 않음** → egress 프라이버시가 엔진 선택으로 자동 해결(§6.3). 사내 Claude도 AWS Bedrock(사내 승인 경로)이라 어느 쪽이든 대부분 반출 무관.

## 2. 아키텍처 골격

```
[감시] notify: Windows + WSL 전 distro
   .claude/projects/**/*.jsonl · settings.json · skills/ · plugins/ · mcp 설정
        │ (변경분만, read-only tail — 완결된 개행 라인만 파싱)
        ▼
[수집] 증분 파서 → 정규화 이벤트
        │ (host, project, sessionId) 키잉, isSidechain 인지
        ▼
[저장] SQLite(rusqlite): 원시 이벤트 + 세션/일/주 롤업 집계 + Finding + 다이어리 색인
        │
        ▼
[규칙 엔진] Tier 0 결정론적 규칙을 집계 위에서 실행 → Finding emit
        │
        ▼
[Finding 저장소 + SQLite] ─── 단일 통화(currency) ───►
        ├─► 다이어리 생성기 (Tier 1 시맨틱 서사)
        ├─► 처방 카드 (승인→적용)
        ├─► 실시간 넛지 (희소, 전역 쿨다운)
        └─► 채팅 (온디맨드 자연어 질의 — §7.4)
```

**핵심 원리**: 코칭을 **한 번 계산(Finding)** 해서 **여러 갈래로 렌더링**한다. 다이어리는 Finding을 서술하고, 카드는 실행 가능한 Finding이며, 넛지는 고심각도 Finding의 라이브 표출, 채팅은 스토어 위의 자연어 질의. 모든 UI가 같은 뇌를 공유한다.

## 3. 데이터 모델

### 3.1 정규화 이벤트 (전제 — 파서 설계에서 상세)

실측 검증된 Claude Code JSONL 스키마에서 최소한 아래를 추출한다:
- `assistant` 라인: `message.model`, `message.usage.{input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, cache_creation.ephemeral_{5m,1h}_input_tokens, server_tool_use.{web_search,web_fetch}_requests}`, `iterations[]`
- `tool_use` 블록: `name`, `input`(예: `file_path`)
- 라인 공통: `sessionId`, `isSidechain`, `parentUuid`, cwd/project 귀속
- 파일시스템: `skills/`·`plugins/` 디렉터리 스냅샷(신규 감지용), `settings.json`/mcp 설정(always-on 비용 계산용)

### 3.2 Finding (설계의 심장)

하나의 **Finding** = 코칭할 만한 관찰 1건. 모든 코칭이 이 단위로 환원된다.

| 필드 | 내용 |
|---|---|
| `rule_id`, `severity` | 어떤 규칙이 냈나 / `info` · `suggest` · `warn` |
| `scope` | (host, project, session \| day \| week) |
| `evidence` | 원시 근거(예: "session X에서 `report.xlsx` ×7 Read", 토큰 수) |
| **`est_tokens_saved`** | **정량화된 임팩트 — 코칭의 공용 통화.** 모든 걸 "토큰"으로 측정 |
| `prescription?` | `{kind: skill_draft \| remove_mcp \| switch_model \| restructure, payload, apply_action}` |
| `status` | `new \| shown \| snoozed \| dismissed \| following` (나깅 방지 상태머신) |
| `first_seen`, `occurrences` | 종단 추적 (다이어리 주간 서사의 재료) |

두 결정이 여기 박혀 있다:
1. **모든 코칭을 토큰으로 계량**(`est_tokens_saved`) — "캐시 히트율 낮음"이 아니라 "고치면 ~8k/일 절약". 코치가 제 가치를 숫자로 증명하고, 자기 소비(Tier 1/2)와 같은 단위로 정직하게 상계.
2. **`following` 상태** — 사용자가 이미 조언을 따르기 시작하면 규칙이 자동 감지해 조용해진다(나깅 방지의 뿌리). 이 전이는 동시에 다이어리의 **칭찬거리**가 된다.

`est_tokens_saved` 산정식은 규칙별로 다르며 v0 이후 사용자 히스토리로 보정한다(§9 참조).

## 4. 다중 세션 모델

- 세계를 **(host, project, sessionId)** 로 키잉된 세션 이벤트 스트림으로 본다. host ∈ {`Windows`, `wsl:<distro>`}.
- **감시**: `notify`가 Win + WSL 전 distro의 `.claude/projects/**/*.jsonl`을 동시 tail. 각 파일이 독립 스트림이라 동시 append 문제없음. 우리는 read-only tailer 이므로 락 경합 없음 — 쓰이는 중인 마지막 라인은 미완결일 수 있으니 **개행으로 끝난 완결 라인만 파싱**하고 tail을 버퍼링.
- **나깅 제어**: 3개 세션 라이브면 턴별 넛지는 3배 소음 → 실시간 넛지는 **전역 쿨다운**(세션별 아님)으로 묶고, 동시성 높으면 억제하며 마스코트는 "N개 세션 진행 중" 차분한 집계 상태만 표시.
- **다이어리 귀속**: 다이제스트가 하루치를 프로젝트별로 집계 — "오늘 3개 세션 (cowork 2, agent-mentor 1)". **동시성이 문제가 아니라 서사의 재료.**
- **서브에이전트**: `isSidechain` 플래그로 메인 턴 vs 서브에이전트 턴 구분. 다이어리엔 서브에이전트 토큰을 **부모 세션으로 롤업**(사용자는 "작업" 단위 인지), 심층 분석 땐 서브에이전트 단위도 열람.
- **"이 세션 코칭해줘" 지목**: 훅/슬래시커맨드로 세션 내부에서 부르면 sessionId 전달 → 없으면 최근성(가장 최근 append된 JSONL) → 그래도 애매하면 채팅창에서 활성 세션 목록(최근순) 중 선택.

## 5. Tier 0 규칙 카탈로그 (v0 기본 임계값, 전부 튜닝 가능)

⭐ = 3대 차별점 직결.

| # | 규칙 | 탐지 신호 | v0 임계값 | 처방 |
|---|---|---|---|---|
| **R1** ⭐ | 안 쓰는 always-on MCP | mcp 설정 상주 토큰 vs 도구 호출 0회 | 최근 10세션 호출 0 **and** 상주 >2k토큰 | `remove_mcp` |
| R2 | 미사용 plugin/skill 상주 비용 | 설치됨 but 미호출 | R1과 동일 | 비활성 제안 |
| R3 | 낮은 캐시 히트율 | `cache_read`/(read+creation+input) | 히트율 <50% **and** 20턴↑ | 대화 재시작·구조 |
| R4 | 1h 캐시 생성 후 미재사용 | `ephemeral_1h` 생성 vs 재사용 | 생성 큼 + 후속 read 낮음 | 캐시 전략 |
| **R5** ⭐ | 같은 파일 반복 Read | `tool_use.input.file_path` 카운트 | 동일 경로 ≥4회/세션 | 재읽기 줄이기 |
| **R6** ⭐ | 반복 워크플로 → 스킬 | 유사 tool-시퀀스 반복 | 유사 시퀀스 ≥3회(세션 교차) | `skill_draft` (Tier1 군집 확인) |
| R7 | 단순 작업에 Opus | `model`=Opus + 사소한 단일 도구 | 출력<300토큰 & trivial 도구 | `switch_model`→Haiku |
| R8 | MCP 결과 매번 폐기 | tool_result 후속 미참조 | 폐기율 높음 | 연결 재검토 |
| R9 | 웹 도구 남용 | `server_tool_use` 과다 | 세션당 과다 호출 | 캐싱/로컬 |

### 5.1 칭찬거리 "사실"(Tier 0가 공급, LLM이 판단·서술)

패턴으로 칭찬을 손코딩하지 않는다. 규칙은 **믿을 수 있는 사실만 공급**하고, 시맨틱 층이 맥락으로 인정한다.

- **새 도구를 배움** ⭐ — `skills/`·`plugins/` 파일시스템 diff로 신규 감지 + 그날 사용 횟수 → "주인이 새 무기를 구해왔다!"
- **효율 개선** — 유사 작업 기준 어제/개인 베이스라인 대비 토큰 델타(LLM이 "비슷한 일인지" 맥락 판단)
- **내 조언을 채택** ⭐ — Finding `following` 전이 감지 → "어제 재읽기 줄이자 했는데 오늘 진짜 줄었다. 고마워요." (자기참조 칭찬 루프)
- **좋은 컨텍스트 위생** — 긴 세션인데 캐시율 높음
- **기능 첫 성공 사용** — 서브에이전트/worktree 첫 활용 등

> **폐기됨**: "에러 반복 후 스킬로 탈출"(P1). 스킬은 보통 작업 지시 시 자동 발동되므로 거의 트리거되지 않음.

## 6. LLM 티어링 · 프라이버시 · 자기 계량

### 6.1 정밀도의 선 (재확인)

| 종류 | 담당 | 이유 |
|---|---|---|
| 처방(결과 있는 행동) | **결정론적 규칙** | 승인→적용 카드 → 환각 불가 |
| 인정·서사(칭찬·회고·"오늘 어땠나") | **시맨틱 LLM** | 뉘앙스 필요·저위험 |

### 6.2 티어

- **Tier 0** (무료·상시·Rust): 정량 사실 + 델타 + 파일시스템 diff + 처방. 결정론적.
- **Tier 1** (기본 on·저렴): 다이어리의 시맨틱 코치. 사실 브리프를 받아 칭찬·회고·톤을 판단하고 인격으로 서술. 엔진 = 기본 사내 on-prem, 옵션 Claude 우선+폴백(§1.6).
- **Tier 2** (옵트인·온디맨드): "이 세션/이번 주 깊게 봐줘" → 규칙이 못 잡는 질적 코칭(프롬프트 두서없음, 작업 분해 아쉬움, 전략 대안). 엔진 정책 따름(심층 품질 위해 Claude 옵션 권장), 캐싱.

### 6.3 프라이버시 경계 (수정됨 — 로컬 풀 컨텍스트 + egress는 엔진 선택으로)

- **로컬은 전부 보관·활용.** 본인 PC의 본인 데이터이므로 백엔드는 풀 컨텍스트(코드/프롬프트 포함)를 자유롭게 참조 — 분석 품질 우선. NormalizedEvent는 메타 + 원본 소스 포인터라 필요 시 원본을 로컬에서 당겨 씀.
- **egress = 엔진 선택으로 해결.** 기본 엔진이 사내 on-prem(사내망)이라 기본 상태에서 데이터가 망을 벗어나지 않음. 사내 Claude도 AWS Bedrock(사내 승인 경로)이라 대부분 무관.
- 별도 "리댁트 모드"는 두지 않음(YAGNI) — 엔진 선택이 곧 프라이버시 자세. 무엇이 나가는지는 여전히 **열람 가능**.

### 6.4 자기 토큰 계량

- Tier 1/2가 소비한 토큰을 기록해 다이어리 푸터·UI에 표시. 모순을 기능(자기 비용 투명성)으로 전환.

### 7.2 생성 파이프라인 (LLM 필수)

```
트리거(일 종료 / 온디맨드 / 주·월)
  → 그날 Findings 수집 (문제 + 칭찬거리 사실 둘 다), host·project별 스코프
  → 브리프(JSON) 조립: findings·수치 중심(토큰 효율). 필요 시 원본 발췌 포함 가능(로컬/사내 엔진일수록 자유롭게)
  → LLM(기본 사내 on-prem, 옵션 Claude 우선+폴백)이 브리프를 에이전트-시점 일기로 서술
        시스템 프롬프트에 인격·톤프리셋·호칭 주입
        재량 = "사실 근거 자유 서술"(§1.4)
  → 지정 디렉터리(Obsidian 등)에 날짜별 .md 기록 + SQLite 색인
  → 토큰 자기계량 표기
  → 엔진 미인증 시 큐 보류(템플릿 금지), 엔진 살아나면 생성
```

### 7.3 종단 서사

주간/월간: 같은 파이프라인을 집계된 Findings/추세 위에서 실행 → 성장 서사("이번 주 캐시 히트율 +12%, Opus 남용 3회→0회"). per-session 도구가 원천적으로 못 하는 층.

### 7.4 채팅 = 자연어 히스토리 질의 (온디맨드)

마스코트/채팅창은 SQLite 스토어 + Finding + 다이어리 아카이브 위의 **자연어 질의 프론트엔드**다. "지난주 한 일 요약해줘" 같은 질문이 가능하다. **정밀도의 선(§1.4)을 질의에도 적용**해 토큰을 아끼는 것이 핵심.

**라우팅**
1. **의도·스코프 파싱**: "지난주" → 날짜 범위, "cowork" → 프로젝트. 흔한 시간표현은 규칙 파싱, 애매하면 저렴한 LLM 분류.
2. **티어 라우팅**:
   - **정량/사실 질의**("지난주 토큰 얼마?", "제일 많이 쓴 스킬?") → SQL 조회 → 포맷 답변. **0 LLM 토큰.**
   - **서사/요약 질의**("지난주 요약해줘", "이번 달 어땠어?") → 증류 브리프 → LLM 서술(마스코트 인격). 이미 존재하는 **일일 다이어리가 그 주의 압축본**이라 "요약의 요약"으로 매우 저렴 (= §7.3 주간 서사의 온디맨드 트리거).
   - **코칭 질의**("어떻게 더 잘 쓸까?") → Tier 2 심층 리뷰.
3. **토큰 정직성**: 원문 트랜스크립트를 절대 통째로 넣지 않는다. 결정론적으로 검색·증류한 컴팩트 브리프만 LLM에 전달(§6.3 프라이버시 경계 동일 적용).
4. **경계**: 앱은 "당신의 코딩 여정"에 대한 멘토이지 범용 챗봇이 아니다. 범위 밖 요청("코드 짜줘")은 인격으로 정중히 넘김 — "그건 Claude Code한테 시키시죠, 주인."
