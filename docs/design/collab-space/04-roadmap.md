## 2. 구현 순서 (의존성 기준)

```
① 계약 정의        C1(MCP Tool) + C2(REST) 스키마 문서화
                   ↑ 팀 전체 공유. ★여기서부터 세 사람이 병렬 작업 가능★
                   │
② core + 인메모리   도메인 로직 + fake 어댑터로 E2E 통과
                   │
③ MCP 서버 붙이기   Claude Desktop/Cursor에서 실제 호출 성공
                   ↑ ★데모 최소 요건 — 여기까지만 되어도 발표는 성립★
                   │
④ 실 DB 교체       Vector / Graph 어댑터 구현
                   │
⑤ 클러스터 연결     llm_fake → llm_litellm 교체
                   │
⑥ 심야 압축 배치    유휴 GPU 활용 (킬러 피쳐)
                   │
⑦ 시각화 API 확정   Pillar 3에 실데이터 제공
```

### 컷라인의 의미

**③번까지만 되어도 데모는 성립한다.** ④~⑥은 완성도를 올리는 단계이므로,
시간이 부족하면 여기서 잘라도 **발표에 구멍이 나지 않는다.**

역으로 ①번이 늦어지면 **팀 전체가 늦어진다.** 계약이 없으면 아무도 병렬로 일할 수 없다.

## 3. 데모 시나리오

심사위원에게 보여줄 **"지식이 순환하는 순간"**.

| # | 단계 | 포인트 |
|---|---|---|
| 1 | **상황 발생** — 개발 에이전트가 코드 작성 중 처음 보는 라이브러리 의존성 에러에 직면 | 누구나 겪는 상황 |
| 2 | **로컬 작동** — 에이전트가 Space A(MCP)에 질의. 사내 로컬 LLM이 하이브리드 검색 수행 | **외부 API 비용 0** |
| 3 | **그래프 추적** — Vector로 에러 메시지를 찾고, Graph로 *"지난주 옆 팀 에이전트가 이 에러를 풀려고 특정 MCP 환경변수를 수정했다"*는 관계를 짚어냄 | **Vector 단독으로는 불가능한 추론** |
| 4 | **최적화된 컨텍스트 전달** — 방대한 로그 대신 딱 필요한 "해결 조건 JSON"만 리턴 | **토큰 사용량 대폭 절감** |
| 5 | **최종 해결** — 에이전트가 최소 토큰으로 상용 모델을 호출해 코드 수정 성공 | |
| 6 | **지식 환류** — 해결 과정을 다시 Space A에 기록 → **다음 사람의 에이전트가 재사용** | **루프가 닫힌다** |

> 3~4번이 이 프로젝트의 기술적 클라이맥스다. 데모에서 **"이 JSON이 원본 로그였다면 N배였다"**를
> 나란히 보여주면 토큰 절감이 눈에 보인다.

나중에 붙이려면 **이미 늦는 것들.**

- [x] **Public / Team / Private 권한 모델** — 계약에 반영 ([05 §1.1](05-contracts.md#11-권한-모델-visibility))
- [x] **신원(Identity) 전달 방식** — Bearer 토큰, `team`은 **토큰에서 유도** ([05 §1.2](05-contracts.md#12-신원-identity--권한-모델의-전제))
- [x] **호출 뎁스 추적** — `trace_id` / `depth` 헤더를 계약에 실음 ([05 §1.3](05-contracts.md#13-호출-뎁스-추적-circuit-breaker의-전제))
- [ ] **사내 SSO 연동 방식 확정** (SAML/OIDC) — 인프라 담당 협의 필요.
      MVP는 정적 토큰 → team 매핑으로 시작하되, **헤더 위치·클레임 구조는 이미 고정**했으므로 C1은 안 깨진다
- [ ] **Ollama 노드 네트워크 보호** — 방화벽으로 게이트웨이 IP만 허용 ([03 §5.2](03-architecture.md#52-클러스터-구성--litellm--ollama)).
      공용 인프라 담당 영역이나 **계약상 전제**
- [ ] `import-linter`로 레이어 규칙 CI 강제 ([03 §4](03-architecture.md#4-내부-구조--포트와-어댑터))
- [ ] 환각 전염 차단 — 기록 전 검증 / 신뢰도 스코어
- [ ] Circuit Breaker 구현 — 뎁스 상한(기본 5) + `trace_id` 단위 일일 토큰 상한
