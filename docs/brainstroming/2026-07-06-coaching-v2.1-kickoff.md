## 문제 (사용자 원문 요지, 2026-07-06)

코칭 v2 완성 직후 사용자가 같은 잣대("실제 조치 가능한 것만 코칭")로 두 룰을 추가 지적:

1. **R5 (반복 Read)**: "같은 파일을 반복적으로 읽고 있다는 코칭도 내가 직접 같은 파일을 계속 읽으라고 한 게 아닌데
   코칭의 의미가 있나?" — 반복 읽기의 주체는 에이전트이고, 상당 부분은 컨텍스트 압축 후 재읽기라는 하네스 동작.
   현행 처방("한 번만 읽고 기억해 두면")은 조치 주체가 없음. **v2 원칙 위반(지나간 세션 행동 교정) — v2 범위에서 누락됨.**
2. **R11 (권한 재시도 마찰)**: "이벤트는 많이 발생하는데 별로 의미가 없어 보임." — ToolResult 미수집 상태에서
   연속 호출의 원인(권한 거부 vs 편집 실패 vs 정상 반복 작업)을 판별할 수 없어 가설 카드가 다발.
   → **v2에서 발화 보류 처리됨**(ops.rs 등록 해제, 코드·테스트 보존 — 스펙 §4.4 보류 블록 참조).

## v2.1 후보 카탈로그 (브레인스토밍에서 우선순위·범위 결정)

### 1. ToolResult/UserPrompt 수집 (선행 과제 — 이 사이클의 열쇠)

트랜스크립트 JSONL의 tool_result(성공/거부/에러 메시지)와 user prompt 이벤트를 수집한다.
이것이 풀리면: R11 결정론 승격(§2), 유예 중인 R3(캐시 히트율)/R4(1h 캐시)/R8(에러 정밀 탐지),
그리고 R5 재설계의 "압축 후 재읽기 vs 단순 반복" 구분까지 가능해진다.
- 논점: 수집 범위(결과 전문 저장은 프라이버시·용량 부담 → 결과 크기·에러/거부 플래그·메시지 요지만?),
  events 스키마 확장 vs 별도 테이블, 재수집(마이그레이션) 전략.

### 2. R11 승격 — 권한 거부의 결정론 판정

ToolResult 수집 후: tool_result의 거부 메시지 매칭으로 "권한 거부"를 사실로 판별 → 가설 문구 제거.
- 발화 조건을 "거부로 확인된 마찰"로 좁힘 → 오탐 제거.
- **의도적 거부 케이스**: 사용자가 일부러 거부한 도구에 "허용목록에 추가하세요"는 역방향 조언.
  같은 (도구, 대상)이 거부 후 결국 승인된 패턴만 코칭? 문구에 "직접 거부하신 도구라면 무시하세요" 병기? 논점.
- 룰 코드·테스트는 v2에 보존되어 있음(`r11_permission_friction.rs`) — 판정 입력만 교체.

### 3. R5 재설계 — 세션 카드 폐기, 실제 레버로 전환

현행 R5(세션 내 동일 파일 ≥4회 → 세션 카드)는 폐기하고, 레버가 있는 신호로 분해:

1. **크로스세션 반복 파일 → CLAUDE.md 처방** (프로젝트 집계): 같은 프로젝트의 여러 세션에서
   반복해서 읽히는 파일은 "매 세션 필요한 정보인데 상주 컨텍스트에 없다"는 신호.
   → "이 파일의 요약/포인터를 **CLAUDE.md에 추가**하세요" — 정확히 "설정 파일 한 곳" 레버.
   집계 finding 인프라(scope_kind="project", evidence session_ids, 펼치기 UI)는 v2 것을 그대로 재사용.
2. **세션 내 반복(압축 후 재읽기 포함)**: 카탈로그의 "컨텍스트 눈덩이"(v2 킥오프 5번, 유예 중)에 흡수 —
   "긴 세션은 압축 후 재읽기 낭비가 생겨요, 독립 작업은 세션 분리/서브에이전트" (다음 세션의 선택 레버).
   단독 카드로는 폐기, 다이어리 서사의 사실 인용으로만 유지 검토.
- 기존 R5 세션 finding 이행: v2의 R7 전례(스캔 시 일괄 삭제)를 따를지 논점.
- 임계값 논점: 크로스세션 판정(몇 세션에서 몇 회?), 대상 파일 필터(소스 vs 문서? node_modules 제외?).
