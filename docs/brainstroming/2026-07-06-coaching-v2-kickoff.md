## 문제 (사용자 원문 요지, 2026-07-06)

R7("가벼운 작업에 Opus는 과해요" + `/model haiku`)이 실전에서 헛돎:

1. **세션 단위 dedup** → 자동화 도구(cowork probe)가 만든 동형 초단기 세션마다 카드 1장, 같은 지적 81회 관측·반복 노출.
2. **처방이 사용자의 실제 레버가 아님** — 모델은 세션 시작 때 정해지고, 컨텍스트 때문에 세션 중 전환은 거의 불가능하며, 문제 세션들은 사용자가 직접 명령한 게 아니라 **도구가 생성**한 것.
3. 사용자 요구: "한 세션을 통째로 종합한 후, 그 안에서 **내가 실제 조치할 수 있는 것**에 대해 가이드해야 의미가 있다."

**v2 설계 원칙(합의됨)**: 조치 지점이 ① 설정 파일 한 곳 ② 다음 세션의 선택(습관·작업 방식)인 것만 코칭한다.
지나간 세션 안에서의 행동 교정 권고는 폐기. (기존 "정밀도의 선" 원칙 유지 — 결정론 사실만 서사에 인용)

## v2 후보 카탈로그 (브레인스토밍에서 우선순위·범위 결정)

지금 수집 데이터(모델 raw·토큰·도구 호출·tool_target·세션·프로젝트·플러그인/MCP 인벤토리·Skill 툴콜)로 탐지 가능:

1. **자동화 버스트 탐지** — 같은 프로젝트에서 턴 수 적은 동형 세션 N건+(temp 경로 패턴, 짧은 간격).
   → "자동화 파이프라인이 Opus로 돌고 있어요. **그 도구의 모델 설정 한 곳**을 haiku로." (실증: cowork-probe 81건)
   기존 R7 세션 finding 다발을 카드 1장으로 흡수.
2. **R7 재설계: 프로젝트 집계 + 시작 시점 권고** — 프로젝트별 "가벼운 Opus 세션" 비율 집계.
   → "이 프로젝트 세션 90%가 잔심부름 — 다음엔 `claude --model sonnet`으로 시작하거나 기본 모델을 낮춰보세요."
   (신규 스코프 개념 필요: session → **project/pattern 집계 finding**)
3. **서브에이전트 미활용** — 대량 편집+큰 출력 구현 세션 + `Task`(SubAgent) 0회 (+플랜 문서 Read 흔적 휴리스틱).
   → "확정 플랜 구현은 superpowers subagent-driven-development로 — 컨트롤러만 Opus, 구현은 sonnet."
4. **권한 재시도 낭비** — 동일 도구+동일 tool_target 연속 호출(권한 거부 재시도 패턴, 실증: Write 3연발).
   → "settings.json 허용목록에 추가하면 거부→재시도 낭비가 사라져요."
5. **컨텍스트 눈덩이** — 세션 후반 턴당 input이 초반 대비 급증한 장수 세션.
   → "긴 세션은 /compact, 독립 작업은 새 세션/서브에이전트 분리."
6. **유용한 스킬 설치/사용 제안** (사용자 제안) — ①설치돼 있는데 작업 패턴과 매칭되는 스킬 미사용
   ("대형 구현 세션인데 플랜/브레인스토밍 스킬 호출 0회") ②미설치 추천은 큐레이션 테이블(rule→추천 스킬)로 시작.
   절약이 아닌 **가치 제안** 코칭 — 멘토 정체성에 부합.
7. **R1/R2 서사 강화** (사용자 제안) — 플러그인/MCP 용도 설명 + 사용자의 실제 작업과 대조.
   "frontend-design 플러그인은 UI 디자인 작업에 유용해요. 최근 작업은 그런 것과 무관해서 상주 토큰만 소비 중이에요."
   용도 메타는 큐레이션 사전(알려진 플러그인 용도 테이블)으로 결정론 유지. 스킬 description 활용 검토.

**유예 유지**: 캐시 히트율·MCP 대형 결과 폐기·에러 정밀 탐지(R3/R4/R8)는 ToolResult/UserPrompt 수집 선행 필요.
