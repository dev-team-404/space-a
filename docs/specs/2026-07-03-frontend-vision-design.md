# Agent Mentor — 프론트엔드 비전 & 1단계(셸+데이터) 설계

> **상태**: 브레인스토밍 합의 완료 (2026-07-03)
> **범위**: Tauri v2 프론트엔드 전체 비전(3-윈도우 + 마스코트 + 미니홈피)과 1단계(셸+데이터)의 상세 설계.
> 2·3단계(마스코트, 미니홈피 완성)는 비전 수준으로만 담고, 착수 시 별도 상세 스펙을 쓴다.
> **선행**: 백엔드 크레이트 완성 상태(main 93330a9, R1·R2·R5·R7·R9 + 다이어리, cargo test 87 무경고).
> **제약**: Tauri v2 전용(v1 API 금지), Windows 전용, 상주/업데이트/자동시작은 v2 공식 플러그인만.

---

## 1. 합의된 비전 요약

| 항목 | 결정 |
|---|---|
| 마스코트 정체성 | **레트로 픽셀아트 소형 로봇**. 다이어리 페르소나(1인칭, "주인"을 섬기는 다마고치풍)와 동일 인물 |
| 개인화 | 안정적 ID(호스트명+사용자명) 해시를 시드로 **파츠 조합형 절차 생성** — 사용자마다 다른 로봇 |
| 전체 미감 | **싸이월드풍 레트로** — 미니홈피, 미니룸, 도트 폰트, 파스텔+도트 프레임 |
| chat 창 구조 | 미니홈피형: 왼쪽 사이드바(카운터·미니룸·기분) + 탭 **홈 / 다이어리 / 코칭 / 채팅** |
| 다이어리 열람 | 채팅 메시지로 흘리지 않고 **다이어리 탭에서 달력 기반 날짜별 열람** |
| 말풍선 트리거 | ① 새/악화 finding ② 다이어리 완성 ③ occasions(기념일·마일스톤) ④ 유휴 잡담(빈도 설정) |
| 파이프라인 | notify 감시 → **60초 디바운스 배치**로 ingest→inventory→rules, WSL UNC는 30초 폴링 폴백 |
| 다이어리 생성 | **자정 이후 첫 파이프라인 완료 시 전날치 자동 생성**(밀린 날짜 순차 보충) |
| 마스코트 창 | **제자리형** 작은 투명 창(~160×160), 드래그로만 이동, 말풍선 때만 일시 확장 |
| 프론트 스택 | **Svelte 5 + Vite 멀티페이지**(창별 엔트리), 로봇 렌더는 canvas 픽셀 그리드 |

## 2. 리포 구조 — cargo workspace 재구성

```
agent-mentor/
├─ Cargo.toml              # [workspace] members = ["crates/core", "src-tauri"]
├─ crates/core/            # 기존 백엔드 크레이트를 무수정 이동 (adapter·hosts·store·rules·diary·inventory)
│                          #   CLI(main.rs)는 core의 bin으로 유지 — 디버깅용
├─ src-tauri/              # Tauri v2 앱 크레이트
│  ├─ tauri.conf.json
│  └─ src/
│     ├─ lib.rs            # 앱 셋업, 윈도우·플러그인 등록
│     ├─ commands.rs       # #[tauri::command] 배선
│     ├─ pipeline.rs       # notify 감시·디바운스·diff (Tauri 무관 순수 로직 분리)
│     └─ tray.rs           # 트레이 아이콘·메뉴
├─ src/                    # Svelte 5 + Vite 멀티페이지
│  ├─ mascot.html          # mascot 창 엔트리 (2단계에서 활성)
│  ├─ chat.html            # chat 창 엔트리
│  └─ lib/
│     ├─ api.ts            # invoke/listen 래퍼
│     ├─ robot/            # 파츠 라이브러리·canvas 렌더 (2단계)
│     └─ ui/               # 탭·달력·목록 컴포넌트
└─ docs/
```

- 기존 코드는 `crates/core`로 **이동만** 한다(경로 외 무수정). 검증 기준: 기존 87 테스트 무변경 통과.
- `src-tauri`는 path 의존으로 core를 사용. 공개 함수는 이미 배선 가능한 형태.

## 3. 윈도우 구조와 트레이

| 창 | 속성 | 동작 |
|---|---|---|
| (tray) | 창 아님, Tauri v2 코어 tray API(`tray-icon` 기능 플래그) | 좌클릭 → chat 토글. 우클릭 메뉴: 열기 / 마스코트 표시 ✓ / 지금 스캔 / 시작 시 실행 ✓ / 종료 |
| mascot | ~160×160, 투명·무테두리·alwaysOnTop·skipTaskbar | 제자리형, 드래그 이동(위치 영속화). 말풍선 표시 시 창 일시 확장(~320×220) 후 복원. 클릭스루 폴링 불필요(작은 창 전략) |
| chat | 일반 창 ~900×640 | on-demand 표시. X 버튼 → destroy 아닌 **hide**(상주 유지) |

- **autostart**: `tauri-plugin-autostart`(공식 v2)로 1단계부터. 트레이 메뉴에서 토글.
- **updater**: 서명 인프라 필요 → 1단계에서는 `tauri-plugin-updater` 설정 뼈대만 두고 3단계에서 활성화.
- 창 위치·설정 영속화는 SQLite `settings` 테이블(또는 동등한 로컬 저장)에.

## 4. 백그라운드 파이프라인

```
notify 감시(호스트별 projects/**)      Windows: RecommendedWatcher
        │                             WSL UNC: 30초 PollWatcher 폴백
        ▼
  60초 디바운스 배치 (변경 이벤트가 조용해질 때까지 모음)
        ▼
ingest(증분) → inventory → rules 재실행     ← 기존 관대한 수집 정책 그대로
        ▼
finding diff (dedup_key 기준 신규/악화만 추출)
        ▼
이벤트 emit: "coach:finding" → mascot 말풍선 · chat 코칭 탭 갱신
```

- 앱 시작 시 풀 스캔 1회.
- **자정 이후 첫 파이프라인 완료 시** 전날치 다이어리 생성 → `"diary:ready"` emit → 말풍선. PC가 꺼져 있었으면 다음 부팅 때 밀린 날짜를 순차 생성.
- 파이프라인은 전용 스레드 + 채널. `SqliteStore`는 `tauri::State<Mutex<SqliteStore>>`로 커맨드와 공유.
- watcher 사망 시 자동 재시작.

### 커맨드 표면 (1단계)

| 커맨드 | 반환 | 용도 |
|---|---|---|
| `get_summary()` | 오늘 세션 수·모델별 토큰·절약 가능 토큰 합계·마지막 스캔 시각 | 홈 탭, 사이드바 카운터 |
| `list_findings()` | Finding 목록(severity·evidence·prescription·est_tokens_saved) | 코칭 탭 |
| `list_diary_dates()` | 일기 존재 날짜 목록 | 다이어리 탭 달력 도트 |
| `get_diary(date)` | 해당 날짜 일기 본문 | 다이어리 탭 |
| `get_mascot_seed()` | RobotSpec(파츠 인덱스·팔레트) | 로봇 렌더(2단계 사용, 배선은 1단계) |
| `run_scan_now()` | 파이프라인 즉시 1회 실행 | 트레이 "지금 스캔" |
| `get_settings()` / `set_settings(...)` | 설정 (마스코트 표시, 잡담 빈도, contentProtected, autostart 등) | 설정 UI |

## 5. 마스코트 (2단계 비전)

- **절차 생성**: `SHA-256(호스트명+사용자명)` → u64 시드 → Rust `get_mascot_seed`가 `RobotSpec { antenna, head, eyes, body, arms, palette }` 결정. Rust에 두는 이유: 다이어리 서사와 로봇 정체성 연동 여지.
- **파츠 라이브러리**(TS 상수): 슬롯 6개 × 변형 ~6종 + 레트로 팔레트 8종 → 수만 조합. 각 파츠는 16×16 그리드 픽셀 좌표 배열.
- **렌더**: canvas 16×16 → `image-rendering: pixelated` 8배 확대.
- **애니메이션 상태 머신**: `idle`(바운스·깜빡임) / `talk` / `happy` / `alert` / `sleep`(새벽). 프레임은 파츠 오프셋·스왑이라 모든 조합에 공통 적용.
- **말풍선**: 픽셀 보더, 최대 2줄, 5–8초 자동 소멸, 클릭 시 chat 관련 탭 오픈(finding→코칭, diary→다이어리). 동시 발생은 큐로 순차. 유휴 잡담은 빈도 설정(기본 보수적).

## 6. chat 창 = 미니홈피 (1단계 뼈대, 3단계 완성)

```
┌─────────────────────────────────────────────────┐
│  ♪ agent mentor                          _  □  ✕ │
│ ┌───────────┐  ┌[홈]─[다이어리]─[코칭]─[채팅]────┐ │
│ │ TODAY 12  │  │                                │ │
│ │ TOTAL 345 │  │        (탭 콘텐츠)              │ │
│ │ ┌───────┐ │  │                                │ │
│ │ │미니룸  │ │  │                                │ │
│ │ │  🤖   │ │  │                                │ │
│ │ └───────┘ │  │                                │ │
│ │ 오늘의 기분 │  │                                │ │
│ └───────────┘  └────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

- **사이드바**: TODAY/TOTAL(오늘 세션 수/누적 — 싸이월드 방문자 카운터 오마주), 미니룸(픽셀 방+내 로봇, 클릭 리액션, 3단계), 로봇의 "오늘의 기분" 한 줄(최근 finding 상황 반영).
- **홈 탭**(1단계): 오늘 요약 — 세션 수, 모델별 토큰, 절약 가능 토큰 합계, 최근 알림 히스토리, 하단 상태줄(마지막 스캔 HH:MM · 경고 N건).
- **다이어리 탭**(3단계): 미니 달력(일기 있는 날 도트) → 날짜 선택 시 본문. occasions 뱃지.
- **코칭 탭**(1단계): finding 목록(severity 아이콘·규칙별 그룹·~절약 토큰) → 클릭 시 evidence·prescription 상세.
- **채팅 탭**(3단계): 마스코트와 1:1 대화. 기존 `Engine` 추상화 재사용, 엔진 미설정 시 안내. 1단계에는 자리만.
- **스킨**: 한글 픽셀 폰트(Galmuri·둥근모 계열), 파스텔+도트 프레임. 1단계는 기본 스킨, 3단계에서 완성.

## 7. 에러 처리

- 파이프라인은 기존 CLI의 관대한 정책 유지(파일 단위 실패 스킵, reconcile 읽기 가드). **에러를 말풍선으로 알리지 않는다** — 홈 탭 상태줄과 tray 툴팁에만 표시.
- 다이어리 엔진 실패(네트워크 등): 조용히 다음 파이프라인 사이클에서 재시도.
- 커맨드 에러는 `Result<T, String>` → 프론트 토스트.

## 8. 프라이버시

- `contentProtected`(스크린샷 방지)는 설정 옵션, **기본 off**.
- 외부 전송 경계는 기존과 동일: Engine 옵트인뿐. 채팅 탭도 같은 경계 안.

## 9. 테스트

- `crates/core`: 기존 87 테스트 **무변경 통과**가 workspace 이동의 검증 기준.
- `src-tauri`: 디바운스·finding diff(신규/악화 판정)를 Tauri 무관 순수 모듈로 분리해 단위 테스트.
- 로봇 생성: 같은 시드 → 같은 RobotSpec 결정성 테스트(Rust). 파츠 렌더 스모크는 vitest 최소(2단계).
- E2E는 수동 체크리스트(Tauri WebDriver 불안정).
