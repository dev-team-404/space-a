## 0. 기능 지도

| 계열 | 기능 | 외부 의존 |
|---|---|---|
| **코칭** (핵심) | 수집 · 인벤토리 · 규칙 엔진 · 코칭 탭 | 없음 (완전 로컬) |
| **서사** | 다이어리 · 오늘의 한마디 · 잡담 · 채팅 · 메모리 | LLM 엔진 |
| **배움 피드** | 콘텐츠 큐레이션(오늘의 배움) | 인터넷 + (번역은 LLM) |
| **캐릭터** | 마스코트 창 · 절차 생성 로봇 · AI 스프라이트 · 오늘의 컷 · 프로필/MBTI | 이미지 모델(선택) |
| **팀 연동** | 지식 공유 · 인정 루프 · 텔레메트리 · 세션 회고 | a-hub (work) |
| **미니홈피** | 방 · 방문 · 방명록 · 인테리어 · 친구/공개범위 | a-hub (life) |
| **셸** | 트레이 상주 · 자동 시작 · 자동 업데이트 · 테마 스킨 | 릴리스 저장소 |

**전부 꺼져 있어도 앱이 동작한다.** 외부 의존이 있는 기능은 조건 미충족 시 조용히 no-op이고,
코칭 계열(수집·규칙·UI)은 인터넷 없이 완결된다.

## 1. 데이터 수집 (Windows + WSL 통합)

**무엇을**: Claude Code가 남기는 로컬 기록 전부.

- `~/.claude/projects/**/*.jsonl` — 세션 트랜스크립트 (메시지, tool_use/result, 토큰 usage, 모델명)
- `settings.json` / `~/.claude.json` / 프로젝트 `.mcp.json` — 활성 MCP 서버·플러그인 셋
- `skills/`·`plugins/` 디렉터리 — 설치 자산 스냅샷 (신규 감지 diff용)

**어디서**: Windows `%USERPROFILE%\.claude` + WSL 전 distro (`wsl -l -q`로 열거 →
`\\wsl.localhost\<distro>\home\*\.claude` UNC 접근, username 하드코딩 없이 자동 발견).
각 소스는 `host` 라벨(`Windows` | `wsl:<distro>`)로 구분되어 한 스토어에 통합된다.

**어떻게**:

- `notify` 파일 감시 → **60초 디바운스 배치**로 ingest → rollup → inventory → rules. WSL UNC는 폴링 폴백.
- **증분 수집**: 파일별 offset 워터마크(`ingest_state`)부터 tail. 쓰이는 중인 미완결 라인은 버퍼링하고 완결 라인만 파싱 — 동시 다중 세션 append에 안전.
- **멱등 upsert**: `dedup_key` `INSERT OR IGNORE`라 재실행/재시작 안전.
- **관대한 파싱**: 스키마 이상은 로깅만, 절대 하드 실패하지 않음. 파일 단위 실패는 스킵.
- 앱 시작 시 풀 스캔 1회.

**프라이버시 설계**: 대화 원문(프로즈)은 DB에 저장하지 않는다. 분류 플래그·미리보기 한 줄·
**원본 포인터(source_file + offset)** 만 저장하고, 세션 상세를 열 때만 JSONL에서 지연 로드(deref)한다.
원본이 삭제되면 미리보기로 graceful fallback. Bash 명령의 시크릿은 `<redacted: secret>`로 치환해 저장한다.

## 2. 인벤토리 — always-on 비용의 지반

세션과 별개로 "지금 설정에 뭐가 깔려 있나"의 시점 스냅샷을 관리한다.

- 세 곳(글로벌 settings의 enabledPlugins / `~/.claude.json`의 프로젝트별 mcpServers / 프로젝트 `.mcp.json`)을 종합해 **세션에서 활성인 MCP 셋**을 산출.
- **snapshot-replace reconciliation**: 스캔마다 호스트별 인벤토리를 현재 활성 셋으로 원자적 교체(트랜잭션). 단, 설정 파일 읽기가 일시 실패하면 그 호스트는 스킵(오삭제 방지 가드).
- 사용 이력(`events`)은 역사적 사실이라 절대 삭제하지 않음.
- **총 always-on 토큰 = 정확 측정**: 세션 첫 턴의 `cache_creation_input_tokens` ≈ 시스템 프롬프트 + 전체 도구 정의 + CLAUDE.md. 서버별 귀속은 차등+휴리스틱 추정("약 ~" 라벨).
- 개인 스킬 인벤토리(`personal_skill_inventory`)도 함께 갱신된다.

## 3. 코칭 규칙 엔진

모든 코칭은 **Finding** 1건으로 환원된다: `rule_id`, `severity(info|suggest|warn)`, `scope`,
`evidence`(규칙이 로그에서 직접 센 실측 근거), `prescription`(처방), `dedup_key`.
DB 행에는 여기에 `status` · `occurrences` · `first_seen`/`last_seen`이 붙는다.

`est_tokens_saved` 필드도 구조체에 있지만 **등록된 세 규칙이 전부 0으로 두고, 화면에도 내보내지
않는다** — 실제 절약분은 사용자가 조언을 어떻게 적용하느냐에 달려 규칙이 강변할 수 없기 때문이다
(§ [01-product 4.2](01-product.md)). 카드가 보여주는 근거 칩은 룰별 실측치다:
R6 「N개 세션」 · R7 「N개 세션」 · R8 「N회 대형 결과」. 재료가 없으면 칩을 생략한다.

### 3.1 현재 등록된 규칙 (3종)

`ops::registered_rules()`가 실행하는 것이 전부다.

| # | 규칙 | 형태 |
|---|---|---|
| **R6** ⭐ | 반복 지시 → 스킬/커맨드화 | 반복 프롬프트 감지 → 세션 되짚어 실사용 도구 집계 → SKILL.md 초안 생성·저장 |
| **R7** | 사소한 작업에 상위 모델(Opus) | 프로젝트 잔심부름 비율 집계 + "다음 세션 시작 시점"의 모델 선택 권고 |
| **R8** ⭐ | MCP 대형 결과 | 서버별 큰 결과 집계, 측정된 평균/누적 토큰 인용, "필드 좁히기" 권고. **유일한 팀 공유 대상** |

### 3.2 은퇴한 규칙 (코드는 남아 있음)

`rules/` 디렉터리에는 R1·R2·R5·R9·R10·R11·R12 파일이 있지만 **등록되어 있지 않다.**
코드를 지우지 않은 이유는 다른 규칙이 계속 쓰는 헬퍼가 섞여 있어서다
(예: `r10_automation_burst::detect_bursts`는 R7의 후보 제외에 쓰인다).

| 규칙 | 은퇴 사유 |
|---|---|
| R1 안 쓰는 MCP / R2 미사용 플러그인 | 코칭 v3에서 정리 — 조치 레버가 약하고 오탐이 잦았다 |
| R5 크로스세션 반복 Read | 주체가 대부분 에이전트 자신이라 "사용자 잘못"으로 오독됨 (§ 04-history 3.3) |
| R9 웹 도구 남용 / R10 자동화 버스트 / R11 권한 마찰 / R12 스킬 미활용 | 코칭 v3 정리 |
| R24 컨텍스트 위생 | 완전 제거 ([`specs/2026-07-23-retire-r24-context-hygiene.md`](../../archive/design/a-mate/specs/2026-07-23-retire-r24-context-hygiene.md)) |

R3(캐시 히트율)·R4(1h 캐시 미재사용)는 여전히 미구현이다.

### 3.3 LLM 판정 계층

결정론 규칙 위에 `run_coaching_judgments`(`judge.rs`)가 얹힌다. 엔진이 없으면 no-op이라
결정론 코칭에는 영향이 없다. 세션 work-kind 분류(`session_work_kinds`)도 같은 계층이다.

### 3.4 나깅 방지

- dedup_key 기준 upsert — 같은 지적은 카드 1장에 `occurrences`만 증가.
- **상태**: `new` → 「해결함」(`resolved`) 또는 「무시」(`dismissed`). LLM 판정 계층이 쓰는
  `pending`(판정 대기)·`rejected`(판정 탈락)는 내부 상태라 **UI에 노출하지 않는다**(fail-safe 침묵).
- **처분은 재스캔에도 유지된다** — dedup_key 충돌 시 evidence·occurrences만 갱신하고 status는 건드리지 않는다.
- **두 처분의 수명이 다르다.** 「해결함」은 7일간 스트림 하단의 접힌 줄로 남아 실행취소할 수 있고
  (그 뒤엔 화면에서만 사라지고 DB 행은 재발 감지용으로 보존), 「무시」는 영구히 접힌 줄이다.
- **재발하면 돌아온다** — 근거 칩과 **같은 룰별 실측 수치**가 처분 시점보다 늘었을 때만 활성으로 복귀한다.
- **칭찬 루프** — 레슨을 내보낸 뒤 실측이 좋아지면(캐시 재읽기 30%+ 감소, 도구 오류 절반 이하)
  칭찬 레슨이 발화하고 같은 축의 잔소리는 침묵한다.

## 4. 다이어리

에이전트(마스코트)가 1인칭으로 쓰는 하루 일기. 단순 템플릿이 아니라 **LLM 필수**, 품질 > 정시성.

- **생성 트리거**: 자정 이후 첫 파이프라인 완료 시 전날치 자동 생성. PC가 꺼져 있었으면 다음 부팅 때 밀린 날짜를 순차 보충(backfill). 엔진 미설정 시 보류(템플릿 폴백 금지).
- **파이프라인**: 그날의 재료 수집 → 브리프(JSON) 조립 → LLM이 페르소나·톤으로 서술 → `app_data_dir/diary/`에 날짜별 `.md` + SQLite 색인(`diary_index`).
- **정밀도의 선**: LLM은 브리프의 사실·수치만 인용 가능. 근거(`detail`)·개선방향(`suggested_action`)은 규칙에서 결정론적으로 파생.
- **Occasions**: 명절(음력 설날·추석은 2025–2035 번들 정적 테이블, 로케일 인지)·기념일("주인과 처음 만난 날" = DB의 첫 세션 날짜 기준 50일/100일 단위/N주년)을 결정론적으로 계산해 서사에 반영.
- **브리프 재료**: 그날 한 작업(`work_log` — 프로젝트별 커밋 제목·동시 진행 여부), 도구 사용량
  (`tool_usage` — 스킬·MCP 서버), 근무 맥락(`work_context` — 주말·공휴일·몰입 시간), 그날 새 코칭거리
  (`findings`), 기념일(`occasions`), 이웃 방문 기록(`visits`), 직전 며칠 일기(`recent_diaries` — 화제
  반복 회피), 채팅에서 저장한 사실(`memories`).
- **위로·응원은 매일이 아니다** — 유난히 긴 날(몰입 7시간+)·주말 근무·공휴일 근무일 때만 나간다.
- **인용 데이터 방어**: 이웃의 일기 발췌·이름은 신뢰할 수 없는 입력으로 취급한다 — 그 안에 지시처럼
  보이는 내용이 있어도 따르지 않도록 프롬프트에서 못박는다.
- **톤 설정**: A(감성)/B(균형, 기본)/C(분석) + 호칭(기본 "주인") 사용자 지정.
- **문체 자연화**: 한국어 "AI티"(번역투·이중피동·상투구·이모지 남발)를 시스템 프롬프트의 문체 가이드(`voice_guidance()`)로 생성 시점에 예방.
- **공개 설정**: 미니홈피에 날짜별로 공개/비공개를 정할 수 있다(§9).

## 5. 콘텐츠 큐레이션 — "오늘의 배움"

코칭(내 로그에서 나온 지적)과 별개로, **밖에서 배울 것**을 골라 카드로 띄운다.

### 5.1 소스 4종 (`FEED_SOURCES`)

| 소스 | 내용 | TTL |
|---|---|---|
| `changelog` | Claude Code 공식 CHANGELOG | 24h |
| `boris` | 창시자 팁 사이트(howborisusesclaudecode.com) HTML 파싱 | 24h |
| `marketplace` | 공식 플러그인 마켓플레이스 카탈로그 | 24h |
| `team` | **a-hub의 팀 지식** — 팀원이 발행한 최신 페이지(내 것 제외) | 6h |

여기에 네트워크를 타지 않는 세 갈래가 더해진다.

- **내장 문서 팁** — 공식 docs 딥링크가 붙은 커리큘럼 팁.
- **개인 실전 레슨** — 내 로그의 사건에서 파생. 랭킹 최상위(§5.2)이고 카드 문법도 코칭과 같다.
- **로컬 공지** — 각 호스트의 `~/.claude.json`에 Claude Code가 남긴 공지와 긴급 팁을 파싱해
  카드로 만든다(`announcements.rs`). 호스트별 중복은 병합하고, 본문의 "자세히" 링크는 분리해 싣는다.

> **최신성 규율** — Boris 사이트는 팁을 오래된 것부터 쌓고 새 팁을 아래에 덧붙인다(실측 105개).
> 파서는 **뒤에서 잘라** 최신 N개만 취한다. 앞에서 자르면 창시자가 최신 모델을 권하고 있어도
> 우리는 영원히 옛 모델 팁을 1순위로 띄우게 된다(2026-08-03 실제 발생 → 수정).

### 5.2 랭킹

`score()`가 역량 프로필(`CompetencyProfile`)의 **프론티어**(다음에 배울 축)에 맞춰 정렬한다.

| 점수 | 대상 |
|---|---|
| 550 | 개인 실전 레슨 — 내 로그의 사건이 일반 커리큘럼보다 먼저 |
| 500 | 프론티어 축과 일치하는 팁 |
| 320 | 로컬 공지 |
| 그 외 | 태그 매칭 / 소식(changelog) / 태그 미스 / 마스터한 축은 침묵 |

- **프룬**: 피드에서 사라진 `status='new'` 카드는 자동 삭제. 단 사용자가 닫은(`dismissed`) 카드는 쿨다운 기록으로 보존한다.
- **번역**: 영어 소스는 아이템당 1회 LLM 번역해 `title_ko`/`summary_ko`로 캐시. 한국어 소스(팀 지식·내장 팁)는 대상이 아니다.
- 카드는 **코칭 탭**에 표시된다(2026-08-02 홈 → 코칭 이동).

## 6. 마스코트

### 6.1 창과 렌더

- 투명·무테두리·alwaysOnTop의 작은 창(280×280, 말풍선 시 일시 확장). 드래그로만 이동, 위치 영속화(`geometry::sanitize_pos`가 모니터 구성 변경을 방어).
- **절차 생성 로봇**(폴백·기본): `SHA-256(정체성)` 시드 → Rust가 `RobotSpec`(슬롯 × 변형 + 팔레트) 결정 → 프론트가 128px canvas에 프로시저럴 드로잉. 사용자마다 다른 로봇.
- **AI 스프라이트**(선택): 이미지 모델이 설정돼 있으면 시드에서 만든 캐릭터 설명으로 스프라이트를 생성하고, 흰 배경을 투명으로 처리해 마스코트 창에 건다. 실패하면 절차 생성 로봇으로 자연 폴백.
- **애니메이션 상태 머신**: `idle`(바운스·깜빡임) / `talk` / `happy` / `alert` / `sleep`(새벽 1–7시). `requestAnimationFrame` 단일 루프 + 순수 함수 `frameAt`.

### 6.2 말풍선 트리거

| 트리거 | 내용 | 클릭 시 |
|---|---|---|
| `coach:finding` | 새/악화 finding | 코칭 탭 |
| `diary:ready` | 일기 완성 | 다이어리 탭 |
| `occasion:today` | 기념일·명절 | 홈 탭 |
| `announcement:new` | 새 공지 | 코칭 탭 |
| `life:visit` · `guestbook:new` | 방문·방명록 | 미니홈피 |
| **`reuse:celebrated`** | **내 지식이 팀에서 쓰였다** | 코칭 탭 |
| 유휴 잡담 | 주기적 한마디 | 홈 탭 |

여기에 **실시간 조언**(옵트인, `realtime_advice`): 스캔 완료 시 최상위 조언 1건. FIFO 큐(최대 5건).
에러는 절대 말풍선으로 알리지 않는다(홈 탭 상태줄·트레이 툴팁만).

### 6.3 보이스 (LLM 페르소나)

다이어리·채팅과 **동일 인물**이 말하는 것처럼 들리게 하는 계열. 모두 "정밀도의 선"과
`voice_guidance()` 문체 가이드를 공유하고, **MBTI 힌트**(`mbti_voice_hint`)로 말투가 갈린다.

1. **다이어리 문체 자연화** — §4.
2. **오늘의 한마디** — 프로필 초상 밑 상시 1줄. fingerprint가 바뀐 경우에만 LLM 재생성 + 날짜 캐시. 활동 0건이면 LLM 없이 정적 1줄.
3. **잡담 풀** — LLM 1결 + 정적 2결 혼합. 하루 최대 1회 배치 생성·캐시(`chatter_pool`), 프론트 타이머는 pick만(최근 3개 회피). 빈도는 트레이 서브메뉴(자주 / 가끔(기본) / 안 함), 새벽 1–7시 침묵.

### 6.4 프로필 · 오늘의 컷

- **프로필**: 이름 / 소속(org) / uuid / MBTI. 마스코트 외형 시드와 말투에 반영되고, 미니홈피 이름표에도 쓰인다.
- **오늘의 컷**: 하루 1장, 마스코트가 등장하는 장면 이미지를 생성한다. 일일 상한을 `daily_cut.json` 원장으로 관리하고, 수동 버튼(설정 탭 "지금 그려보기")과 자동 스캔이 겹치지 않게 `try_lock`으로 가드한다.

## 7. chat 창 = 미니홈피 UI

싸이월드 미니홈피의 레이아웃 문법(타이틀바 카운터, 좌측 컬럼, 책갈피 탭)에
**파스텔 모던 스킨**을 입힌 메인 창(948×820). X 버튼은 destroy가 아닌 hide(상주 유지).

탭 6개: **홈 · 코칭 · 다이어리 · 채팅 · 방명록 · 설정**

- **홈**: 오늘 스트립(세션·입력·출력) + 위젯 2×2(주간 추이 / 모델 분포 / **지금 볼 코칭** / 최근 알림) + **방**(허브 연결 시 격자 방 `LifeView`, 미연결 시 장식 방 `MiniLife`) + 상태줄(마지막 스캔·지금 스캔).
  「지금 볼 코칭」은 코칭·학습·소식 3종을 코칭 탭과 **같은 kind 색 레일**로 보여주고, 누르면 그 카드로 딥링크한다.
- **코칭**: 코칭·배움·소식이 하나의 시간순 스트림으로 흐른다 — 상세는 §7.1.
- **다이어리**: 미니 달력(일기 있는 날 도트) → 날짜 선택 시 본문(`marked` + `DOMPurify.sanitize`).
- **채팅**: 마스코트 페르소나와 1:1 대화. `Engine` 재사용 + 코칭 컨텍스트 주입. 트랜스크립트 원문은 전송하지 않는다. **메모리 툴**(`save_memory`)로 대화 중 알게 된 사실을 `memories`에 남긴다.
- **방명록**: 내 방 방명록 읽기/쓰기/삭제 + 봇 자동 답글(1-depth, 봇 라벨 표기).
- **설정**: 나(프로필·호칭·톤) / 연결(LLM 엔진·이미지 모델·**팀 지식 허브**·미니홈피 서버) / 외형(테마 모드 × 스킨) / 프라이버시 / 앱 정보.

**테마**: 모드(light/dark, 기본 `system`) × 스킨(sky·mint·peach·lavender) 조합. 색·radius·그림자는
`theme.css`에서만 정의하고 컴포넌트는 시맨틱 토큰만 참조한다 — `no-hardcoded-colors.test.ts`가 이를 강제한다.

### 7.1 코칭 탭 — 한 줄 스트림

섹션 헤더가 없다. 코칭거리·배움·소식이 **`first_seen` 내림차순 한 줄**로 흐르고, 분류는
**좌측 레일 색과 배지**가 나타낸다. 시각을 모르는 항목은 맨 뒤로 간다.

| 분류 | 무엇이 | 카드 문법 |
|---|---|---|
| **코칭** | 룰 finding(R6·R7·R8) + 개인 실전 레슨 | 문법 A — 로그 카드 |
| **학습** | 커리큘럼 팁 · Boris · 팀 지식 | 문법 B — 카드뉴스 |
| **소식** | changelog · 로컬 공지 | 문법 B — 카드뉴스 |

- **문법 A(로그 카드)**: 심각도 아이콘 · 제목 → 근거 + 근거 칩 → (LLM 판정이 있으면) 왜 →
  원리(개인 레슨 전용) → 어떻게. `fix_command`가 있으면 **📋 명령 복사** 버튼이 붙고,
  R6은 **SKILL.md 초안**을 띄워 복사하거나 스킬로 저장할 수 있다(엔진 미설정이면 기본 골격).
  raw evidence는 접힌 「원본 데이터」로 격하한다.
- **문법 B(카드뉴스)**: 분류 배지 + 보조 칩(공지 · Boris · 팀 · 역량 축 라벨) · 제목 ·
  📊 근거 한 줄(내 로그 실측) · 요약 · 출처 링크. 번역 캐시가 있으면 한국어, 없으면 원문 폴백.
- **카드 상한은 없다.** 화면에 뜨는 집합과 탭 배지가 세는 집합이 정확히 일치한다.
  노출 필터는 백엔드가 갖는다(`score >= 0` + 축 쿨다운).
- **탭 배지 = 미확인 카드 수.** 코칭 탭을 열면 그때 화면에 있던 활성 키를 「본 것」으로 저장한다
  (localStorage). 배지와 화면이 같은 재료를 본다.
- **고정 슬롯**: 기한이 있고 · 유효하고 · 아직 확인하지 않은 소식 1건을 스트림 위에 고정한다.
  `[확인]`을 누르거나 **기한이 지나면 자동으로** 일반 카드로 강등된다 — 기한 오추출의 안전망이다.
- **공지 수명**: 데이터에 발행 시각이 없어 「우리가 처음 본 때」로 잰다. 일반 공지 7일, 긴급 팁 2일이
  지나면 스트림에서 걷어낸다.
- **처분 줄**: 스트림 하단에 토글 없이 노출한다. 「해결함」 7일 · 「무시」 영구, 둘 다 실행취소 가능.
- 내부망 환경으로 판단되면 외부 링크를 숨긴다.

## 8. 팀 지식 연동 (a-hub / work)

기본값으로 `https://spacea.msalt.net`의 `sw-innov` 공간에 붙는다(설치 직후 바로 동작).
API 키는 기본값을 두지 않으며 설정 탭에서 1회 입력한다.

### 8.1 지식 공유 (송신)

선별 조건은 `화이트리스트 ∩ status=new ∩ 문턱 통과 ∩ 미공유`, 상한 `MAX_PER_SCAN`.

| 상수 | 값 |
|---|---|
| `SHARE_RULES` | `["R8"]` — R6은 프롬프트 원문이 증거라 제외, R7은 개인 선택이라 제외 |
| `DEFAULT_MIN_TOKENS` | 1000 |
| `MIN_OCCURRENCES_WHEN_NO_EST` | 3 |
| `MAX_PER_SCAN` | 3 |

**무조건 올리지 않는다** — 마커로 팀에 같은 지식이 있는지 먼저 검색(`POST /pages/search`)하고,
있으면 중복 발행 대신 **인용**(`/issues/{id}/cite`), 없으면 새로 발행(`/issues` → `/resolve`).

### 8.2 인정 루프 (수신)

내가 올린 지식을 남이 인용하면 앱이 축하한다. 커서 규약이 dedup을 대신해 **한 이벤트는 평생 1회만** 알린다.
첫 실행에는 emit 없이 커서만 초기화해 설치 직후 도배를 막는다. 상세는
[`03-architecture.md` §7.3](03-architecture.md).

### 8.3 텔레메트리 · 세션 회고

- **텔레메트리**: 하루 1회, 자정 지나 첫 스캔에 어제치. **숫자만** (세션 수·토큰 합계·모델 비율 등). 활동 0인 날은 침묵.
- **세션 회고**: 오류를 여러 번 겪고 회복한 세션만, 종료 후 일정 시간 뒤. Engine이 쓴 2~3문장 로컬 생성 요약만 나간다(엔진 없으면 보류).

**개인정보 경계**: 대화 원문·파일 경로·세션 ID·cwd는 어떤 채널로도 나가지 않는다.

## 9. 미니홈피 (a-hub / life)

지식 공유와 **별개 서버·별개 설정**(`hub_*` 키)으로 돌아가는 소셜 계열.

- **방**: 격자 방에 내 로봇이 서 있고, 셀 단위로 이동한다. 인테리어(가구·창문·바닥)를 배치·저장한다.
- **방문**: 남의 방에 들어가 구경한다. 자동 방문(`maybe_auto_visit`)도 있다. 수신은 커서 diff로 알림.
- **방명록**: 글 남기기/삭제 + 봇 자동 답글(1-depth).
- **친구·공개범위**: 친구 지정, 콘텐츠/다이어리별 공개 범위 설정.
- **동기화**: 마스코트 이미지·얼굴·오늘의 한마디·오늘의 컷을 방에 반영한다.

## 11. LLM · 이미지 엔진

| | 설정 키 / 환경변수 | 없으면 |
|---|---|---|
| **LLM 엔진** | `engine_*` 설정 / `AGENT_MENTOR_ENGINE_URL`·`_KEY`·`_MODEL` | 서사·번역·판정만 no-op. 수집·규칙·UI는 정상 |
| **이미지 모델** | `image_*` 설정 / `AGENT_MENTOR_IMAGE_MODEL` (기본 `google/gemini-2.5-flash-image`) | 절차 생성 로봇으로 폴백 |

- 해석 우선순위는 **설정(store) → 환경변수 → 기본값**. `.env`는 debug 빌드에서만 로드되므로,
  배포 빌드에서는 설정 창 입력이 유일한 경로다.
- LLM에는 **결정론적으로 증류한 컴팩트 브리프**만 전달한다(원문 트랜스크립트 통째 전송 금지).
- 엔진 실패는 조용히 다음 사이클에 재시도한다.
