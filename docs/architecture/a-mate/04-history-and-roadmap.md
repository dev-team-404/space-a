# Agent Mentor — 개발 연혁과 로드맵

> 프로젝트가 어떤 순서로, 어떤 의사결정을 거치며 자랐는지의 기록.
> "왜 이렇게 되어 있나"의 맥락을 제공한다. 기준: 2026-08-04.

## 1. 개발 방식

**브레인스토밍 → 설계 스펙 → 구현 플랜 → 구현(PR) → 사용자 수동 E2E → 교훈을 다음 스펙에 반영**
사이클로 개발됐다. 설계와 구현 계획은 [`docs/archive/design/a-mate/`](../../archive/design/a-mate/)에 이력으로 보존한다.

특징적인 점: **실사용 E2E가 설계를 여러 번 뒤집었다** (§3). 스펙은 "합의 시점의 기록"이고,
이후 결정이 바뀐 경우 후속 스펙이 이전 스펙을 명시적으로 참조하며 수정한다.
완료된 spec/plan은 [ADR 0013](../../adr/0013-docs-lifecycle-and-archive.md)에 따라 `docs/archive/`로 옮긴다.

## 3. E2E에서 얻은 교훈 (설계를 뒤집은 것들)

### 3.1 ccusage 위임 → 직접 파싱

킥오프 시점엔 "집계는 ccusage에 위임"이 확정이었으나, 코칭 신호(턴별 cache_read, tool_use 시퀀스,
메시지별 model)는 **턴 단위 이벤트**가 필요하고 집계기인 ccusage는 그걸 못 준다.
→ 원본 JSONL을 직접 파싱하되, 스키마 취약성은 관대한 파싱으로 방어.

### 3.2 세션 단위 코칭 카드는 스팸이 된다 (v1 → v2)

R7("가벼운 작업에 Opus는 과해요")이 실전에서 **같은 지적 81회 노출** — 자동화 도구가 만든 동형
초단기 세션마다 카드가 1장씩 나왔다. 게다가 처방은 사용자의 실제 레버가 아니었다.
→ **v2 원칙**: 조치 지점이 ① 설정 파일 한 곳 또는 ② 다음 세션의 선택인 것만 코칭.

### 3.3 "사용자 잘못"으로 읽히는 규칙은 신뢰를 깎는다 (v2 → v2.1)

R5(같은 파일 반복 Read)의 주체는 대부분 에이전트 자신인데 카드가 "사용자 잘못"처럼 읽혔다.
→ 세션 카드 폐기, 관찰 지표로 재프레이밍. 이후 v3에서 아예 은퇴했다.

### 3.4 규칙은 많을수록 좋은 게 아니다 (v2.1 → v3)

12개 규칙 중 대부분이 **뻔하거나 오탐**이었다. R1·R2·R5·R9·R10·R11·R12를 순차 은퇴하고,
**남긴 3개(R6·R7·R8)에 LLM 판정을 얹는** 쪽으로 방향을 틀었다. 결정론이 후보를 뽑고
LLM이 "이게 진짜 지적할 만한가"를 판정하는 2단 구조다. 지금 `registered_rules()`는 3개뿐이다.

### 3.5 도트 픽셀 ≠ 싸이월드 미니미 (마스코트 렌더 반복)

16×16 도트 → 32×32 → 128px 프로시저럴 드로잉 → **AI 스프라이트 + 절차 생성 폴백**으로 진화.
"여전히 투박"이라는 피드백이 반복됐고, 결론은 미니미가 뚜뚜한 도트가 아니라 매끈한 소형
스프라이트라는 것. 레트로 픽셀 폰트·도트 프레임도 같은 이유로 **파스텔 모던**으로 선회했다.
단, 미니홈피 **레이아웃 문법**(타이틀바 카운터, 좌측 컬럼, 책갈피 탭)은 유지.

### 3.6 LLM 프로즈의 "AI티"는 사후 수정이 아니라 생성 시점에 예방

사후 수정 패스는 토큰·지연 2배에 팩트 드리프트 위험이 있어 기각. 회피목록을 **문체 가이드로
번역해 시스템 프롬프트에 흡수**(`voice_guidance()`), 팩트 안전은 "정밀도의 선"이 담당.

### 3.7 스캔 락을 통짜로 쥐면 UI가 멈춘다 (X1)

마이그레이션 후 전량 재수집(실측 16.7초) 동안 모든 커맨드가 막혔다. 홈 탭 폴링이
inventory+rules를 통째로 기다려 898ms가 나온 사례도 있다.
→ 락을 **단계·파일 단위로** 잡고 놓고, `hand_off()`로 대기자에게 양보하며,
스캔마다 `longest lock hold`를 로그로 남긴다. 자세한 것은
[architecture §9](03-architecture.md).

### 3.8 외부 피드는 "앞에서 자르면" 영원히 낡는다 (2026-08-03)

Boris 팁 사이트는 팁을 **오래된 것부터** 쌓고 새 팁을 아래에 덧붙인다(실측 105개).
파서가 `take(8)`로 앞에서 잘라서, 창시자가 이미 최신 모델을 권하고 있는데도 우리는 3주 넘게
**"Opus 4.5 with Thinking"을 코칭 1순위**로 띄우고 있었다.
→ 뒤에서 자른다. 회귀 테스트 `boris_keeps_the_newest_tips_not_the_oldest`로 고정.

## 4. 현재 상태 (2026-08-04)

- 규칙 3종(R6·R7·R8) + LLM 판정 계층. 나머지는 은퇴(코드는 헬퍼 때문에 보존).
- 등록된 규칙은 절감 추정치를 채우지 않는다 — 카드는 룰별 **실측 수치**로만 말한다.
- 팀 지식 루프가 **닫혔다**: 발행 → 검색·인용 → 재사용 → 인정 알림.
- 코칭 탭은 코칭·배움·소식이 한 줄로 흐르는 시간순 스트림이고, 상한 없이 탭 배지와 같은 집합을 본다.
- 테스트: core 668 · app 48 · 프론트 339(vitest, 30파일) · svelte-check 통과.

**미해결로 남은 것**

| 항목 | 상태 |
|---|---|
| 운영 허브 `GET /reuse-events` | **404** — a-hub 재배포 전까지 인정 루프는 조용히 no-op |
| `UNSUPPORTED` 플래그 | 404를 프로세스 수명 동안 기억 → 허브 배포 후 **앱 재시작 필요** |
| 운영 공간의 중복 페이지 | 테스트 중 잘못 발행된 `page_119`~`page_121` — 권한 문제로 아카이브 실패 |
