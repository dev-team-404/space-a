# Architecture — 현행 상태 문서

**"지금 이렇게 되어 있다"를 기술하는 문서**의 자리입니다.
설계 안·spec·plan 같은 **시점 기록**은 [`../design/`](../design/)에 있습니다.

| 컴포넌트 | 문서 | 상태 |
|---|---|---|
| **a-mate** (Pillar 1) | [a-mate/](./a-mate/) | 이관 완료 |
| **a-hub** (Pillar 2) | [a-hub/](./a-hub/) | 이관 완료 |
| **a-lens** (Pillar 3) | [a-lens/](./a-lens/) | 이관 완료 |

## 여기에 두는 것

제품 소개 · 기능 카탈로그 · 코드 구조 · 개발 연혁 · 빌드/실행 가이드처럼
**코드가 바뀌면 같이 고쳐야 하는** 문서.

## 여기에 두지 않는 것

- 설계 안·spec·plan·brainstorming → [`../design/<component>/`](../design/)
- 확정된 결정 기록 → [`../adr/`](../adr/)
- 완료·폐기 작업 문서 → [`../archive/`](../archive/)

## 규율

- **코드를 바꾸면서 사실이 달라지면 같은 PR에서 고친다.** 별도 정리 작업으로 미루지 않는다.
  미루면 낡는다 — 실제로 a-mate 아키텍처 문서가 3주 넘게 낡은 채 방치된 적이 있다.
- **같은 내용을 두 곳에 두지 않는다.** 리다이렉트 스텁도 두지 않고, 참조하는 쪽 링크를 고친다.
- **문서 상단에 실측 기준을 적는다** (예: `main @ 3a6981a (2026-08-03)`).
  언제 기준의 사실인지 알 수 있어야 낡았는지 판단할 수 있다.
