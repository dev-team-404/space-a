# A-Lens — 현재 기능

> 실측 기준: 2026-08-04

## 1. 홈과 방 관리

첫 화면은 사옥 단면이 아니라 **Space별 방 목록**이다.

- A-Hub에서 받은 Space를 이미 만든 방과 아직 방이 없는 Space로 나눈다.
- 더미 Space에는 `FAKE` 배지를 붙이고, 사용자가 더미 표시 여부를 로컬에 기억할 수 있다.
- 방을 만들 때 Space, 방 배경 프리셋, 책상 종류와 책상 수를 고르고 PixiJS 미리보기를 본다.
- 책상 수는 1~12개 또는 현재 에이전트 수에 맞춘 자동 모드다.
- 생성한 방은 수정하거나 삭제할 수 있다. 같은 Space의 방은 새 설정으로 덮어쓴다.
- 설정 창에서 Work, Life, LLM 연결과 데이터 원천을 런타임에 바꿀 수 있다.

## 2. 관전 방

방은 통짜 배경 프리셋 위에 책상과 사람 캐릭터를 배치한다. 화면에는 최대 24명을 온라인 우선·최근 활동순으로
그리지만, 잘린 사람도 팀 활동 목록에는 남는다. 아무 기록도 보내지 않은 등록 계정은 씬의 책상을 차지하지 않는다.

| 오브젝트 | 현재 동작 |
|---|---|
| 사람 캐릭터 | 클릭하면 이름, 상태와 최근 활동을 열고 그 사람의 작업 기록으로 이동 |
| 칠판 | 방의 오늘 하이라이트를 표시하고 관련 Issue·Page·ReuseEvent를 해당 탭에서 강조 |
| 책장 | 문서 수를 표시하고 문서함 탭을 연다 |
| 책장 배지 | 쌓인 문서 수를 말풍선으로 안내 |
| 창문 | 방 프리셋의 풍경을 주제로 2~3줄 잡담을 표시 |
| 정수기 | 쉬어 가라는 짧은 잡담을 표시 |

창문·정수기 잡담은 LLM을 우선 사용하지만 실패하면 내장 문구를 사용한다. 첫 클릭 지연을 줄이기 위해 방 입장 시
미리 요청한다.

## 3. Collaboration Hub

오른쪽 사이드바는 접기와 300~720px 너비 조절을 지원하고 선택값을 브라우저에 기억한다.

| 탭 | 제공 정보 |
|---|---|
| 작업 기록 | 사람을 고른 뒤 해당 사람의 Issue·문서를 시간순으로 확인. 프로젝트 필터와 페이지 이동 지원 |
| 이슈 공유 | 상태·사람 필터, 오늘/어제/이번 주/이전 묶음, Issue 타임라인과 해결자 표시 |
| 지식 재사용 | 이 방이 주거나 받은 재사용 이벤트, 재사용 횟수와 추천 지식 |
| 문서함 | 작성자가 연결된 전체 Page, 카테고리·사람 필터와 원문 모달 |

별도의 팀 활동 카드는 씬 왼쪽 아래에 유지된다. 사이드바를 접어도 볼 수 있고, 온라인/오프라인 상태와 최근 활동을
표시한다.

## 4. 협업 지도

작업 기록 화면은 사람을 노드로 놓고 관계를 세 종류의 엣지로 분리한다.

- `reuse`: 한 사람이 쓴 지식이 다른 사람에게 실제 인용된 관계
- `handoff`: 다른 사람이 연 Issue를 해결한 사실 관계
- `topic`: 두 사람 문서에 겹치는 희소 주제어를 이용한 추정 관계

사실 엣지와 추정 엣지를 합쳐 하나의 “협업 점수”로 만들지 않는다. 선을 누르면 근거 문서나 Issue가 표시되고,
그 항목의 상세 모달로 이동할 수 있다. A-Mate가 제목에 넣은 프로젝트 마커가 있으면 프로젝트별 부분 지도로 좁힌다.

## 5. 사람 신원과 실시간 갱신

Work 계정에 Life 사용자를 연결할 수 있으면 다음 정보가 적용된다.

- Life의 표시 이름과 주인 이름
- Life 마스코트 원본 이미지
- Life의 `connected`, `last_seen` 기반 상태
- 여러 Work 계정을 한 사람으로 합치는 별칭

Work 계정과 연결되지 않은 Life 사람도 방 사람 목록에서 지우지 않는다. 활동 기록 없이 이름, 마스코트와
접속 상태만 있는 카드로 남긴다 — 연결이 안 됐다는 것은 데이터 상태이지 그 사람이 없다는 뜻이 아니기 때문이다.

방 안에서는 45초마다 사람 정보만 가볍게 다시 읽는다. 캐릭터 위치와 사용자가 보고 있는 탭을 유지한 채 이름,
마스코트와 팀 활동 카드만 갱신하며, 브라우저가 백그라운드이면 폴링하지 않는다.

## 6. 분류·요약·하이라이트

Page와 Issue에는 다음 폐쇄 카테고리를 붙일 수 있다.

`문제해결`, `설계·스펙`, `분석·결과`, `릴리즈·변경`, `노트·회의`, `가이드`

LLM은 문서 하나를 한 번 호출해 명사형 제목, 카테고리, 요약과 한 줄 서사를 함께 만든다. 생성된 제목은 원문
제목이 길거나 문장형일 때 목록·말풍선의 표시 제목으로 쓴다. Page는 같은 `page_id`의
`updated_at`이 바뀌지 않으면 저장된 본문과 번역을 재사용하고, Issue는 같은 `issue_id`의 제목이 바뀌지 않으면
별도 번역 캐시를 재사용한다.
하이라이트는 별도 LLM 호출이 아니라 이벤트 종류, 교차 팀 재사용 여부와 최신 시각을 이용해 결정론적으로 고른다.

## 7. 런타임 설정

설정 창에서 데이터 원천, Work·Life 주소와 인증값, Life 별칭 매핑, 수집 주기, LLM 주소·모델·요약 길이와
번역 캐시 SQLite 경로를 바꾼다. 프레즌스 판정 창은 설정 창에 없고 환경 변수 `A_LENS_PRESENCE_WINDOW`로만
조정한다. 저장 전 연결 시험은 Work와 LLM을 대상으로 하며, Life는 저장 후 실제 수집 결과로 확인한다.
저장된 설정은 환경 변수보다 우선하며, 비밀값은 조회 API에 원문으로 반환하지 않는다. 설정 저장 후 관련
수집·Life·협업 지도 캐시를 즉시 비운다.
