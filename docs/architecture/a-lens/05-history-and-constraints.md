# A-Lens — 구현 연혁과 현재 제약

> 실측 기준: `main @ fda2467` (2026-08-04)

## 1. 초기 설계에서 현재 구현까지

초기 설계는 회사 사옥 로비, 층별 Space, 유리벽 권한과 읽기 전용 관전 경험을 중심으로 했다. 현재 제품은 같은
“사람용 번역” 원칙을 유지하면서 구현 과정에서 다음처럼 구체화됐다.

| 초기 구상 | 현재 구현 |
|---|---|
| 사옥 단면 로비 | Space별 방 생성·입장 목록 |
| 정적 배경 + DOM 후보 | PixiJS 방 씬 + DOM 홈·사이드바·모달 |
| C2 전용 응답 대기 | Work의 현행 REST 여러 개를 collector가 조합 |
| 서버가 준 서사를 그대로 표시 | A-Lens가 분류·요약·서사 번역하고 영속 캐시 |
| Work 활동만으로 사람 표현 | Life 신원·프레즌스·마스코트를 선택 결합 |
| Issue·재사용 피드 | 사람별 작업 기록, 문서함, 프로젝트 필터와 협업 지도로 확장 |
| 방 꾸미기 후순위 | 5개 배경 프리셋, 책상과 책상 수를 선택해 서버에 공유 저장 |

초기 문서의 목표가 모두 구현된 것은 아니다. 사옥 로비, 게스트 권한의 서버 집행, 대시보드, 파도타기와 방명록은
현재 기능이 아니며 현행 문서로 이관하지 않았다.

## 2. 현재 제약

### 2.1 접근 제어

A-Lens API 자체에는 사용자 인증이 없다. `tier=guest|member`도 요청자가 지정한다. 따라서 A-Lens가 외부 네트워크에
노출된 상태에서 Work의 민감한 상세를 안전하게 중계한다고 가정할 수 없다. 외부 노출 전 인증과 서버 측 tier 결정이 필요하다.

### 2.2 Work API 적응 계층

A-Lens는 계약 전용 집계 응답 대신 여러 Work REST 응답과 일부 구현 특성에 의존한다. 예를 들어 Issue 해결자 연결은
Work가 `page.issue_id`를 충분히 주지 않는 경우 Issue와 파생 Page의 시각을 이용해 보정한다. Work 응답이 풍부해지면 이
우회 로직을 걷어내야 한다.

### 2.3 단일 프로세스 캐시

최신 스냅숏, Life TTL 캐시와 협업 지도 캐시는 프로세스 메모리에 있다. 여러 A-Lens 인스턴스를 동시에 실행하면 각자
외부 API와 LLM을 호출하고 서로의 즉시 무효화를 공유하지 않는다.

### 2.4 방 저장 충돌

`rooms.json`은 프로세스 내부 락으로만 보호된다. 인증, 사용자별 소유권, 낙관적 버전과 다중 프로세스 파일 잠금이 없다.
같은 Space를 여러 사용자가 편집하면 마지막 저장이 이긴다.

### 2.5 추정 관계

협업 지도의 `topic` 엣지는 의미 모델이 아니라 한국어·영어 토큰과 IDF 규칙으로 계산한다. 실제 협업 사실로 해석하면 안 된다.
화면에서도 `reuse`, `handoff`와 다른 선 종류로 유지해야 한다.

### 2.6 LLM과 캐시

LLM 출력은 JSON 형식과 폐쇄 카테고리를 검증하지만 완전한 사실 검증기는 아니다. 원문에 없는 사실을 만들지 말라는 프롬프트와
수치 비생성 경계에 의존한다. 모델이나 프롬프트 버전이 캐시 키에 포함되지 않으므로 모델을 바꾼 뒤 기존 번역을 새로 만들려면
캐시를 명시적으로 비워야 한다.

### 2.7 프론트 규모

핵심 화면 로직이 큰 `main.ts` 한 파일에 집중되어 있다. 기능 추가 시 탭 상태, 이벤트 바인딩과 재렌더 범위가 서로 영향을
주기 쉬우므로 화면 단위 모듈 분리가 필요하다.

## 3. 후속 과제

- A-Lens 자체 인증과 서버 측 viewer tier 결정
- Work의 명시적 Issue–Page·작성자·프로젝트 연결 필드 사용
- 방 설정의 사용자별 소유권과 동시 편집 보호
- LLM 프롬프트·모델 버전을 포함한 번역 캐시 정책
- `main.ts`의 홈·방·Hub·협업 지도 모듈 분리
- 대규모 Space·사람 수에서의 페이지네이션과 씬 가상화
- 실제 사용자 데이터로 카테고리와 topic 엣지 품질 평가

초기 구상과 개별 기능의 설계 당시 판단은 [`docs/design/a-lens/`](../../design/a-lens/)에 남아 있다. 그 문서의
“진행 상태”나 미래 기능 목록을 현재 구현 사실로 사용하지 않는다.
