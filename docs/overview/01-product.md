# Agent Mentor — 제품 소개

> 이 문서는 프로젝트를 처음 접하는 사람을 위한 소개입니다.
> 상세 설계는 `docs/specs/`, 구현 계획은 `docs/plans/`에 있으며, 이 문서는 그 전체를 압축한 개요입니다.

## 1. 한 줄 요약

**Agent Mentor** — Windows와 WSL 양쪽의 Claude Code 사용 기록(JSONL 트랜스크립트)을 로컬에서 분석해,
사용자가 AI 코딩 에이전트를 **토큰 낭비 없이 효율적으로** 쓰도록 코칭하는 **Windows 상주형 데스크톱 앱**.
조용한 트레이 유틸리티로도, 데스크톱 위 픽셀 로봇 마스코트로도 동작한다.

- **제품명 유래**: "Mentor"는 오디세이아에서 텔레마코스를 가르친 인물 — Claude 모델의 신화 명명(Mythos, Fable)과 결이 통한다.
- **"agent" 접두어**: Claude Code에 국한하지 않고 OpenCode·Codex 등 다른 에이전트로의 확장을 이름에서부터 열어둔다.
  실제로 에이전트별 로직은 어댑터 인터페이스 뒤로 추상화되어 있다(아키텍처 문서 참고).

## 2. 핵심 컨셉 — "집계"가 아니라 "코칭"

사용자의 에이전트 사용 패턴을 관찰해서:

- 어떤 MCP / 플러그인 / 스킬을 어떤 용도로 얼마나 쓰는지 파악하고
- **잘못 쓰고 있는 경우 개선점을 제시**한다
  (예: 안 쓰는 MCP가 매 세션 수천 토큰을 상주 소모, 자동화 도구가 만든 세션 버스트, 단순 작업에 고급 모델)
- 하루의 사용 기록을 **에이전트(마스코트) 1인칭 일기**로 서사화해 돌아보게 한다
- 전체적으로 **불필요한 토큰 소모 없이** 에이전트를 쓰도록 돕는다

제품 정체성을 한 문장으로 다시 쓰면:

> **당신의 AI 코딩 여정을 (에이전트의 시점에서) 저널링하며, 그 안에서 코칭하는 동반자.**

## 3. 경쟁 지형과 포지셔닝

| 축 | ccusage | claude-hud | **Agent Mentor** |
|---|---|---|---|
| 성격 | 집계 | per-session 라이브 statusline | **해석·코칭** |
| 시간 | 리포트 | 지금 이 세션 | **여러 세션·며칠·몇 주 종단** |
| 형태 | CLI | 터미널 계기판 | **곁에서 회고하는 멘토(다이어리 + 마스코트 GUI)** |

토큰 집계·실시간 모니터링은 이미 레드오션이라 의도적으로 만들지 않는다.
무게중심은 **사후 서사 + 코칭 + 종단 성장**이다.

**3대 차별점:**

1. **WSL + Windows 통합 모니터링을 GUI로** — 경쟁 도구는 전부 단일 환경 CLI.
2. **컨텍스트 비용 정적 분석** — 대화를 시작하기도 전에 새는 always-on 토큰(안 쓰는 MCP 5개가 대화 전 수만 토큰을 깔고 시작하는 문제)을 잡는다. 대부분의 사용자가 이 비용의 존재 자체를 모른다.
3. **데스크톱 코치 UX** — 트레이 상주 + 픽셀 로봇 마스코트 + 싸이월드 미니홈피풍 창. 지표가 아니라 "동반자"로 다가간다.

## 4. 설계 원칙 (전 기능을 관통하는 헌법)

프로젝트 전체에서 반복적으로 참조되는 원칙들. 새 기능을 논의할 때 이 원칙과의 정합성을 먼저 본다.

### 4.1 정밀도의 선 (Line of Precision)

- **처방(결과 있는 행동) = 결정론적 규칙.** "이 MCP를 제거하라" 같은 실행 가능한 조언은 Rust 규칙 엔진만 낸다. 환각 불가.
- **인정·서사(칭찬·회고) = LLM.** 일기와 말풍선의 뉘앙스는 LLM이 담당하되, **수치·사실은 브리프에 담긴 것만 인용** 가능하다. 수치를 지어내면 안 되고, 자유 소감은 서사에만 허용되며 행동 카드로 자동 승격되지 않는다.

### 4.2 코칭의 공용 통화 = 토큰

모든 코칭 발견(Finding)은 `est_tokens_saved`(절약 가능 토큰)로 정량화된다.
"캐시 히트율이 낮다"가 아니라 "고치면 ~8k/일 절약". 추정치는 "약(~)" 라벨로 정직하게 표기하고,
코치 자신이 소비한 LLM 토큰도 같은 단위로 계량해 표시한다("이 일기 ~1.2k 토큰").

### 4.3 실제 조치 가능한 것만 코칭한다 (코칭 v2에서 확립)

실사용 E2E에서 얻은 교훈으로 확립된 원칙. 코칭 대상은 조치 지점이
**① 설정 파일 한 곳** 또는 **② 다음 세션의 선택(습관·작업 방식)** 인 것만.
지나간 세션 안에서의 행동 교정 권고("아까 그렇게 하지 말았어야죠")는 폐기.
세션 단위 카드 스팸 대신 **프로젝트 집계 카드**가 기본.

### 4.4 나깅(잔소리) 방지

- Finding 상태머신: `new → shown → {snoozed | dismissed | following}`.
- 사용자가 조언을 따르기 시작하면 `following`으로 자동 전이 → 규칙이 조용해지고 **칭찬으로 전환**된다("어제 말한 거 오늘 진짜 줄었네요, 고마워요").
- 실시간 넛지는 전역 쿨다운으로 희소하게.

### 4.5 프라이버시 = 로컬 기본 + egress는 엔진 선택으로

- 트랜스크립트는 **100% 로컬 처리 기본**. 프로즈(대화 원문)는 DB에도 저장하지 않고, 미리보기 + 원본 파일 포인터(파일+offset)만 저장해 필요할 때 지연 로드(deref)한다.
- 외부 전송 경계는 **LLM 엔진 선택**이 좌우: 기본은 사내 on-prem(OpenAI 호환 엔드포인트), Claude는 옵션. 기본 상태에서 데이터가 망을 벗어나지 않는다.

### 4.6 관대한 파싱 (하드 실패 금지)

Claude Code의 JSONL 스키마는 비공식이고 릴리스마다 바뀐다. 어댑터는 `#[serde(default)]` + `Option` + 미지 필드 catch-all로 **절대 하드 실패하지 않으며**, 스키마 이상은 로깅만 한다. 파일 하나가 깨져도 전체 수집이 멈추지 않는다.

## 5. 페르소나 — 다마고치풍 픽셀 로봇

- 마스코트는 제품명 "Mentor"의 의인화. **레트로 픽셀아트 소형 로봇**으로, 사용자를 "주인"이라 부르는 1인칭 다마고치풍 캐릭터다.
- 다이어리의 화자와 마스코트는 **동일 인물** — 일기는 "에이전트가 쓰는 자기 일기"다.
- 로봇 외형은 호스트명+사용자명 해시를 시드로 한 **파츠 조합형 절차 생성** — 사용자마다 다른 로봇을 갖는다.
- 한국어 서사는 "AI티"(번역투·상투구·이모지 남발)를 생성 시점에 예방하는 문체 가이드(`voice_guidance()`)를 거친다.

## 6. 기술 스택 요약

| 층 | 선택 | 이유 |
|---|---|---|
| 셸 | **Tauri v2** (v1 API 금지) | 종일 트레이 상주 앱 — OS webview라 Electron 대비 메모리가 가벼움. 트레이/autostart/updater가 공식 v2 플러그인 |
| 백엔드 | **Rust** (cargo workspace: `crates/core` + `src-tauri`) | JSONL 대량 파싱·집계·파일 감시(`notify`)·SQLite(`rusqlite`)를 네이티브로 |
| 프론트 | **Svelte 5 + Vite 멀티페이지** (창별 엔트리) | 마스코트/채팅 두 창이 독립 엔트리. 로봇 렌더는 canvas 프로시저럴 드로잉 |
| 저장 | **SQLite** 단일 파일 | 이벤트·롤업·Finding·인벤토리·다이어리 색인 |
| 플랫폼 | **Windows 전용** | WSL+Win 양쪽 `.claude`를 모니터링하되 앱은 네이티브. 크로스플랫폼 포기로 투명 창/클릭스루 함정 회피 |
