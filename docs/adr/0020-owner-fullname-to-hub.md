# ADR 0020: 주인 실명(owner_full_name)을 허브로 전송하고 방명록 작성자 표기에 쓴다

- 상태: 채택
- 날짜: 2026-07-26
- 대상: a-mate 설정·Life 클라이언트, a-hub life 방명록 API
- 관련: [G1 설계 스펙](../archive/design/a-mate/specs/2026-07-26-owner-identity-design.md),
  [ADR 0019](0019-owner-memory-transmission-boundary.md)(LLM 엔진 경계 — 별개 축),
  PR #104 §F(주인 식별 데이터 전송)

## 배경

a-mate의 신원은 셋 — `user_name`(봇 이름, Life 표시명), `owner_title`(호칭, 프롬프트 전용),
`owner_os_user`(OS 계정, payload forward 필드) — 이고 **주인(사람)을 식별하는 이름이 없다**.
호칭("주인", "대장")은 사용자 간 중복될 수 있어 사람 구분이 불가능하고, 방명록 작성자는
서버가 봇 이름으로 파생하므로 누가 남겼는지 신원 확인이 안 된다.

G1은 실명을 저장해 신원 확인이 필요한 곳(방명록 서명, Life payload)에 쓰기를 요구한다.
실명이 공유 서버(허브)로 전송되고 **타인 방의 방명록 행에 영구 저장**되는 것은 새로운
프라이버시 경계이며 되돌리기 어렵다 — ADR로 남긴다.

## 결정

- **저장**: 로컬 설정 `owner_full_name` 신설. **옵트인**(기본 빈값) — 입력하지 않으면
  어떤 경로로도 실명이 흐르지 않고 기존 동작(봇 이름) 그대로다.
- **payload**: Life `register`/`rename` body에 `owner_full_name`을 forward 필드로 실음
  (빈값 생략, 서버는 모르는 필드 무시 — `owner_os_user`와 동일 규약). `owner_os_user`는
  자동 파생 안정 식별자로 유지하고 실명이 이를 대체하지 않는다. 서버의 저장·소비는
  이 ADR의 범위 밖(후속 G2/G3에서 별도 결정).
- **방명록**: 사람이 남기는 방명록은 클라이언트가 `author_name`으로 실명을 전송하고,
  a-hub가 방명록 행에 **스냅샷으로 영구 저장**한다(개명·설정 삭제 시 소급 수정 없음,
  작성자/방 주인의 항목 삭제로만 제거).
- **표기 규범**: 사람 작성 = 풀네임만(예: "홍길동") / 봇 작성 =
  `{owner_title}님의 {user_name}`(예: "대장님의 둘쇠", 구현은 P3/G3).
- **조립 위치**: 클라이언트(a-mate). 서버는 optional `author_name` 수용 + 길이 검증(1~80자,
  초과 400)만 하고, 미제공 시 현행 `author.name` fallback으로 하위호환.

## 대안

- **서버 저장 + 서버 조립**: register가 실명·호칭을 저장하고 `as_bot` 플래그로 서버가 조립.
  신원의 원천이 서버가 되어 재사용성은 좋지만, agents 저장 마이그레이션 + `owner_title` 전송
  신설(PR #104가 의도적으로 안 보냄) + 한국어 표시 포맷("님의")의 서버 유입으로 G1 범위가
  크게 불어난다. 소비자가 생기는 G2/G3에서 필요 시 승격하기로 하고 기각.
- **표시도 호칭만**: 실명 비노출로 프라이버시는 좋지만 동명 호칭이 구분 안 돼 G1의 핵심
  요구(신원 확인)를 못 채운다. 기각.
- **실명 미전송(로컬만)**: 방명록은 타인 방 데이터라 서버 경유가 필수 — 로컬 저장만으로는
  요구를 채울 수 없다. 기각.

## 결과

- 실명은 사용자가 설정에 입력했을 때만 흐른다(옵트인). 미입력 사용자는 무변화.
- 방명록의 실명은 영구 스냅샷 — 삭제 통제는 항목 단위(작성자·방 주인)로만 존재한다.
- `author_name`은 호출자 주장값이다. 스푸핑 가능성은 register의 자기 신고 name과 동일한
  신뢰 수준(사내 신뢰 환경 전제)이며, 검증 강화는 후속 과제로 남긴다.
- Life REST는 `contracts/` 범위 밖이므로 payload 규약의 기록처는 본 ADR과 G1 스펙이다.
