# ADR 0023: Life 방을 반깊이 삼각 바닥으로 전환한다

- 상태: 채택
- 날짜: 2026-07-28

## 배경

기존 Life 방은 20×20 전체 격자를 아이소메트릭으로 투영해 완전한 마름모 바닥과
그 위에 평행한 두 벽을 그린다. 이 구조는 싸이월드 미니룸처럼 화면 상단 전체가 벽이고,
뒤 코너에서 화면 좌우로 바닥이 펼쳐지는 가로형 공간과 다르다.

논리 좌표 번호와 기존 벽·창문 데이터는 유지하되, 화면 앞쪽 절반의 좌표와 가구는
버릴 수 있고 그 위치의 에이전트는 유효한 위치로 옮겨도 된다.

## 결정

- 논리 격자 크기 `20×20`은 유지한다.
- 바닥 셀은 `0 <= x < 20`, `0 <= y < 20`, `x+y < 20`일 때만 유효하다.
- 서버 capabilities를 `life_protocol=4`로 올리고
  `floor={shape:"half-depth",max_xy_exclusive:20}`을 공개한다.
- 이동·입장·자동 스폰·가구 점유 검증은 하나의 바닥 유효성 함수를 공유한다.
- 서버가 영속 데이터를 로드할 때 새 바닥을 조금이라도 벗어난 바닥 가구는 객체 전체를
  제거한다. 창문은 유지한다.
- 비활성 셀, 가구 점유 셀 또는 중복 셀에 있는 에이전트는 유효한 빈 셀로 결정론적으로
  재배치하고 즉시 영속화한다.
- 클라이언트는 기존 아이소메트릭 좌표식과 에셋 배율을 유지하되, 유효 셀만 렌더·입력한다.
- 두 벽은 화면 상단 전체까지 채우고, 뷰포트는 앞 절반을 잘라 가로형 비율로 바꾼다.

상세 좌표와 마이그레이션 순서는
[`2026-07-28-half-depth-life-room-design.md`](../design/a-mate/specs/2026-07-28-half-depth-life-room-design.md)를 따른다.

## 결과

- 기존 20×20 좌표 번호, 방 ID, 테마, 창문, 유효 영역의 가구는 유지된다.
- 앞쪽 절반의 가구는 서버 재시작 시 제거되며 복구되지 않는다.
- 에이전트 위치는 서버가 유효 영역으로 자동 보정한다.
- 프로토콜 3 클라이언트는 편집 저장을 거부하므로 서버와 클라이언트를 함께 배포해야 한다.
- DB 스키마 변경은 없다.

## 검증

- 경계 셀 이동·입장·스폰·가구 배치 단위 테스트
- SQLite 복원 시 가구 제거·에이전트 재배치·멱등성 테스트
- 클라이언트 geometry 경계·회전·배치 보정 테스트
- 기본 크기 창에서 벽·바닥 무여백과 스프라이트 종횡비 수동 확인
