# ADR 0019: a-mate 주인 메모리를 도입하고 전송 경계를 메모리에 한해 완화한다

- 상태: 채택
- 날짜: 2026-07-22
- 대상: a-mate(Agent Mentor) 채팅·코칭·일기, 로컬 데이터 전송 경계
- 관련: [설계 스펙](../archive/design/a-mate/specs/2026-07-22-owner-memory-design.md), [ADR 0013](0013-docs-lifecycle-and-archive.md)

## 배경

a-mate는 지금까지 "주인이 말한 것을 기억하는" 기능이 없었다. 고정 프로필 4필드
(name/org/uuid/mbti)와 로그에서 매 스캔 재계산되는 역량 프로필만 있었고, 채팅은 창 수명 동안만
프론트 메모리에 남고 **의도적으로 영속화하지 않았다**. 시스템 프롬프트는 트랜스크립트 원문 없이
파생 수치·advice 요약만으로 결정론 조립됐다(전송 경계).

주인이 자신에 대한 자유 텍스트 사실("나는 비건이야", "목요일 오후는 회의")을 마스코트가 기억하고
대화·코칭·일기에서 참조하려면, 그 사실을 저장하고 시스템 프롬프트에 실어 **LLM 엔진으로 전송**해야
한다. 이는 "파생 수치만 전송"하던 기존 경계를 넘는 최초의 사용자 자유 텍스트 전송이다. 스키마 신설과
전송 경계 완화는 되돌리기 어려운 결정이므로 ADR로 남긴다.

## 결정

- **저장**: 신규 `memories` 테이블(자유 텍스트 1건 + 생성시각, 삭제 전까지 영구). key-value
  `settings`가 아닌 전용 테이블. 분류/태그·만료(TTL)는 범위 밖.
- **캡처**: 채팅 중 명시적 저장만 — LLM `save_memory` 툴콜(tool-calling 루프) 또는 설정탭 수동 추가.
  대화에서 자동으로 사실을 추출·저장하지 않는다.
- **회상**: 활성 메모리를 채팅·코칭·일기 시스템 프롬프트에 **결정론적으로** 주입한다(LLM 랭킹 없음,
  개수·문자수 캡 적용). 주입되는 메모리 텍스트는 설정된 엔진으로 전송된다.
- **전송 경계**: 트랜스크립트 원문은 여전히 절대 전송하지 않는다. 완화는 **사용자가 명시적으로
  저장한 메모리 텍스트에 한정**된다. 엔진은 기존과 동일하게 유일한 외부 경계(사내 on-prem 기본)다.
- **통제권**: 사용자는 명시적으로만 저장하고, 설정탭에서 언제든 조회·편집·삭제할 수 있다.

## 대안

- **자동 추출**: 대화에서 마스코트가 알아서 기억할 사실을 뽑아 저장. 자연스럽지만 추가 LLM 호출로
  비용·비결정성이 늘고, 사용자가 의도하지 않은 문장이 저장·전송될 위험이 있어 기각.
- **수동 메모장만**: 전송 없이 로컬에만 저장. 경계는 지키지만 "말하면 알아서 기억하고 대화에 반영"
  하는 핵심 경험을 못 준다 — 회상 시 어차피 프롬프트에 실어 전송해야 하므로 반쪽 해결.
- **키워드 게이트 + 단발 추출**: tool-calling 미지원 엔진에서도 동작하나, 창의적 표현을 놓치거나
  오탐하고 모델이 "스스로 판단"하는 느낌이 약하다. 네이티브 tool-calling을 채택하고, 툴 미지원
  엔진은 graceful degrade(저장 no-op·채팅 정상, 수동 UI가 신뢰 경로)로 처리.

## 결과

- 사용자가 저장한 메모리 텍스트는 설정된 엔진(기본 on-prem)으로 전송된다 — 파생 수치만 보내던
  경계의 의도된 확장. 트랜스크립트 원문 비전송 원칙은 유지된다.
- 저장은 명시적·사용자 통제(조회/편집/삭제) 하에 있어 오·과전송 위험이 낮다.
- 채팅 엔진은 tool-calling을 사용하게 되며, 미지원 엔진에서도 채팅은 깨지지 않는다.
- 채팅으로 잊기(`forget_memory`), 태그/분류, 만료, 관련도 랭킹은 후속 과제로 남는다.
