# ADR 0006: 자산 실제 방향 메타데이터와 뷰 해석

- 상태: 채택
- 날짜: 2026-07-18
- 대체 범위: ADR 0005의 `0=NE`, `90=mirror(NE)`, `180=SW`, `270=mirror(SW)` 공통 규칙

## 배경

생성된 두 원본 파일의 이름(`ne.png`, `sw.png`)은 파일 슬롯 이름일 뿐, 그림 속 가구가 실제로
바라보는 방향을 보장하지 않는다. 실제 자산을 확인한 결과 같은 `ne.png`라도 소파·책상·의자와
가전 개별 품목의 시각 방향이 서로 달랐다. 공통 순서로 파일을 선택하면 footprint는 올바르게
회전해도 스프라이트가 한 방향씩 밀리며, 품목별 CSS 보정으로는 이 불일치를 해결할 수 없다.

또한 좌우 반전은 화면 방향을 다음처럼 바꾼다.

| 원래 방향 | 좌우 반전 방향 |
|---|---|
| ↗ (`ne`) | ↖ (`nw`) |
| ↘ (`se`) | ↙ (`sw`) |
| ↙ (`sw`) | ↘ (`se`) |
| ↖ (`nw`) | ↗ (`ne`) |

## 결정

### 원본 이름과 실제 방향 분리

- 각 바닥 자산은 사용할 원본 슬롯과 그 그림의 **실제 시각 방향**을 메타데이터로 가진다.
- 렌더러는 목표 회전에서 파일 순번을 계산하지 않는다. 원본과 좌우 반전 후보를 만든 뒤 실제
  방향이 목표 방향과 일치하는 후보를 선택한다.
- 방향을 만들 수 없는 자산은 카탈로그 초기화 중 오류를 발생시킨다. 임의의 기본값으로 표시하지 않는다.

```text
목표 회전 → 목표 화면 방향 → 실제 방향 메타데이터 검색 → 원본 슬롯 + mirrorX
```

### 방향 의미 유형

- `directed`: 앞뒤가 구분되는 소파·책상·의자·가전. 네 목표 방향이 모두 정확히 해석되어야 한다.
- `axial`: 앞뒤가 대칭인 직사각형 테이블과 아크 조명. 목표 방향 또는 180도 반대 방향을 같은
  축으로 취급한다.
- `invariant`: 방향성이 없는 1×1 조명. 모든 회전에서 한 원본을 그대로 사용한다.
- 창문은 바닥 가구 해석기를 사용하지 않는다. 설치 벽으로 회전이 결정되고, 평면 원본을 반전해
  좌상벽과 우상벽에 각각 붙인다.

### 점유 셀

- 스프라이트 방향 해석과 footprint 회전은 같은 목표 회전을 입력으로 사용하지만 서로 독립된
  데이터다. 이미지 방향을 맞추기 위해 footprint를 전치하거나 밀지 않는다.
- 레트로 TV의 기본 footprint는 외형에 맞춰 3×2의 6셀로 변경한다.

## 검증

- 소파, 책상, 테이블, 의자와 가전의 품목군별 네 방향 원본·반전 선택을 단위 테스트로 고정한다.
- 모든 `directed` 자산은 선택된 뷰의 실제 방향이 목표 방향과 정확히 같아야 한다.
- 모든 `axial` 자산은 목표 방향과 같거나 정확히 180도 반대여야 한다.
- 레트로 TV는 3×2 크기와 6개의 footprint 셀을 가진다.
- 개발 브라우저에서 카테고리별 네 방향 썸네일, 배치 미리보기와 배치 후 스프라이트를 함께 확인한다.
