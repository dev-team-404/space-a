# ADR 0018: a-mate 인앱 자동 업데이트 채널을 도입한다

- 상태: 채택
- 날짜: 2026-07-22
- 대상: a-mate(Agent Mentor) 배포·업데이트, 릴리스 저장소 구성
- 관련: [설계 스펙](../archive/design/a-mate/specs/2026-07-22-auto-update-design.md), [ADR 0013](0013-docs-lifecycle-and-archive.md)

## 배경

a-mate는 지금까지 자동 업데이트가 없었다. 배포는 로컬 Windows에서 수동 빌드한 NSIS 설치
파일을 전달하고, 새 버전마다 사용자가 다시 받아 재설치해야 했다. 로드맵에는 "updater 활성화
(서명 인프라 미확정으로 보류)"로만 남아 있었다. 일반 사용자가 앱 안에서 쉽게 업데이트하도록
하려면 업데이트 채널·서명·발행 방식을 확정해야 한다.

"서명 인프라 미확정"은 두 가지 서명을 뭉뚱그린 것이었다. **updater 서명키**(minisign, 무료)는
자동 업데이트에 필수이고, **Windows 코드 서명 인증서**(Authenticode, 유료)는 SmartScreen 경고
제거용으로 선택 사항이다. 후자가 없어도 자동 업데이트는 동작한다.

## 결정

- **메커니즘**: Tauri v2 공식 `tauri-plugin-updater`(업데이트) + `tauri-plugin-process`(재시작).
  흐름은 프론트엔드 주도 — chat 창이 시작 시 `check()`, 결과를 상단 배너로 표시하고 클릭 한 번으로
  다운로드·설치·재시작. 트레이 "업데이트 확인"이 수동 트리거.
- **피드 호스팅**: GitHub Releases의 정적 `latest.json` 엔드포인트.
- **저장소 구성**: 소스 저장소(`space-a`)는 private을 유지하고, **공개 릴리스 전용 저장소
  `dev-team-404/a-mate-releases`** 를 분리해 설치 파일·`latest.json`만 올린다. 앱은 인증 없이
  공개 URL에서 업데이트를 받는다(토큰 임베드 불필요).
- **서명**: updater 서명키(무료)만 사용한다. Windows 코드 서명 인증서는 이번 범위에서 제외 —
  SmartScreen 경고는 최초 설치 1회에만 발생하며 이후 인앱 업데이트에는 지장이 없다.
- **발행**: 수동 릴리스 스크립트(`a-mate/scripts/release-amate.sh`). 개발자가 로컬 Windows에서
  빌드·서명·`latest.json` 생성·`gh release` 업로드를 한 번에 수행한다. CI 자동화는 제외.

## 대안

- **사내/OCI 서버 호스팅**: 온프렘·비공개에 부합하나 서버 유지보수가 필요. 설치 파일이 외부에
  노출되면 안 되는 상황이 아니라면 과한 인프라.
- **private 저장소 + 토큰 임베드**: 앱 바이너리에서 토큰이 추출될 수 있어 사실상 공개와 동급
  위험에 관리 부담만 늘어 기각.
- **코드 서명 인증서 포함**: 비용·조달 리드타임이 들고 자동 업데이트 자체에는 불필요해 이번
  범위에서 보류. 추후 별도 결정으로 추가 가능.

## 결과

- 공개 릴리스 저장소에 설치 파일이 노출된다. a-mate는 로컬 데이터만 읽는 코칭 툴이고 설치 파일에
  비밀이 없으며, 노출되는 것은 공개용 updater public key뿐이라 실질 위험은 낮다.
- updater private key는 릴리스 담당자가 비공개 보관하며 저장소에 커밋하지 않는다.
- 최초 설치는 여전히 SmartScreen 경고를 동반한다("추가 정보 → 실행").
- 코드 서명·CI 자동 릴리스·주기적 자동 체크는 후속 과제로 남는다.
