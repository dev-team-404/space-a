목표 아키텍처 — 데이터 흐름

a-mate와 a-lens는 서로를 모른다. 모든 데이터는 두 서버(A-Hub · Room Server)에서 만난다.

구현됨 계약 확정 · 구현 예정 계획 (요청·협의 필요)

만나는 곳은 항상 서버다

a-mate는 서버에 밀어 넣기만 하고(push), a-lens는 서버에서 꺼내 보기만 한다(pull). 두 앱이 직접 통신하는 경로는 없다.

원문은 로컬을 떠나지 않는다

claude.jsonl은 a-mate가 로컬에서만 분석한다. 서버로 나가는 것은 카운트 · 상태 · 로컬 생성 요약 같은 파생 신호뿐이다.

숨기는 것은 서버 몫이다

누가 무엇을 보는지(lobby · guest · member · manager)는 C2가 트리밍해서 내려준다. a-lens는 받은 것을 그대로 그릴 뿐, 클라이언트에서 가리지 않는다.

연결별 상세
연결인터페이스싣는 데이터상태
Claude Code → A-Hub C1 (MCP) 이슈 등록 · 해결, 지식 저장, 검색, 인용(재사용 이벤트) 구현됨
A-Mate → Room Server rooms API 에이전트 등록, 방 입장, 자리 이동 구현됨
A-Mate → Room Server 하트비트 (신설) working / idle 상태, 마지막 활동 시각 계획
A-Mate → A-Hub 텔레메트리 (신설 · 계약 협의 필요) 토큰 사용량 · 모델 믹스, 코칭 채택 · 절감량, Skill화 후보, MCP 사용 카운트 계획
A-Hub → A-Lens C2 (읽기 전용 REST) 로비 집계, 방 상세, 재사용 이벤트, 활동 피드, 통계 — tier별 트리밍 계약 확정 · 구현 예정
Room Server → A-Lens 조회 API 방 배치 · 프레즌스 (온라인 수, working/idle) 계획

※ 프로토타입의 GitHub PR 스냅숏 경로는 임시 확인용이라 이 그림에서 제외했다. 프레즌스처럼 작업 내용이 담기지 않는 데이터는 Room Server 경유, 작업 맥락이 담기는 텔레메트리는 A-Hub(C2 계약 협의) 경유가 현재 방침.
